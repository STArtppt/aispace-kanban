# 看板使用帮助

看板扫描你的工作空间并渲染出来，**原则上只读**：真正动手的是你和 AI ——
看板负责让你们俩看到同一份东西，再把你的反馈原样交还给 AI。
少数几件**你亲手点的事**会写盘，范围见文末「看板会不会改我的文件」。

一条主线：**建空间 → 放资料 → 转成 AI 可读 → 让 AI 干活 → 收产出 → 反馈给 AI**。

---

## 1 · 新建工作空间

侧栏工作空间列表下方点「新建」，一个对话框里有两个 tab：

- **新建工作空间**：选模板类型、填名字和目录即可。路径框后面的文件夹图标会弹出系统的目录选择器，
  不用再去终端里 `pwd` 拷路径（选择器起不来时照样可以手填）。
- **登记已有目录**：已经有目录了就指过去。**准入门槛只有两条：有 `input/` 和 `output/`。**
  `mkdir -p 我的调研/{input,output}` 就能加进来，不需要模板。

模板会铺出一套开箱即用的骨架：目录约定、转换脚本、给 AI 用的技能和协作约定。
内置的是「产品经理 AI 空间」；想要别的角色（调研、写作、分析…），
在「模板类型」旁点复制提示词，交给 AI 让它照着建一份，落点在 `{{userRoot}}/`。

## 2 · 放入资料

资料有三种入口，最后都汇到 `input/converted/`，AI 只读那里。

**文件**：把原始文件**原样**丢进 `input/raw/`，不用整理、不用改名，子目录随你分。

```
input/raw/需求规格说明书.docx
input/raw/站点数据/闸门底坎库容.xlsx
```

`input/raw/` 是**溯源的终点**，进去之后就别再改它。用不上的资料不必删，
在「原始资料」列表那一行的「更多」里点「忽略此文件 / 忽略此目录」，它就不再算缺口
（写进 `input/.ingestignore`，文件本身还在）。

**网页**：政策文件、公开标准、友商文档站这类网页资料，让 AI 跑工作空间的
`scripts/web_ingest.py <URL>`，正文会转成 Markdown 落进 `input/converted/`，带溯源。
要登录才能看的页面走浏览器采集插件或剪藏，见第 7 节的「刷新收件箱」。

**数据库**：库可以作为**按需查询**的远端资料源。「输入资料 → 原始资料」标题栏的数据库图标
打开「添加数据库源」，填显示名、粘一段连接信息，点「复制 prompt 给 AI」，粘给 AI 由它落配置
（`input/sources/<名字>.yaml`，口令只进工作空间 `.env`）。配好后「数据库源」tab 出现，
点「刷新 schema」采一份表结构快照到 `input/converted/_sources/`；具体数据由 AI 需要时再查。

> 看板**不存凭据**：口令和 key 只从输入框进剪贴板，刷新页面就没了。
> 配置里给的通常是高权限账号，别指望「反正是只读账号」——让 AI 查询前想清楚。

## 3 · 解决依赖

多数格式开箱即用。缺依赖只影响对应格式，其余照常转换。

| 格式 | 靠什么 | 要装吗 |
| --- | --- | --- |
| PDF、`.doc`、`.ppt` | 本地 anydoc | **看板自带**，从界面点「转换」永远可用 |
| `.docx` `.odt` `.rtf` `.epub` | 本地 anydoc | **看板自带**，从界面点「转换」永远可用 |
| `.xlsx` `.xls` `.csv`、图片、纯文本 | 脚本自带解析 | 不用 |
| 扫描件 OCR、pptx 抽图 | MinerU 在线 API | 要 token，见下 |
| 网页 | `defuddle`（抽正文）、`single-file-cli`（抓页面） | 用网页入口才要，`npm i -g defuddle single-file-cli` |

**PDF 默认在本机转换，文件不出这台机器。** 只有两种情况会上传到 MinerU：
你显式要求，或者遇到扫描件（没有文字层，只能靠 OCR）。

要配 MinerU 的 token（在 <https://mineru.net/apiManage> 领）：「原始资料」标题栏的钥匙图标打开
「添加 API Key」，填 `MINERU_API_KEY` 和值，点「复制 prompt 给 AI」，粘给 AI 让它写进工作空间的 `.env`。
也可以自己照着 `.env.example` 在工作空间根目录建 `.env`。

> 在终端里自己跑 `python3 scripts/ingest.py` 时，如果开头出现
> **「⚠ 找不到本地 anydoc」**，说明这轮 PDF 会被传出去。先起一次看板（它会把自带
> anydoc 的位置记到 `{{configDir}}/runtime.json`，脚本自己会去读），或者
> `npm i -g @firecrawl/anydoc`。涉密资料看到这句先停下。

## 4 · 转换文档

「输入资料」分四个 tab：**原始资料**（还没转的）、**转换产物**、**图片资料**，
配过数据源时还有**数据库源**。在「原始资料」点「开始转换」一次处理全部，
某一行点「转成AI易读」只转那一份。转完你会得到：

- `input/converted/` —— 目录结构与 `raw/` 一一对齐的 `.md` / `.csv`，
  每份都带溯源 frontmatter（来自哪个源文件、什么工具、什么时候转的）；
- `input/INDEX.md` —— 资料台账，一行一份，含状态与告警。

**转换是幂等的**：源文件没变就跳过，可以随时重跑。
转完扫一眼台账里的 `⚠`：需另存为、扫描件需 OCR、转换失败——这些是真缺口，别当资料齐了。

「转换产物」右上角的筛选可以只看**原件动过**（产物可能已经不对，行内「更多 → 重新转换」）
或**未被引用**（转好了但没有一篇产出提到它——AI 可能根本没读）。

## 5 · 让 AI 接手

在**工作空间目录里**打开你的 AI 编程工具（Claude Code、Codex 等），它会自己读到
`AGENTS.md`（协作约定）和 `.claude/skills/`（这个角色的技能）。你不用解释规矩。

模板空间里第一句话通常就够：

> 资料我放进 input/ 了，先入库，然后帮我摸清这个项目的现状。

之后是**持续对话**，不是一次性提问：让它读 `input/converted/`，你补背景、纠正它的
误读、指出哪份资料更可信；它把结论写进 `output/`。看板会自动刷新，你在网页上读渲染
后的结果，比在终端里翻字舒服得多。

**让 AI 读转换产物，不要读 `input/raw/` 原件**——原件体积大、烧上下文，内容已经在
`converted/` 里了。要对照原文时再说。

## 6 · 收产出

产出落在 `output/`，「产出文档」视图按三层渲染：

| 目录 | 放什么 | 什么时候看 |
| --- | --- | --- |
| `analysis/` | 摸底、拆解 | 过程中，随时会被推翻 |
| `docs/` | 成稿：报告 / 方案 / PRD / 稿件 | 要交出去的 |
| `decisions/` | 决策记录，一事一档，只追加 | 回头查「当时为什么这么定」 |

另外两个目录不进这三组列表，而是在 **⌘K 工作台**里看（见第 8 节）：

| 目录 | 放什么 |
| --- | --- |
| `questions/` | 未决问题，一问一文件 `Q<编号>.md` |
| `records/` | 产出物记录，一份产出一个 `I<编号>.md`，记它的状态流转；批注落在 `records/notes/` |

预览里什么格式都能看：Markdown（含 mermaid 图、代码高亮）、常见源码与 yaml / json / xml、
CSV、xlsx（分页、多 sheet）、图片。标题栏的搜索框能在当前内容里检索，表格会扫整张表。
docx、PDF 这类原件在网页里不渲染，点「用默认程序打开」交给系统。

### 归档

产出只会越攒越多，陈旧的分析、被取代的文档和在用的东西混在一起，AI 读的时候会全量读进去。
不再作数的，在那一行的「更多」里点**归档**：文件移进同组的 `一次归档/` 目录
（比如 `output/docs/一次归档/`），从主列表分出去，放到列表底下的「已归档」分区。

- **不删除。** 归档项照样能搜、能点开预览，AI 需要时照样能读；同名时加日期后缀，不覆盖。
- **归档不是状态。** 产出物记录的状态不会因此改变；记录会标「指向丢失」，让 AI 走
  `pm-output-record` 把路径跟进过去就好。
- **交接单。** `一次归档/README.md` 逐条记着原路径和新路径，底下有一段提示词。
  攒多了把它粘给 AI（`pm-output-archive` 技能），它会按主题分堆、每堆写一份短索引。
- 只能归档组根目录下的文件，子目录里的菜单项置灰；要挪就自己在终端里移。
  归档靠工作空间的 `scripts/archive_output.py`，旧工作空间没有这支脚本时同样置灰。

## 7 · 视觉呈现

`visualization/` 是视觉平面，「视觉呈现」视图分两个 tab：

- **参考** —— `references/` 里收下来的别人的页面，一份一个目录，入口叫 `index.html`；
- **原型** —— `prototypes/` 里工具产出的、**已构建好**的可点击 HTML 包，
  或用一份 `meta.json` 记一条云端发布链接。

**贴 URL 收进来**：两个 tab 顶部都有「贴链接」图标。参考 tab 贴一个公开可访问的网址，
抓下整页 + 三张截图；原型 tab 贴一条云端发布链接（axhub-make 发布、figma make 的 publish / share），
只存链接和一张封面，点开的是原站。

贴 URL 采集要靠本机的两个**独立工具**，它们不随看板一起安装：

| 工具 | 干什么 | 装不装 | 装法 |
| --- | --- | --- | --- |
| `single-file-cli` | 把整页抓成一个自包含 HTML | **参考采集必需** | `npm i -g single-file-cli` |
| `playwright` | 出截图 / 封面 | 可选，**缺了只是没有图** | `npm i -g playwright && playwright install chromium` |

> 贴 URL 只适合**不用登录就能看的页面**，而且采下来的是页面当时的**全部内容、不做脱敏** ——
> 别对着不该落盘的页面点采集。

**要登录才能看的页面**，有两条路：

- **采集插件投递**：在浏览器里用 annotation-collect 采集插件把页面投给看板（默认就投到
  `127.0.0.1:7788`），直接出现在参考 tab，来源标「插件投递」。插件会尽力脱敏，但**不是安全保证**。
- **刷新收件箱**：用剪藏或「另存为」把 `.html` 丢进 `visualization/references/` 根上，
  点参考 tab 的「刷新收件箱」，散装页面会收成标准参考目录，正文同时抽进 `input/converted/`
  让 AI 能读。旧工作空间没有 `scripts/web_ingest.py` 时不显示这个按钮。

**已接入原型工作区的原型**（Axhub Make 同步过来的镜像，目录里有 `SYNC.md`）会聚合成一行：
离线包、在线版、规格 / 文档 / 标注 / 批注合在一起，同步状态写在行里。
「在线版落后」「离线包没更新」标橙。点行上的「刷新」会跑原型工作区自己的同步脚本，一次拉取 + 推送；
按钮置灰时看它给的原因，通常是先要在原型工作区里跑一次同步。

## 8 · 反馈给 AI：工作台与批注

看板不起 AI，也不替你发消息。反馈的形状统一是：**在看板上点选 → 复制一段提示词 → 粘给已经开着的 AI 会话**。
AI 改完文件，看板自动刷新。

### ⌘K 工作台

任意视图按 **⌘K**（Windows / Linux 上 Ctrl+K），或点右下角的悬浮按钮，打开工作台。两页：

**未决问题** —— 按「阻塞了谁」分组，不按优先级。四个筛选：未处理 / 待 AI 更新 / 已消解 / 状态冲突。
每条问题给你四个去向，选一个再「保存」：

| 去向 | 意思 | 之后 |
| --- | --- | --- |
| 资料里应该有，待查证 | 派给 AI 去查 | 进「待 AI 更新」，复制查证 prompt 给 AI |
| 我方自行决定 | 不用问人，我们定 | 复制决策草稿 prompt，AI 出一份 `output/decisions/` 草稿 |
| 本期不做 / 不相关 | 当场关掉 | 真终态，不用再派给谁 |
| 确需对方答复 | 要问客户 / 对方 | 进会议清单，必须填最迟答复日期 |

AI 给的结论不成立时点「再问一轮」，上一轮的内容会原样保留在轮次记录里。
凭据是「我方推断」的结论不能用来关闭问题——查不到依据就只能当待验证假设。

**产出物** —— 每份产出物的记录，按类别和状态分组。三类各有自己的状态：

| 类别 | 状态 |
| --- | --- |
| 分析 | 在写 → 已被吸收 / 过时未用 |
| 文档 | 草稿 → 已发出 → 待修订 → 已定稿 / 被取代 |
| 决策 | 待确认 → 已确认 / 已推翻 |

选一个状态、写一句补充说明、保存，就是「状态流水」里的一条。
「已被吸收 / 被取代 / 已推翻」要填被谁消解（另一份记录的编号），否则引用它的人无处可去。
记录由 AI 建（`pm-output-record` 技能），看板只改状态，不新建记录。

### 批注

在阅读器标题栏点「批注」进入批注模式：点「选取元素」点正文里的一块，或切到「选中文字」划一段，
写下意见。攒成一批，点「复制提示词」粘给 AI。

提示词里带着文件路径、选中的原文和你的意见，也告诉 AI 改完之后去哪回写结果。
每条批注有状态：**待处理 / 已采纳 / 未采纳 / 待确认**，由 AI 逐条回写，
所以发了 10 条、它改了 6 条，剩下 4 条仍然挂着「待处理」，不会被整批清掉。

这份产出物有记录时，批注落进工作空间的 `output/records/notes/I<编号>.md`，跟着工作空间和 git 走，
AI 也读得到；还没有记录时暂存在看板缓存里，让 AI 建一份记录后可以迁过去。

## 常见问题

**界面没更新？** 看板监听 `input/` `output/` `visualization/` 和 `project.yaml` 的改动，
自动刷新。其他位置的变化不在监听范围内，点侧栏底部的「重新扫描」
（侧栏收起成贴边工具条时，在「设置」里）。

**工作空间标红 / 打不开？** 目录被改名或移走了。点工作空间右侧的齿轮，重新指路径。

**docx、PDF 在网页里不渲染？** 那是原件。点「用默认程序打开」交给系统。
要在网页里读，读它在 `converted/` 里的产物。

**复制提示词失败？** 看板跑在 http 的非本机地址时，浏览器常常不给剪贴板。
改用 `127.0.0.1` 打开再试，或者从弹窗里手工选中复制。

**按钮点了没反应 / 提示「请重启服务」？** 前端升级了但常驻服务还是旧的，新接口不存在。
重启一次看板服务即可。

**看板会不会改我的文件？** 大部分时候不会。写工作空间的只有你、AI，以及下面这些**你亲手点的事**，
每一件都只在本机访问（`127.0.0.1`）时可用：

| 你点的 | 谁写 | 写哪里 |
| --- | --- | --- |
| 转换资料 | 工作空间的 `scripts/ingest.py` | `input/converted/` |
| 忽略此文件 / 目录 | 看板 | 往 `input/.ingestignore` 追加一行 |
| 刷新 schema | 工作空间的 `scripts/db_ingest.py` | `input/converted/_sources/` |
| 贴 URL 采集 | 看板 | `visualization/references/` `visualization/prototypes/` 下**新建**目录 |
| 刷新收件箱 | 工作空间的 `scripts/web_ingest.py` | 散装页面收成新参考目录，正文进 `input/converted/` |
| 刷新原型 | 原型工作区的同步脚本 | 该原型的镜像目录 |
| 保存未决问题 | 看板 | 那一份 `Q<编号>.md` 的人工反馈部分 |
| 保存产出物状态 | 看板 | 那一份 `I<编号>.md` 的状态与流水 |
| 批注复制提示词 | 看板 | 追加到 `output/records/notes/I<编号>.md` |
| 归档 | 工作空间的 `scripts/archive_output.py` | 把那一份移进同组 `一次归档/`，并往那里的 `README.md` 追加一行 |

产出物的内容（`analysis/` `docs/` `decisions/` 里的文件）、`input/raw/` 原件、`project.yaml`
看板一个字节都不改；归档只挪位置不改内容。不删除、不覆盖任何已有文件。
