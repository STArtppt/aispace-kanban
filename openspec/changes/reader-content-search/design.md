## Context

预览窗(`src/app/components/Reader.tsx`)按 `item.reader` 分七种形态渲染:
markdown 正文、表格(单表 / 多表包)、纯文本、图片、HTML 原型、图库、不渲染的原始格式。
其中真正"有大段文字可读"的只有四处:markdown 正文、表格包的「摘要」页、
HTML 原型的「校验说明」页、纯文本预览 —— 前三者都走同一个 `Markdown` 组件,
最后一个是一个 `<pre>`。

现状里能帮人定位的只有右缘的文档目录(`DocumentToc`),它的条目来自渲染后的 DOM 标题,
所以只到标题一级;正文里的一个词没有任何入口。

两条必须尊重的现有机制:

1. **批注锚点**。markdown 正文在可批注时由 `rehypeSourcePos` 盖上契约 A2 属性
   (`data-source-file` / `data-source-range`,UTF-8 字节区间),`AnnotationLayer` 再把
   字节区间映射回文本节点建 `Range`。**正文里任何文本节点的插入、拆分、删除都会让已有批注错位。**
2. **表格数据页只拉一页**(`TABLE_PAGE_SIZE = 50`),大点表从不整份进内存;
   HTML 原型装在带 `sandbox` 的 iframe 里,看板读不到它的 DOM。
   这两处不是"暂时没做搜索",是**结构上搜不了**。

本仓前端没有动画库,没有模糊匹配库,没有 popover 基元;标题栏用的是 `HeaderIconButton`,
列表页的关键词过滤用的是 `ExpandableSearch`(横向展开的输入框,无结果列表)。

交互形态参考同机另一个项目 `pentou` 的检索面板:防抖输入、结果列表带命中片段、
`{text, matched}[]` 渲染高亮(不走 `innerHTML`)、上下键翻结果、Enter 选中、
Esc 关闭并归还焦点、输入法组合期让位快捷键、选中后在正文里滚动定位并临时闪烁。
下面的决策说明哪些照抄、哪些因为"我们是单文档内检索"而必须改。

## Goals / Non-Goals

**Goals:**

- 预览窗左上角一颗搜索按钮,点开就能在**当前这一份**内容里模糊找词,并跳到位置。
- 全程前端本地计算:不发请求、不落索引、不动 `api.ts` 契约、不需要重启常驻服务。
- 一行正文 DOM 都不改动 —— 批注、目录、源码锚点全部照旧工作。
- 搜不了的形态老实说搜不了,不给假入口。

**Non-Goals:**

- 跨文件 / 全工作空间检索(要服务端建索引,是另一件事)。
- 正则、大小写敏感、整词匹配等高级选项;替换;搜索历史。
- 表格「数据」页的全表检索 —— 那需要把整张表拉进浏览器,与"只拉一页"的现有决策冲突。
- 接管 `Cmd/Ctrl+F`。

## Decisions

### 决策 1:索引建在渲染后的 DOM 块上,不建在源文本上

**选择**:打开浮层时遍历当前滚动区里的正文根(`.markdown-body` 或纯文本的 `<pre>`),
把叶子块(`h1`–`h6` / `p` / `li` / `td` / `th` / `blockquote` / `pre` / `figcaption` 等)
收成 `{ el, text }[]`,匹配和打分都对着这份数组做。命中项天然带着元素引用,
跳转就是 `el.scrollIntoView` + 加一个 class,没有第二次查找。

**备选 A:对源 markdown 文本切块,命中后用片段文本回到 DOM 里找元素**
(`pentou` 的 `locateAndFlash` 就是这么干的)。不选,两个理由:

- 源文本里有一堆用户看不见、也不该被搜到的东西:`**` 强调符、表格的 `|---|` 分隔行、
  图片与链接语法、HTML 注释。搜"表"能命中一行 `|---|` 是纯噪音。
- 文本回查会失败。`pentou` 自己就得在全串匹配不到时退化成"前 16 字 / 后 16 字"再试 ——
  它能忍是因为跨文档跳转本来就允许定位失败退到顶部;我们是同一屏内跳转,
  跳不准比不跳更难受。

**备选 B:用契约 A2 的 `data-source-range` 字节区间反查元素。** 不选:
这属性只在传了 `sourceFile` 的可批注正文上有,表格包摘要与校验说明那两处
`Markdown` 都没传 —— 一半的目标场景没有锚点,还得再写一条退路。

**代价**:索引依赖"正文已渲染完",且内容变了要重建。用**懒建**化解 ——
只在打开浮层的那一刻建一次,不打开就不花这个钱;浮层关闭即丢弃,
内容对象一变就连浮层一起关掉(见 spec"状态重置")。

### 决策 2:纯文本预览按行包一层 `<span>`,不做 Range 定位

纯文本模式渲染成一个 `<pre>`,整份内容是**一个文本节点**,没有块可索引。

**选择**:把 `<pre>` 的内容按行渲染成 `<span class="block">{line}{'\n'}</span>` ——
换行符仍是真实文本、`whitespace-pre-wrap` 的折行行为不变、复制粘贴结果不变,
但每一行成了一个可定位的块元素,直接复用决策 1 的那套索引与跳转。

**备选 A:在 `<pre>` 的文本节点上按字符偏移建 `Range`,用 `getBoundingClientRect` 算滚动
目标,高亮画成绝对定位的矩形浮层**(`AnnotationLayer` 画批注框就是这个路子)。不选:
为了一种形态引入一整套坐标计算与浮层重排逻辑,换来的收益和包一层 span 完全一样。

**备选 B:纯文本干脆不支持搜索。** 不选:纯文本恰恰是**唯一没有目录**的形态,
最需要这个功能。

**为什么这次改渲染路径是安全的**:`canAnnotate` 只在 `mode === 'markdown'` 时为真,
纯文本上没有批注、没有源码锚点,决策 4 那条红线在这里不适用。
(反过来说,markdown 正文**绝不能**用这招。)

### 决策 3:模糊匹配自己写,不引 fuse.js

**选择**:`src/app/lib/fuzzySearch.ts`,几十行:

- **分词**:连续 CJK 一段、连续 `[A-Za-z0-9]` 一段,其余作分隔(与 `pentou` 的
  `TOKEN_RE` 同构)。
- **归一**:小写化 + 全角字母数字转半角,查询与块文本都过一遍。
- **打分**:每个查询词在块里出现即得分,允许乱序与不连续;命中词数为主序,
  命中位置的密集度为次序,块在正文中的先后为末序(保证同分稳定)。
- **片段**:以第一处命中为中心开窗,切成 `{ text, matched }[]` 交给渲染。

**备选:引 `fuse.js`。** 不选:它的模糊靠 Bitap 的编辑距离,对中文是逐字符的,
"重试导出"和"导出重试"这类词序问题它并不比上面这套做得好;而 `threshold` 之外的
分词、全半角归一、片段切分我们照样得自己写。为一个前端本地功能加一个运行时依赖,
换来的只是打分公式,不划算。

**备选:不做模糊,`String.includes` 了事。** 不选:用户就是被原生查找的字面匹配逼过来的,
做成字面匹配等于没做。

### 决策 4:高亮只给块元素加 class,一个文本节点都不动

**选择**:跳转后给命中块加一个临时 class(约 2s 后移除),用 CSS 做背景/描边的淡入淡出。

**备选 A:用 `<mark>` 包住命中词。** 视觉上最直观,但**必须否决** ——
契约 A2 的字节区间是映射到文本节点上的,插一层 `mark` 就把文本节点拆了,
`domRangeFromBytes` 算出来的位置全部偏移,这份文档上已有的批注会集体错位。
这不是"可能有风险",是确定会坏。

**备选 B:CSS Custom Highlight API(`::highlight()`)。** 它确实不改 DOM,是个好东西,
但不适配这个功能的语义:我们的命中是**块级的模糊命中**(词可以乱序、不连续),
根本不存在一段连续的 `Range` 可以画;给散落的多个词各画一段,视觉上是一片碎斑。
块级高亮更诚实 —— 它说的是"你要的东西在这一块里"。

**配色**:走黑白灰令牌(`--accent` / `--muted` 一系 + `--ring` 描边),
**不用 `--destructive`(橙)** —— 按本仓约定橙只给"需要注意",而这里只是"在这儿"。
令牌与 `@keyframes` 都写进 `src/app/styles/globals.css`,组件里不硬编码色值。
批注高亮是文字底色,搜索高亮是整块描边+淡背景,两者视觉上要能分开。

### 决策 5:浮层锚在预览窗左上角,不做全屏遮罩

`pentou` 的检索是全局的,所以它居中偏上 + 毛玻璃遮罩 —— 反正结果在别的文档里,
盖住当前页无所谓。**我们相反**:用户要一边看结果一边看正文,遮罩会盖掉他要找的东西。

**选择**:浮层从搜索按钮下方展开,锚预览窗左上角,宽度约 360–420px、结果区限高;
正文始终可见。点浮层外、Esc、选中结果都关闭。

**备选:照抄全屏遮罩。** 不选,理由如上。

**备选:像 `ExpandableSearch` 那样在标题栏里横向展开。** 不选:标题栏高 `h-16`、
右侧已有 4–5 颗按钮,横向展开会把标题和路径挤没;而且这个功能需要**结果列表**,
一根横条放不下。

**注意与右缘目录轨的关系**:目录是 `absolute inset-y-0 right-0` 的 200/220px 轨道。
浮层锚左侧、宽度不越过它,层级要压过目录轨。

### 决策 6:动画用 CSS,不引 motion

`pentou` 用 `motion/react` 做浮层的进出与结果区的高度过渡。本仓依赖表里没有动画库,
且已有 `transition-[width] duration-200 ease-out` 一类的纯 CSS 写法在跑。
为一个浮层引一个运行时依赖不划算 —— 展开/淡入用 `transition`,命中闪烁用 `@keyframes`,
够用。

### 决策 7:不接管 `Cmd/Ctrl+F`

**备选:接管,最符合肌肉记忆。** 不选,两个理由:

- 我们**搜不到**的形态是实打实存在的(iframe 里的 HTML 原型、表格数据页)。
  原生查找是用户在那些地方唯一的退路,劫持了就把退路也拿走了。
- 在一块"只读看板"上抢浏览器的全局快捷键,属于越权。

v1 也不给 `/` 之类的自定义快捷键,只从图标按钮进 —— 少一条要解释的规则。

### 决策 8:搜不了的形态直接不显示按钮,不做"常显但禁用"

**备选:按钮常显,不可用时置灰 + tooltip 解释。** 不选:标题栏本来就挤,
一颗永远点不动的按钮是噪音;而且"为什么搜不了"的解释成本不低
(iframe 是隔离的 / 表格只加载了一页),藏起来比每次解释一遍便宜。

代价是可发现性:用户在 HTML 原型页看不到按钮可能会愣一下。
用"结果空态里说清搜索范围只是当前这一份"来补,见风险一节。

## Risks / Trade-offs

- **[大文档打开浮层时卡一下]** → 索引是"遍历一遍 DOM 取 `textContent`",
  块的数量级是百到千,一次同步遍历应在毫秒级;且**懒建**,不打开搜索就不发生。
  实现后拿仓库里的合成长文档实测一次,若真有可感卡顿再退到 `requestIdleCallback` 分片。
- **[两个字的关键词命中一大片,结果全是噪音]** → 结果条数设上限(暂定 50),
  按命中词数与密集度排序,列表末尾明说"只显示前 N 条";空态与超限态都要写清
  "只搜了当前这一份内容"。
- **[用户以为搜索覆盖整份表 / 整个工作空间]** → 两道防线:搜不了的形态不给按钮(决策 8);
  空态文案直说范围。**不要**写成"没有找到结果"这种让人误以为搜遍了的说法。
- **[搜索高亮和批注高亮撞车,看不出谁是谁]** → 视觉手段分开(决策 4),
  且搜索高亮 2s 自动消失,批注高亮常驻。
- **[临时高亮的 class 残留]** → 定时器要在组件卸载、换文件、再次跳转时清掉;
  同一时刻只允许一个块带这个 class。
- **[改了纯文本渲染,复制出来的文本变样]** → 换行符留在 span 内当真实文本,
  理论上 `textContent` 与复制结果都不变;这条**必须在浏览器里实测一次**
  (选中多行复制到编辑器比对),不能只看类型检查。

## Migration Plan

纯前端增量,没有接口与数据形状变化:

- **不需要重启常驻服务** —— 本 change 一行 `src/server/**` 和 `bin/cli.mjs` 都不碰。
  `pnpm build` 后刷新页面即可;开发时 `pnpm dev` 热更新直接生效。
- **没有新老进程兼容问题** —— 没有新增接口字段,旧服务进程配新前端行为完全一致。
- **回滚**:撤掉搜索按钮与 `PreviewSearch` 组件即可。唯一动到主渲染路径的是
  决策 2 的纯文本按行分块,回滚时一并撤回 `<pre>` 的原写法。

## Open Questions

- 结果条数上限取 50 是拍的,等实际用长文档试过再定。
- 纯文本按行分块对超长单行(比如一整份压成一行的 JSON)会退化成"一个块"、
  片段窗口也切不开 —— v1 先接受,若常见再考虑按字符数二次切窗。
- 表格包的「摘要」与「数据」是两个 tab,搜索只覆盖摘要。是否要在数据页给一句
  "想搜整表请用摘要里给的 sqlite 命令"的提示,还是保持安静?倾向保持安静,留待反馈。
