## Context

批注现在的形状是三段:当前批注在浏览器 `localStorage`,提示词靠用户自己粘给 agent,
归档批次写在看板配置目录 `~/.pmwork/dashboard/note-history/<工作空间 id>.json`
(`src/server/note-history.mjs`,文件开头的注释原话是「不碰工作空间」)。

这个形状当年成立,是因为它一条只读红线都不用动。代价现在显出来了:

- **工作空间里的 AI 读不到批注**。它能读到的只有被改过的正文,读不到「人当时提了什么、为什么」。
- **批注不跟工作空间走**。换机器、重装、换人接手就全丢;git 同步不经过看板配置目录。
- **没有逐条闭环**。`AnnotationToolbar` 里那段 effect 是「文档 mtime 一变就整批 append 进历史、
  `onClear()` 清掉页面标记」,不看 agent 改没改全。发 10 条、改了 6 条,10 条一起归档,
  剩下 4 条没有任何地方记着。

`output-item-record` 刚落地,给了两样本 change 需要的东西:
`output/records/I<编号>.md` 这个**按产出物聚合的挂载点**,以及一套已经跑通的
「人写区 / AI 写区物理隔开、看板只改已存在文件、先写临时文件再原子替换」的写入形状
(`src/server/records.mjs` 下半部分)。本 change 沿用它,不另起一套。

## Goals / Non-Goals

**Goals:**

- 批注落进工作空间,跟着 git 和机器走,工作空间的 agent 读得到。
- 每条批注有自己的状态,由 agent 回写,而不是从「文档变了」推断。
- 未回写的批注不消失、能再发一次 —— 这才是「闭环」两个字的实际内容。
- 提示词自带回写路径与格式,agent 冷启动也知道该在哪里交代结果。
- 放宽只读红线的口子**压到最小**,并且把边界写死在 spec 与 AGENTS.md 里。

**Non-Goals:**

- **不做归档搬运**(`output-archive` 那条线),两者唯一的交集是「归档后的产出物路径会变」,
  本 change 只保证 `target` 变了之后批注文件仍按编号找得到。
- **不改锚点算法、不改两种选法、不改标记点交互**。本 change 只动「批注去哪儿、状态怎么回来」。
- **不让看板调 agent**。`preview-annotation` 已经定过调子:用户自己把提示词粘到开着的会话里,
  看板不起任何子进程。回写状态是 agent 在用户终端里做的事,不需要看板的任何权限。
- **不做跨文档的批注总览页**。批注清单仍然是「当前这篇文档」的清单。
- **不把旧批注重新贴回被改写后的文档**。原要求保留,坐标对不上就是对不上。

## Decisions

### 1. 落点:`output/records/notes/I<编号>.md`,一份产出物一个文件

批注文件与记录文件同编号、放在记录目录的 `notes/` 子目录下。

备选 A:**写进记录文件本身的正文**。不选 —— 记录正文除「## 状态流水」外整块是 AI 写区
(`records/README.md` 写死的),看板往那里写就把刚立的分区规矩自己破了;
而且一批十几条、每条带选中原文,几轮评审就能把一份两屏的记录撑成十屏,
状态流水会被埋掉。

备选 B:**每批次一个文件**(`notes/I0007-2026-09-22.md`)。不选 —— 文件数按「产出物 × 评审轮数」
膨胀,而 agent 要回答的是「这份文档上还有哪些没处理的批注」,那是**跨批次**的问题,
分文件等于每次都要先把散件拼回去。

备选 C:放 `output/records/` 根上叫 `I0007-notes.md`。不选 —— `scanRecords` 认的是
`^(I\d{4})\.md$`,`I0007-notes.md` 不匹配会被静默跳过,但这是「靠正则没匹配上」的隐式排除,
将来正则一松就漏。`notes/` 是目录,`scanRecords` 那层 `entry.isFile()` 天然不收,
是**结构上**排除的,比正则可靠。

### 2. 写盘的时机是「复制提示词」,不是「文档被改动」

**这是本 change 最关键的一条。** 现行归档由文档 mtime 变化自动触发 ——
搬进工作空间之后,那等于「agent 改完文档,看板在用户没看着的时候往工作空间写了一个文件」,
直接撞上历次窄例外都守着的第③条:**必须用户明确发起,没有后台任务、没有定时**。

所以写盘的时机改成用户点**「复制提示词」**的那一刻:这一批要发出去了,
把它们以 `pending` 落进 `notes/I<编号>.md`,提示词里带上这个文件的路径。

顺下来的好处是连锁的:

- 写入由用户的点击发起,与第四、六条例外口径一致;
- agent 拿到提示词的同时,批注已经在工作空间里等着它回写,不存在「先改完再落盘」的时间差;
- 文档之后被改动时,看板要做的只剩**清页面标记**(纯前端,不写盘),
  归档失败、403、写坏文件这些分支整片消失。

备选 A:保持自动归档,把例外的第③条放宽成「用户发起的批注 + agent 发起的文档改动」。
不选 —— 那条是整套窄例外里最不该动的一条,一旦松掉,以后任何写入都能论证「这也是用户间接发起的」。

备选 B:在胶囊上单加一个「归档这一批」按钮。不选 —— 多一个按钮,而它的语义
(「我要把这批发出去了」)与「复制提示词」完全重合;用户会点了复制忘了归档,
于是回写无处可去,闭环在第一步就断。

**重复点复制不会产生重复条目**:落盘按条目指纹(源码区间 + 选中原文 + 意见)去重,
文件里已有的不再追加,只追加新写的那几条。用户改了某条的意见再复制,指纹变了会多出一条 ——
这是对的,那是一条新意见,旧的那条 agent 可能已经处理过了。

### 3. 一条批注一个 `###` 小节,状态与回执各占一行

```markdown
## 2026-09-22 · 第 1 批

### N0003 · 段落

- 状态：pending
- 回执：
- 源码区间：1204,1876

> 选中的原文引用

意见：这里的口径和第二节对不上。
```

分界按**行**划:看板只**整条追加**,追加之后这一条一个字都不再改;
agent 只改「- 状态:」与「- 回执:」这两行。两边不会写到同一行,
与 `records/README.md` 那套「人写区 / AI 写区物理隔开,因此不需要锁」是同一个办法。

备选:给每条批注做成带 front-matter 的独立文件。不选 —— 一篇文档一轮评审十几条,
文件数量级直接失控,而这套格式的读者是 agent,它读 Markdown 比读一地碎文件强。

### 4. 四个状态,终态必须有回执

| 状态 | 含义 | 约束 |
| --- | --- | --- |
| `pending` | 待处理。看板落盘时一律是它 | 回执为空 |
| `adopted` | 已采纳,正文照这条改了 | 回执写改了什么 |
| `rejected` | 未采纳 | 回执 **MUST** 写原因 —— 没有原因的拒绝等于没有回答 |
| `unclear` | 看不懂 / 需要人确认 | 回执写卡在哪 |

照 `records` 那条经验:**状态必须对应分化的后续动作**。四个状态各自对应一个明确的下一步
(等、无、看原因决定要不要争、回去把话说清楚),没有第五个能对应上动作的状态,所以就四个。

### 5. 批注编号 `N<四位>`,与页面上的「批注 N」是两套

页面标记点仍然按当前批次 `1..n` 编号(用户看的是这一批),
写进文件的是工作空间内该产出物下唯一、只增不复用的 `N<四位>`。
提示词里两个都带:`### 批注 3 · N0003`。

回写按 `N` 编号定位。不这样的话,第二批的「批注 1」和第一批的「批注 1」在文件里撞名,
agent 改错行没有任何东西拦得住。

这也意味着 `preview-annotation` 里「每条标题里的批注 N MUST 与页面标记点和清单里的编号一致,
MUST NOT 按处理顺序重新编号」那句要跟着扩:页面序号照旧不变,**再加**一个稳定编号。

### 6. 未回写的批注保留为 `pending`,并且能再发一次

文档被改动 → 页面标记点与高亮照旧清掉(坐标失效,这条不变),
但清单 MUST 把「这份文档上还有几条 `pending`」摆出来,并给一个
**「把未处理的重新组装成提示词」**的出口。

这就是 proposal 里「归档不再整批一刀切」的落地形态:不是把失效的标记点硬留在页面上,
而是让没被处理的那几条在清单里可见、可重发。重发的提示词 MUST 说明
「源码区间可能已失效,以原文引用为准」—— 现行提示词已有一句同义的话,扩一句即可。

### 7. 没有记录的产出物:退回看板缓存,并说清怎么接上

批注挂在记录上。`target` 反查不到记录(这份产出物还没建记录,或者根本不在 `output/` 下,
比如 `input/converted/` 的资料)时,MUST NOT 报错、MUST NOT 拒绝批注 ——
退回现状(写看板缓存目录),并在清单里说明「这份还没有记录,批注暂存在看板缓存里;
让 agent 建一份记录之后可以迁过去」。

看板 **MUST NOT** 替它建记录:第六条例外①「不新建记录文件」原样保留,建记录是
`pm-output-record` 技能的活。

### 8. 读是双源的,写只写一处

读:工作空间的 `notes/I<编号>.md` + 看板缓存目录,两边合并后按时间倒序给前端,
每条带 `source`(`workspace` / `cache`)。缓存目录**只读不再写新的**(除第 7 条那种没记录的情况)。

这让存量迁移不是必须先跑完的前置:没迁的照样看得见,迁过去的也看得见,
迁移脚本可以慢慢跑。

### 9. 「清空历史」收窄成「只能清缓存那一半」

现行 spec 有「用户 MUST 能清空该文档的历史」。搬进工作空间后这句要收窄:
**已经写进工作空间的批次不能从看板清空**,删除由用户自己在文件系统里做 ——
与 `capture` 那条例外的第⑤条同一口径。看板上的「清空历史」只清缓存目录那一半,
按钮文案与提示要说清楚它清的是哪一半。

### 10. 非环回(`--host`)时:提示词照给,但不落盘且不带回写路径

写盘要过 `allowMutations` + `rejectIfForeignOrigin`,非环回一律 403。
但复制提示词本身不该因此不可用。

决定:落盘失败(403 或别的原因)时,提示词照常进剪贴板,但 MUST 去掉回写那一段、
MUST 说明这次没有落盘、agent 无处回写。MUST NOT 给一句「保存失败」了事 ——
用户拿着一段带路径的提示词去让 agent 回写一个根本不存在的文件,比不给更糟。

## Risks / Trade-offs

**[看板开始往工作空间新建文件]** → 第六条例外原本写死「只改已存在的文件,不新建」,
而首次给一份产出物写批注时 `notes/I0007.md` 还不存在。这是本 change 对那条例外的**实质扩张**,
不是同形复用。压法:新建只允许发生在 `output/records/notes/` 下、文件名只能是
`I<四位编号>.md`、且**该编号的记录文件必须已存在**(记录不存在一律 404,建记录仍归技能),
除此之外仍然不新建、不删除、不改名。**这一点需要人在审阅时单独确认**,见 Open Questions。

**[这是窄例外里体量最大的一笔写入]** → 一批十几条、每条带整段选中原文。
压法:spec 把「只追加、不改写已有条目、不删除」写死,并设单条意见与整批条数的上限;
超限一律 400 且不落盘。它 MUST NOT 成为「往工作空间写别的东西」的先例。

**[agent 不回写,状态永远停在 pending]** → 看板管不了 agent 做不做。
缓解:提示词里带格式、`pm-output-record` 技能里写清楚、清单把 `pending` 条数摆在明面上。
承认剩余风险:agent 就是不写的话,结果与现状持平(现状是连记都没记),不会更差。

**[两套编号(页面 1..n 与 `N<四位>`)会让人看花]** → 缓解:提示词与清单里始终两个一起出现,
页面标记点只出现页面序号;文件里只出现 `N` 编号。不在任何一处只给一半。

**[存量迁移按 `target` 反查可能一条都命中不了]** → 老工作空间可能压根没有 `records/`。
缓解:迁移脚本默认预演、不落盘;没命中的一条不删,缓存目录作为只读回退源继续可读。

**[`target` 改名后批注文件与产出物脱钩]** → 批注挂的是记录编号,不是路径,
产出物改名时 agent 跟进记录的 `target` 即可,批注文件不用动。这正是挂在记录上而不是挂在路径上的理由。

## Migration Plan

1. 先上读:双源合并读取 + 前端显示 `source` 与状态。这一步不写任何工作空间文件,可单独验收。
2. 再上写:复制提示词时落盘,带回写路径的提示词同步上线。
3. 最后跑迁移脚本(默认预演):按 `target` 反查把缓存目录里的历史批次搬进对应的 `notes/` 文件,
   状态一律填 `pending`(它们当年就没有回执),来源标注为迁移。没命中的留在缓存里。
4. 回退:迁移脚本只**追加**,不删缓存目录里的任何东西;想退回旧行为,停用落盘那一步即可,
   读仍然双源,已经搬过去的批注照样看得见。

## Open Questions

- **(需要人拍板)** 允许看板在 `output/records/notes/` 下**新建**批注文件 —— 这是对第六条例外
  「不新建」那一款的实质扩张。决策 1、3 与 Risks 第一条已经把边界写到最小,
  但要不要开这个口子,应当与当初拍板「批注搭第六条例外」分开确认一次。
  若不开,替代形态是:`pm-output-record` 技能建记录时一并建一份空的 `notes/I<编号>.md`,
  看板仍然只改已存在文件 —— 代价是老记录都要先补跑一遍技能才能写批注。
- 单条意见与单批条数的具体上限取多少,写 spec 时定;先按「意见 1000 字 / 单批 50 条」起步。
