# aispace-kanban

**与 AI 反复对话完成知识工作的只读看板。**

---

**本地空间** 
- 服务起在你自己的机器上,工作空间就是本地一个普通**文件夹目录**;
- 资料不上传、不进云端,默认只有本机能连。

**AI 协作**
- 内置「产品经理AI空间模板」,也可按角色复制提示词让 AI 再建一份;
- 新建工作空间时选模板类型,骨架和技能跟着角色走。

**网页浏览**
- 不管何种格式、不管输入输出，均通过网页预览或打开；
- 丢入原始文档可启动一键转换，AI输出文档会自动扫描渲染。

**人机易读**
- AI读转换后的 .md 文档，又快又省，人类读网页渲染的文档，顺畅高效；
- 指引AI阅读上下文，明确目标实现最终成果。

## 用法

一条命令起服务,浏览器会自动打开(macOS / Windows / Linux 都一样,只要有 **Node.js ≥ 20**):

```bash
npx -y @startist/aispace-kanban@latest
```

然后在界面上「添加工作空间」指一个目录就行。也可以用命令登记:

```bash
npx -y @startist/aispace-kanban@latest add ~/work/某个工作空间
npx -y @startist/aispace-kanban@latest list
```

serve 的选项:`--port <n>`(默认 7788,被占用时自动往上顺延至多 10 个)、
`--host <addr>`(默认 127.0.0.1,只有本机能连)、`--no-open`(不自动开浏览器)。

## 什么算一个「工作空间」

就是一个普通目录,**准入门槛只有两条:有 `input/` 和 `output/`**。
`mkdir -p 我的调研/{input,output}` 就能加进看板,不需要装模板、不需要跑脚本。

看板认的是这套目录约定:

```
你的工作空间/
├── project.yaml         这摊活儿的元信息(可选,没有就不显示这块)
├── input/
│   ├── raw/               你丢进来的原始材料(PDF / docx / xlsx / 网页存档…)
│   ├── converted/         转成 AI 能读的 .md / .csv,带溯源 frontmatter
│   └── assets/            图片资料,按来源分目录(单张图进 未分类/)
├── output/
│   ├── analysis/          中间产物:摸底、拆解、待确认问题清单
│   ├── docs/              成稿:报告 / 方案 / PRD / 稿件
│   └── decisions/         决策记录,一事一档,只追加
└── visualization/       视觉平面:给人看、能点开的页面(可选)
    ├── references/      收下来的别人的页面:竞品、友商后台、公开文档站
    └── prototypes/      工具产出的可点击原型
```

这套目录不是随便定的,它对应**与 AI 协作的一条单向流水线**:
`原料 → 加工成 AI 可读 → 分析 → 成稿`。
每一步的产物是下一步的输入,所以每一步都能被单独检查、单独重做。

自己建目录、按这个结构往里放文件就够了。要一套开箱即用的骨架(含转换脚本和 AI 技能),
见下面「[配套的工作空间模板](#配套的工作空间模板)」。

## 它适合哪些活儿

任何**「资料进来 → 和 AI 反复对话 → 文档出去」**的知识工作:

| 场景 | `input/` 放什么 | `output/` 长出什么 |
| --- | --- | --- |
| **市场 / 竞品调研** | 行业报告 PDF、财报、网页存档、访谈录音转写 | 竞品矩阵、结论摘要、调研报告、选型决策 |
| **方案与标书撰写** | 招标文件、客户资料、往期方案 | 需求理解、技术方案、报价说明、废标风险清单 |
| **数据分析** | 导出的 xlsx / csv、埋点日志 | 口径说明、分析结论、图表说明、复盘 |
| **内容创作** | 素材、采访稿、参考资料、往期内容 | 大纲、初稿、改稿记录、选题决策 |
| **接手一个既有项目** | 交接来的一堆 docx / PDF / Excel | 现状基线、需求拆解、PRD、澄清问题清单 |

共同点是:**材料是别人给的、结论要能被追问、产出要交出去。**
这三条一旦成立,「AI 说了什么」就不够了,你需要看见「文件里现在是什么」。

## 四个视图

| 视图 | 回答什么问题 |
| --- | --- |
| **概览** | 这摊活儿现在到哪一步了?元信息还有哪些字段是空的?`project.yaml` 还没有时,阶段是按目录状态**推断**的,界面上会明确标「推断」 |
| **输入资料** | 我给 AI 的料,它拿到了多少?原始资料 / 转换产物对账,**还没转换**和**转出来内容存疑**的单独标橙 |
| **产出文档** | AI 到底写了什么?`output/` 的分析 / 成稿 / 决策三栏,带篇幅和更新时间 |
| **视觉呈现** | 参考和可点击的产物在哪?「参考」列 `visualization/references/` 里收下来的页面(点开进查看器,左下角浮截图),「原型」列 `visualization/prototypes/` 里已构建的 HTML 包和云端发布链接 |

产出多了、有些已经不作数时,在那一行的「更多」里点**归档**:文件移进同组的 `一次归档/` 目录,
从主列表里分出去,但**不删除** —— 照样能搜、能点开预览,AI 需要时照样能读。
移动由工作空间自己的 `scripts/archive_output.py` 完成(用模板新建的工作空间自带),看板不写盘。

`.md` 那一行的「更多」里还有**转成 Word**:选一个模板(「通用规范」或工作台里提炼出的客户模板),
然后「转换」—— 成品写在 `.md` 同目录、同名的 `.docx`,完成后 toast 里点「预览」直接在看板里看分页版式;
或者「复制提示词」,交给工作空间 AI 去转(适合要让 AI 顺手修 md 写法的时候)。
转换由工作空间的 `scripts/md2docx.py` 完成,看板不写盘。同名 `.docx` 只有是上次转出来的(带生成标记)
才能勾选覆盖,人手改过或客户给的同名 Word 一律不覆盖。**直接转换需要本机装有 pandoc 3**
(macOS `brew install pandoc`;装在别处时在工作空间 `.env` 里写 `PANDOC_BIN=<路径>`),没装时「转换」置灰,「复制提示词」照样能用。

转换时顺手处理 md 里的写作习惯,只动格式、不改文字:开头唯一的 `#` 取作文档标题(`##` 起是一级标题)、
模板标题样式带编号时剥掉手写的 `1.` / `一、`、`> [!note]` 这类批注块转成提示框、只保留段首标签式加粗。
模板从带封面的客户 Word 提炼时,成品会带上**前置区**(封面、签署页、版本跟踪表、目录):封面上的标题、客户单位、
编制单位、日期按这份文档填,签署页只留空格子,目录打开 Word 时更新;取不到值的字段显示「【待填：…】」,
toast 里用橙色提醒。每一类处理了几处,在成功 toast 里展开「处理记录」就能看到。

「更多」里还有**去 AI 味…**:复制一段提示词,让工作空间 AI 按规则库把这份文档改写成**交付稿**,
写到 `output/delivery/`,原稿一个字节不动。有交付稿的文档,阅读器顶部会出现**版本条**:「原稿 · v001 · v002…」切换阅读,
「与原稿对比」「与上一版对比」看改了什么(段内逐字标出),对某一版「转成 Word」,成品落在交付稿旁边。
要改交付稿就在那一版上**批注**、复制提示词:AI 改出下一版,同一轮把能推广的写法偏好沉淀进规则库,
回执里的「沉淀为 R0xx」在批注清单里显示成可点的标签。原稿在交付稿之后又改过、交付稿被人绕过批注直接改过,版本条上用橙色标出。

`input/` `output/` `visualization/` 有变化时通过 SSE 推给前端自动刷新 —— AI 在旁边终端里写完一个文件,
看板这边直接就变了,不用手动刷页面。

## 工作台

任意视图按 **⌘K**(Windows / Linux 是 Ctrl+K)打开工作台。第一次打开是**浏览页**:
五张卡片,问题单、记录单、反馈单、模版洗炼、去 AI 味。点进去之后,标题栏的「← 工作台」回到浏览页,
五个模块也可以用标题栏的标签横跳。关掉再打开,停在上次那一页。

| 模块 | 做什么 |
| --- | --- |
| **问题单** | 未决问题。从文档里点问题链接会跳过浏览页,直接打开这一条 |
| **记录单** | 产出物记录的状态。改状态只动记录文件,不动产出物本身 |
| **反馈单** | 工作空间智能体写在 `output/feedback/` 的缺陷单。先预览邮件,再用本机邮件客户端发给项目反馈邮箱;你点「我已发出」之后,看板才记下发送时间。右下角悬浮球仍然只数未决问题,点它直接进问题单 |
| **模版洗炼** | 从一份客户旧 Word 提炼模板:① 从 `input/raw/` 选来源(不提供上传,先把文件放进去) → ② 样式分析:按实际显示的格式聚成格式簇,映射到标准角色 → ③ 大纲层级与格式不一致的取舍 → ④ 生成模板并预览合成样张;旧 Word 有封面、签署页、目录时,第 ④ 步多一块「前置区」:左边对照原件,右边把封面每一段标成标题 / 客户单位 / 编制单位 / 日期 / 文档类型 / 保持原样,每张表选清空规则,也可以「不要前置区」。产物在 `output/docx-template/<模板名>/`,由工作空间的 `scripts/docx_template.py` 写,看板不写盘;采集报告只记编号前缀、字数和结构,不含正文(封面也一样)。生成模板本身不需要 pandoc,没有 pandoc 时只是没有样张 |
| **去 AI 味** | 规则库(当前版本、按类别列出每条规则的判据 / 反例 / 正例,停用的置灰)、版本与变更(每一版的变更说明、任选两版对比全文)、三张提示词卡片(给文档去 AI 味、规则库体检、「批注 → 修改 → 沉淀」及还有待处理批注的交付稿)。**只读**:规则库和交付稿都由工作空间 AI 按技能 `pm-deai-writing` 写,看板只复制提示词。旧工作空间没有这个技能时,卡片显示「未安装」,点进去复制补齐的提示词 |

反馈单、模板目录和交付稿(`output/delivery/`)不出现在「产出文档」的列表和搜索里。

右下角还有一颗悬浮球,数字是还有几条问题要澄清。点它固定进问题单,不经过浏览页。

## 什么格式都在网页里看

你丢进去的是 docx、PDF、xlsx;AI 交出来的是裸 Markdown,`##` 和 `|---|` 混在正文里。
两头都不适合直接看 —— 总不能让人对着一屏 `**加粗**` 提意见,
也不能每次评审前都手动导一遍 Word,导完还发现 AI 又改了一版。

看板把 `input/converted/` 和 `output/` 里的文件直接渲染成能读的网页,
原始格式交给系统打开,**全程不用离开浏览器去翻文件夹**:

| 格式 | 渲染成什么 |
| --- | --- |
| **Markdown** | 标题层级、表格、列表;代码块 Shiki 高亮;**mermaid 图直接画出来**(流程图、时序图、架构图不用再截图贴进去);frontmatter 不是一坨 YAML 糊在开头,而是折叠成一条溯源信息;正文里的相对图片路径自动解析,图能显示 |
| **代码文件** | `.sql` / `.py` / `.js` / `.ts` / `.go` 等常见源码,以及 yaml / json / xml:按语言高亮的代码视图,带行号,可复制原文 |
| **CSV / TSV** | 表格,大文件分页,不用下载下来开 Excel |
| **xlsx / xlsm** | 表格预览:分页、多 sheet 可切换、能搜。显示单元格已经算好的值,不重算公式、不渲染图表;超过 8 MiB 请用系统程序打开 |
| **图片** | 直接看。「输入资料」里按来源摞成图库(一份文档抽出的图算一摞,单张图归「未分类」),点开排缩略图,再点开灯箱看大图,随手复制图片路径 |
| **PDF** | 浏览器自带的 PDF 查看器内嵌预览 |
| **docx** | 在浏览器里渲染成分页版式(页面、样式、编号、表格、图片、页眉页脚),用来核对转出来的 Word 和模板样张。放在不执行脚本的隔离框里,不联网;目录、页码等域不刷新,缺字体时用替代字体,以系统程序打开为准。超过 30MB、加密或损坏的退回系统打开 |
| **.doc / .xls 等** | 网页里不渲染。点「用默认程序打开」或「在访达 / 文件资源管理器中显示」交给系统(按钮文案跟着**服务所在**的操作系统走) |

**待转换的资料可以在看板里一键转。** 工作空间带 `scripts/ingest.py` 时(用模板新建的就有),
「输入资料」视图会给出「开始转换」按钮;看板在工作空间目录里 `spawn` 该脚本,
写 `input/converted/` 的是脚本自己,页面通过 SSE 自动刷新。自己 `mkdir` 的目录没有脚本,
界面仍提示你在终端里跑。

要拉人一起看,起服务时把 `--host` 放开(如 `--host 0.0.0.0`),同一网络里的人打开你的地址就能读:
不用导出、不用发附件、也不用担心对方手里是三天前那版 —— AI 一改完,**所有人的页面自己就变了**(SSE)。

> **注意**:看板没有登录和鉴权。放开 `--host` 之后,同网络的人能读到这几个工作空间的内容。
> **会改本机状态的操作**(新建 / 登记 / 转换资料 / 贴 URL 采集 / 在文件管理器中显示 / 把反馈单标成「我已发出」/ 提炼模板 / 转成 Word)
> 在非环回监听时一律禁用,只读分享不受影响。要用这些操作,请用默认的 `127.0.0.1` 再起一次服务。
> 另外,浏览器里**别的网站**发来的写请求一律拒绝(按请求来源判定)——
> 环回地址不等于可信来源。

### 贴一个 URL 就能把参考和原型收进来

「视觉呈现」的两个 tab 顶部各有一条 URL 输入:

- **参考 · 采集** —— 贴一个**公开可访问**的网址,看板抓下自包含的 `index.html`、
  截三张图(桌面首屏 / 完整页长图 / 移动端),连同 `meta.json` 一起落进
  `visualization/references/<名字>/`。
  只适合不用登录就能看的页面;采下来的是**页面当时的全部内容,不做脱敏**。
- **原型 · 导入** —— 贴一条云端发布链接(axhub-make 发布、figma make 的 publish / share),
  只存链接和一张封面,点卡片打开的是**原站**,本地不留页面副本。

同一个网址采第二次会生成新目录(`<名字>-2`),不覆盖旧的;看板只新建,不删也不改。

**这两件事要靠本机的两个独立工具,它们不随看板一起安装** —— 看板只是在需要时调用它们:

| 工具 | 干什么 | 装不装 | 装法 |
| --- | --- | --- | --- |
| [`single-file-cli`](https://github.com/gildas-lormeau/single-file-cli) | 把整页抓成一个自包含 HTML | **参考采集必需**(它就是参考的本体) | `npm i -g single-file-cli` |
| [`playwright`](https://playwright.dev/) | 出截图 / 封面 | 可选,**缺了只是没有图** | `npm i -g playwright && playwright install chromium` |

缺 `single-file` 时参考采集会失败并告诉你装什么;缺 `playwright` 时任务照样成功,
只是参考没有截图、原型没有封面,界面上会写清少了什么、怎么补。
`playwright` 不进看板依赖是有意的:为一个可选功能让每个用户都多下一个 Chromium 不划算。

**下一步做幻灯片渲染** —— 让 `output/` 里的文档能直接当评审材料投出去,而不是先导成 PPT。
思路和进度记在 [`docs/路线图.md`](./docs/路线图.md)。

## 为什么盯着「缺口」而不是「进度」

看板全局黑白灰,**只有一种情况上橙色:需要你处理的缺口。**

- **还没转换的资料** —— 你丢进 `input/raw/` 但没转成 AI 可读格式的文件。
  它躺在目录里,AI 却读不到,这是和 AI 协作里最隐蔽的一种「以为它知道」。
- **内容存疑的产物** —— 转换产物 frontmatter 里带 `warning`(比如扫描件 OCR 没识别出东西)。
  文件在、字数是 0,不提醒的话你会当它已经进来了。
- **原件在转换后动过** —— 产物还是老的,原件的修改时间已经比它新了。
  你对着的那份 .md 可能已经不是原件现在的样子,这是最容易将错就错的一种。
- **元信息里的空字段** —— `project.yaml` 里的 `null` 是有意义的值:「该有,但资料里还没有答案」。
  看板把它们列进「待补充」,而不是当成 100% 完成度。
- **目录找不到了** —— 登记条目认的是绝对路径,你在文件管理器里改名或挪了位置就扫不到了。

还有几种信号**不上橙色,只用中性灰**,因为它们需要你判断,而不是一定有问题:

- **原件已经不在了** —— 产物记着的来源路径上,那个文件被删掉或改名了。
  转完就删原件省空间是正当用法,所以这里只如实标一句,不催你处理 —— 但你想回查原文时,
  得知道它已经不在。

- **没有被产出引用过的资料** —— 转换好了,但 `output/` 里没有任何一篇提到它。
  可能确实没用上,也可能是产出里漏了标来源。**这是和 AI 反复对话时最隐蔽的一种缺口**:
  资料明明在目录里,AI 却从没读进去,而你以为它读了。
  产出正文里出现它的路径或文件名就算引用,判定故意放宽 —— 宁可少报,不错报。
  一份产出都还没写的时候不提示(那时候全都没被引用,是常态不是缺口)。
- **产出里的标注密度** —— 每篇产出后面标着它有几处 `[推断]` / `[口述待确认]` / `[空白]`。
  **标注是 AI 老实交代的产出,不是要你去修的缺陷**,所以不标红:把它标成错误,
  只会让 AI 学会少写标注,正好跟溯源纪律反着来。

这背后是一条对 AI 协作的判断:**AI 最擅长把话说圆,最不擅长承认自己没有依据。**
所以这套约定反复要求区分「资料里写的」和「我推断的」,而看板负责把没写、没读到、
没依据的部分**显式摆出来**,不让它们被一屏漂亮的产出盖过去。

转换产物的 frontmatter 记着来源路径、sha256、转换工具和时间,阅读器里折叠成一条溯源信息 ——
任何一句结论都能一路追回你最初丢进来的那份原始文件。展开这条信息还有个**「校验原件」**按钮:
列表上的「原件转换后动过」是按修改时间判的,网盘同步、`git checkout` 这类只碰时间戳的操作也会算进去;
点一下会重算原件的 sha256 跟产物记的比,告诉你内容到底变没变,再决定要不要重转。

## 配套的工作空间模板

[`templates/`](./templates) 里是开箱即用的骨架(看板的「新建」就是从里面选一份铺出来的)。
内置第一份是 [`templates/pm-aispace`](./templates/pm-aispace)(产品经理AI空间模板):

- `scripts/ingest.py` —— 把 docx / PDF / pptx / xlsx / html 批量转成 Markdown 和 CSV,
  自动写溯源 frontmatter,幂等(源文件没变就跳过)。PDF 默认走本地 anydoc,不外发;
  扫描件 / 抽图 / 复杂版式才升级 MinerU
- `scripts/docx_template.py` + `scripts/md2docx.py`(公共代码在 `scripts/docxkit/`)—— 从客户旧 Word 提炼模板、
  按模板把 `.md` 转成 `.docx`;只用 Python 标准库,转换另需 pandoc 3。终端、工作空间 AI、看板跑的是同一份脚本。
  这之前建的工作空间没有这两支脚本,看板会提示,「复制提示词」里带着补齐的说明
- `.claude/skills/` 下预装的 AI 技能,以及一份多 Agent 通用的 `AGENTS.md` 工作约定

看板本身不认这些技能 —— 它只认 `input/` `output/` 的目录约定。没有符合你角色的模板时,
在「新建」对话框里复制提示词发给 AI,它会按你的工作方式建一份空间,并把模板留在
`~/.pmwork/templates/` 供下次再用。

用模板需要 **Python 3**(Windows 上 `py` 或 `python`,macOS / Linux 上是 `python3`)。
不用「新建工作空间」这个功能可以不装。

## 想先看看长什么样

`templates/pm-aispace/` 是**空骨架**,自己不带任何示例内容,刚指过去四个视图当然都是空的。

要看一个走完四阶段的完整样本,去 Releases 下载 **`数字孪生示例工作空间.zip`**,
解压后在看板里「添加工作空间」指向它:概览有元信息完整度,输入有 1 份资料,产出有 8 篇文档。
示例项目是虚拟的,资料本身就自标「假定」—— 它演示的重点是**怎么把「资料没写」和「我推断的」
老老实实标出来**,而不是把文档写满。

## 破坏性变更:原型搬进 `visualization/`

**原型的落点从工作空间根上的 `prototypes/` 改成了 `visualization/prototypes/`,不留双根。**
看板不再扫旧位置,也**不会代你搬家**(它对工作空间只读)。升级后原型那一栏会空 ——
在工作空间根目录跑一次:

```bash
mkdir -p visualization && mv prototypes visualization/prototypes
```

没搬之前,「视觉呈现 → 原型」的空态会显示这条命令;搬完不用刷新页面,卡片自己就出来了。
新建的工作空间直接带 `visualization/references/` 和 `visualization/prototypes/` 两棵空树。

同时第四个视图从「原型」改名为「视觉呈现」,内分「参考 / 原型」两个 tab。
「上次打开的视图」不受影响,不需要任何迁移。

## 登记与迁移

登记条目认的是**目录绝对路径**。在文件管理器里改了文件夹名或挪了位置,看板就扫不到内容了 ——
侧栏那条会标上橙色警告,点进去填新路径即可(也可以 `relink <id> <新目录>`)。
`id`、显示名、登记时间都保留,不用重新加一遍。

不想在看板里看到某个工作空间(比如已归档),在设置弹窗里「移出看板」。
**只删登记信息,本地目录和文件一个都不动。**

登记信息存在 `~/.pmwork/dashboard/projects.json`(Windows 在 `%USERPROFILE%\.pmwork\`,
和 Axhub Make 的 `~/.axhub/make/projects.json` 一个套路)。

## 从源码跑

```bash
pnpm install
pnpm build                                  # 构建前端（首次必须）

node bin/cli.mjs add ~/work/某个工作空间     # 登记一个工作空间
node bin/cli.mjs serve                      # 起服务 → http://localhost:7788
```

开发时用 `pnpm dev`:同时起接口服务(7788)和 Vite(5180),改前端代码即时热更,
浏览器开 <http://localhost:5180>(dev 模式不自动开浏览器,因为 Vite 还要几秒才起得来)。

打包发布:`pnpm build:npm && pnpm pack:npm && pnpm smoke:npm`(最后一步在干净目录
装上真跑一遍)。推 `v*` tag 由 CI 自动发 npm。

## 设计系统

UI 组件来自 startist-ui(暂未开源,demo 见 <https://ui.startist.top/>),
通过 shadcn registry 拉取(copy-in)。更新组件的方法:

```bash
npx shadcn@latest add https://ui.startist.top/r/<组件名>.json --yes --overwrite
```

配色遵守 startist 的硬约束:黑白灰为主,**orange(`--destructive`)只用于"需要注意"** ——
在这个看板里就是上面「缺口」那一节列的几种情况,别的地方一律不上彩色。
