## 1. `output/` 的分组改成数据驱动

### 问题

`src/server/scan.mjs` 的 `scanOutput` 里，产出分组是写死的三个名字：

```js
for (const group of ['analysis', 'docs', 'decisions']) { … }
```

这三个名字来自模板的 PM 流水线（分析中间产物 / 对外交付文档 / 决策记录），
`src/app/components/OutputPanel.tsx` 的 `GROUPS` 常量里连标题和说明文案都是 PM 语境的
（「PRD、需求规格、评审材料」）。

看板已经把自己定位成**通用的 AI 知识工作看板**（README 开头那一节），
准入门槛也只有 `input/` + `output/` 两个目录（`config.mjs` 的 `inspectWorkspace`）。
于是出现一个矛盾:

- 做市场调研的人建了 `output/竞品/`、`output/报告/` —— **看板一个字都不显示**，
  文件在磁盘上、界面上却是空的。这比不显示更糟：它让人以为 AI 没写。
- 反过来，`output/decisions/` 是空的时候，界面照样给一块「决策记录 · 一个决策一个文件」的
  空态，对一个写稿子的人来说是纯噪音。

**判据一句话：目录约定是产品的一部分，但目录的「名字」不该是。**

### 怎么改

按 `dashboard-feature-flow` 的顺序，服务端 → 契约 → 前端。

**服务端**（`scan.mjs`）：扫 `output/` 下的一级子目录，而不是查表。

- 保留 `analysis` / `docs` / `decisions` 三个键，让老前端和老服务都不受影响（见下面兼容性）。
- 新增 `groups: { key, name, files }[]`，key 用目录名，顺序：已知的三个排前面（保持现在的观感），
  其余按目录名 `localeCompare(zh)`。
- 沿用 `listFiles` 的 `SKIP` 集合和 `rel()`，别另起一套。
- `output/` 下的**散文件**（不在任何子目录里）现在是被忽略的，一并收进一个默认组，
  否则用户在 `output/` 根上直接写一篇就消失了。

**契约**（`src/app/lib/api.ts`）：`output` 加 `groups?: OutputGroup[]`，**可选**。
三个老字段一个都不删 —— 用户完全可能跑着旧服务进程配新前端。

**前端**（`OutputPanel.tsx`）：

- `groups` 存在就按它渲染；缺失（旧服务进程）就退回现在的 `GROUPS` 常量，行为完全不变。
- 标题文案：已知的三个 key 沿用现在的中文名和说明；未知 key 直接显示目录名，**不编说明文案**
  （编不出来就别编，目录名本身已经是用户起的名字）。
- 空目录不再无条件给空态：只有已知的三个组保留空态提示，用户自建的组为空时不渲染。

### 顺带要动的

- `templates/pm-aispace/project.yaml` 的 schema 是乙方交付项目的字段（甲方 / 承建方 / 合同编号 / 质保期）。
  **`meta.mjs` 的 `walk()` 其实完全通用** —— 它不认识任何字段名，只统计叶子节点空不空，
  所以这块不用改看板。按场景铺不同的 `project.yaml` 和技能集是各模板自己的活，
  与本条改动可以分开做，别混在一个提交里。
- `OverviewPanel` 的「工作空间进度」四阶段也是按固定目录判的，等本条落地后一起看。

### 验收

- 建一个只有 `output/竞品/`、`output/报告/` 的工作空间，两组都能列出来、能点开。
- 老三样目录的工作空间，界面和改动前**逐像素一致**（这条是回归线，不达标就是改坏了）。
- 用旧服务进程（不重启 serve）配新前端，产出视图仍按三栏正常显示，不白屏。

## 2. 幻灯片渲染

### 问题

看板的第二个用途是**把 AI 产出的裸 Markdown 变成能给人看的东西**（见 README
「让产出能直接给人看」）。现在这条路走到「渲染成好读的网页」为止，
但知识工作的最后一公里往往是**开会讲**：评审、汇报、给客户过方案。

到了这一步，现在的做法是把 `output/docs/` 里的 Markdown 手动导成 PPT。
两个后果：一是费时间，二是**导出的那一刻就和源文件脱钩了**——
AI 改完文档，投影上那版还是旧的，而这正是看板一开始要解决的问题。

### 怎么改

**这是纯前端改动**：文件内容已经由 `/api/projects/:id/file` 给出来了，
服务端和契约（`api.ts`）一个字都不用动，也就不存在「忘了重启 serve」那类坑。

- **哪些文档能放幻灯片**：不要新增 `output/slides/` 这种硬编码目录——那跟第 1 条
  「目录名不该是产品的一部分」的方向正好相反。改成**阅读器里的一个「幻灯片」开关**，
  任何 markdown 都能切；文档想默认以幻灯片打开，就在 frontmatter 里写个标志位
  （`slides: true`），沿用 `frontmatter.mjs` 已经能解析的扁平 kv，不引额外依赖。
- **怎么分页**：按顶层 `---` 分隔符切（marp / reveal 的通行写法），没有 `---` 时退回按
  `##` 切。注意 `parseFrontmatter` 是靠开头的 `---` 认 frontmatter 的，
  切页要从正文（`body`）上做，别在原文上正则，否则第一页会把 frontmatter 吃进去。
- **必须继续能用的东西**：mermaid 图和 Shiki 高亮在幻灯片里要照常渲染——
  它们是 `Markdown.tsx` / `MermaidBlock.tsx` / `MarkdownCodeBlock.tsx` 现成的能力，
  幻灯片模式复用同一套渲染管线，不要另写一份。
- **放映**：全屏、左右方向键翻页、页码。字号要跟着容器放大，不能沿用正文的 `text-sm`。
- **导出**：走浏览器打印（`@media print` 每页一屏 + `window.print()`）出 PDF。
  **不要往工作空间里写导出文件**——只读红线，导出只能落到用户的下载目录。

### 验收

- 一篇带 mermaid 和代码块的文档，切成幻灯片后图和高亮都在。
- 没有 `---` 的普通文档切过去也能用（按 `##` 分页），不报错、不空白。
- 关掉幻灯片开关回到正常阅读视图，行为和现在完全一致。
- 深色模式下投影可读（深色底白字，不是一片灰）。

## 3. 多角色的工作空间模板

通道已经铺开：`templates/` 多目录扫描 + `~/.pmwork/templates/` 用户自建，
新建对话框能选模板类型，也能复制提示词让 AI 按角色再建一份。

还没做的是**更多内置模板本身**：

- 市场 / 竞品调研、内容创作——README 的场景表里已经把这两个的 `input` / `output` 形态写清楚了。
- `pm-doc-ingest`（资料入库）和 `skill-creator` 是所有角色都要的，
  越晚拆公共层，后面每个角色要背的无关技能就越多。
- `project.yaml` 的 schema 跟着角色走。看板这侧**不用改**：`meta.mjs` 的 `walk()`
  不认识任何字段名，只统计叶子节点空不空。

## 其余候选（还没排期，按价值粗排）

- **「上次看之后 AI 动了什么」**：把「上次查看时间」记进注册表 `~/.pmwork/`（可写，不碰只读红线），
  给未读标记和最近变更流。现在只有 mtime，看不出「这轮对话动了哪些」。
- **全文检索**：跨 `input/converted` + `output` 的关键词接口。几十上百篇之后没搜索，
  就只能回去问 AI —— 而那等于让它自己给自己打分。
- **多工作空间横向首页**：现在一次只看一摊，做知识工作的人常同时开三五摊。
  一个「每摊各有多少缺口、最近谁动了」的总览才撑得起「看板」这个名字。
- **原型视图去 Axhub 化**：`prototypes.mjs` 现在认的是 `prototypes/.axhub/make/sidebar-tree.json`。
  放宽成「任何 `prototypes/*/index.html` 都列出来」，调研的图表报告、分析的可视化产出就都能进来。
  `describeConverted` 已经会处理 HTML 包了，能力有一半是现成的。
- **批注回流**：在看板里发现「这段是编的」，现在只能回终端复述。
  批注存注册表、导出成一段能直接粘给 AI 的文本 —— 保住只读红线又闭环。
