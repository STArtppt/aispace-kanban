## Why

不做的话,`output/` 三个目录只会单调变长:陈旧的分析、被取代的文档、已推翻的决策
和当下在用的东西平铺在同一个时间序里。人可以靠搜索凑合,
**但 AI 是全量读** —— 这恰恰是 `output/questions/` 那张表当年被放弃的机制
(「两百多条、一半标『高』」,最后整份没人看)。

`output-item-record` 让每份产出物有了状态,于是「哪些已经不作数了」第一次变得可判断。
但状态只是标记,文件还在原地,列表还是那么长。**缺的是把它们移走的动作。**

## What Changes

- **产出文档列表行的更多菜单加「归档」。** 点一下,那份产出物被移进
  `output/<所在子目录>/一次归档/`(如 `output/analysis/一次归档/`)。
- **归档后仍然能在看板里预览。** 这是归档目录放在各子目录**内部**的原因 ——
  `scan.mjs` 的 `listFiles` 是递归的,归档项照样扫得到、读得到。
  但它们 MUST 从主列表里**分出去**(单独的已归档分区或筛选开关),不再占主列表的位置。
- **「一次归档」目录下有一份 README**,由归档脚本维护:列出被归进来的文档、
  以及**二次归档的流程与提示词**。这份 README 是看板与工作空间 AI 之间的**异步交接单** ——
  看板不能调 AI(`preview-annotation` 已经定过这个调子:
  「用户自己粘到已经开着的 agent 会话里,看板不起任何子进程」),
  所以交接靠落一份冷启动的 agent 也能独立读懂的文件。
- **二次归档的产出是「分堆 + 每堆一份短索引」,不是「不读清单」。**
  工作空间 AI 读 README 里的提示词,把一次归档的内容按主题或阶段分堆,
  每堆写一份短索引:这堆是什么、当初为什么产生、**什么情况下需要回来翻**。
  目的是**让人和 AI 用一份几百字的索引代替翻几十份文档**,
  把读取成本降下来 —— 而不是禁止读。

**明确不做:任何形式的「始终无需再读」清单。**
一份自动生成的不读清单会影响此后所有 AI 会话的行为面,而它是 AI 的单向判断、会判错,
错一条的代价是某份资料从此没人再看。归档要降低的是**读取频率与成本**,不是**可达性**:
归档后的一切 MUST 仍然可搜索、可预览、可被 AI 按需读取。

- **归档只移动,不删除。** 别处的会议纪要、决策记录可能正写着「见某某文档」,
  与 `questions/` 的「关闭的问题保留文件、编号只增不减」同一条理由。

## Capabilities

### New Capabilities

- `output-archive`: 一次归档的触发与搬运(`spawn` 工作空间脚本)、归档目录布局、
  README 交接单的格式与维护、二次归档的提示词契约与产出形态(分堆 + 短索引)、
  「只移动不删除」与「归档不降低可达性」的约束。
- `archived-item-view`: 看板侧 —— 归档项从主列表分出去但仍可预览的呈现方式、
  更多菜单里的归档入口、归档后列表与计数的变化、短索引在界面上怎么呈现。

## Impact

| 平面 | 影响 |
| --- | --- |
| 服务端 `src/server/**` | `http.mjs` 加归档 `spawn` 入口;`scan.mjs` 把归档项标出来并与主列表分开 |
| 前端 `src/app/**` | 列表行更多菜单加「归档」;已归档分区或筛选开关 |
| 契约 `src/app/lib/api.ts` | **动**。产出项加「是否已归档」标记;新增归档接口 |
| CLI `bin/cli.mjs` | 不动 |
| `templates/` | **动**。新增归档脚本(真正写盘的是它)、`一次归档/README.md` 模板与二次归档提示词、以及二次归档技能 |

**依赖**:不引入新依赖。

### 需要人拍板:放宽只读红线

归档是**移动文件**(`rename`),看板自己绝对不能做 ——
`writeQuestion` 那条例外的第 ① 条明写「只允许改已存在的问题文件,**不新建、不删除、不改名**」,
归档正好撞在最硬的那个字上。

所以这是**第七条窄例外,且是「看板只 `spawn`,工作空间脚本写盘」的形状**
(与 `ingest.py`、`workspace-sync.mjs`、`web_ingest.py --inbox` 同构),
不是 `output-item-record` 那种服务端直写。约束照那几条的口径写,至少包括:

- 看板只 `spawn`,自己不写、不 `rename`、不 `unlink` 任何一个字节
- 必须用户在列表行明确点「归档」发起,没有后台自动跑、没有定时、没有按状态自动归档
- 必须环回(`allowMutations`)且非跨站(`rejectIfForeignOrigin`)
- 请求只带产出项的标识,**不接受任何路径**;脚本自己算落点
- 脚本只允许在 `output/<三个子目录>/一次归档/` 下写,`input/`、`project.yaml`、
  `visualization/` 仍然只读;**只移动与追加 README,不删除任何文件**

**二次归档的产出范围已拍板(2026-09-22)**:只产出分堆与短索引,
**不产出任何「始终无需再读」的清单**,也不往工作空间的 `AGENTS.md` 或技能里写跳过规则。
归档降低的是读取成本,不是可达性。
