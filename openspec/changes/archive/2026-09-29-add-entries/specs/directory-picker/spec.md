## ADDED Requirements

### Requirement: 路径输入框旁提供系统目录选择器

「新建」对话框的路径输入框后面 MUST 有一个文件夹图标按钮,「新建工作空间」与
「登记已有目录」两个 tab 都 MUST 有。
点击 MUST 在**服务所在的机器**上弹出系统原生的目录选择对话框;
用户选定后,绝对路径 MUST 回填进输入框,且 MUST 仍可继续手工编辑。
按钮 MUST NOT 替代手工输入 —— 输入框在任何情况下都保持可用。

路径 MUST 由服务端返回。看板 MUST NOT 用浏览器侧的目录选择手段
(`showDirectoryPicker()`、`<input webkitdirectory>` 一类)来实现这个按钮:
它们只给目录名或相对路径,**拿不到绝对路径**,而注册表与
`init_workspace.py` 要的正是那串绝对路径。

#### Scenario: 选一个目录
- **WHEN** 用户点文件夹按钮,在弹出的系统对话框里选中一个目录
- **THEN** 该目录的绝对路径出现在路径输入框里
- **AND** 用户可以在它后面接着敲一段新目录名再点「创建」

#### Scenario: 取消选择
- **WHEN** 用户打开了系统对话框但点了取消
- **THEN** 输入框内容保持不变,界面上不出现错误提示

#### Scenario: 等待期间
- **WHEN** 系统对话框已经打开、用户还没选完
- **THEN** 按钮显示为进行中,并提示「已打开系统选择框,请在桌面上完成选择」

### Requirement: 目录选择接口只返回一个路径,且只对本机开放

看板 MUST 提供 `POST /api/pick-directory`,响应形如
`{ picked: boolean, path?: string }`。
该接口 MUST 先过 `rejectIfRemoteWrite`(非环回监听时 403)与 `rejectIfForeignOrigin`,
判据与写接口同级 —— 它虽然不写任何文件,但会让服务所在的机器弹窗。
接口 MUST NOT 列目录、MUST NOT 返回目录内容、MUST NOT 接受任何客户端传来的起始路径以外的参数。
同一时刻 MUST 只允许一个选择框:已有一个在开时,新请求 MUST 返回 409 并说明原因。
选择框 MUST 有超时(不短于 60 秒、不长于 300 秒);超时 MUST 结束子进程并返回中文说明,
MUST NOT 让请求无限期挂着。
三个平台的命令 MUST 只写在 `src/server/platform.mjs` 一处。

#### Scenario: 非环回监听
- **WHEN** 服务以非环回地址启动,有人从别的机器 POST 这个接口
- **THEN** 返回 403 并说明只读分享模式下不能这么做
- **AND** 服务所在的机器上没有弹出任何窗口

#### Scenario: 已经开着一个
- **WHEN** 一个选择框已经打开,又来一次请求
- **THEN** 返回 409 说明已经有一个选择框开着,不弹第二个

#### Scenario: 开太久
- **WHEN** 用户打开选择框后一直没操作,超过超时时间
- **THEN** 子进程被结束,接口返回中文说明,界面回到可点状态

### Requirement: 起不来选择器时退回手工输入,不阻断

接口 MUST 在服务所在机器没有可用的目录选择命令时(没有桌面环境、
Linux 上 `zenity` 与 `kdialog` 都没装)返回明确的中文说明,
前端 MUST 把它显示出来并保持输入框可用。
旧服务进程没有这个接口时,前端 MUST NOT 显示这个按钮,新建/登记流程 MUST 与改动前一字不差。
本能力 MUST NOT 引入任何新的 npm 依赖,MUST NOT 把某个系统命令写成安装前提。

#### Scenario: 服务跑在没有桌面的机器上
- **WHEN** 用户在 ssh 会话里起了服务,然后点文件夹按钮
- **THEN** 提示这台机器上起不了目录选择框、请手工填绝对路径
- **AND** 手工填路径后创建 / 登记照常成功

#### Scenario: 旧服务进程 + 新前端
- **WHEN** 用户跑着改动前的常驻服务,浏览器加载了新前端
- **THEN** 路径框旁边不出现文件夹按钮,对话框其余部分与改动前一致
- **AND** 界面不报错、不白屏
