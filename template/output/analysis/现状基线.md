## 一句话现状

这是一份**厂商侧编写的方案建议书**，描述了一套面向新能源场站（光伏 + 风电）的数字孪生集成平台：
以三维建模还原物理电站，在场景里做运行监视、飞行巡视、告警着色、人员导航和视频联动。
当前处于**方案阶段**——而且比通常的方案阶段更靠前一步：
**文档开头明写「假定以下元信息」**，甲方、周期、覆盖范围、合同金额全是编制方为了写这份方案假定出来的。
最大的不确定性是：**这份文档描述了「系统长什么样」，但没有说明「它是为谁、在什么约束下、做到什么程度算做完」**。

## 业务目标与价值

- 解决的问题：电站管理层级多、信息分散，运营管理层与运维作业层缺少高效联动手段；
  标准化精益化运维难落地；场区大、隐患难及时发现；消缺过程不透明
  （来源：`新能源场站数字孪生集成平台方案建议书.md` 开篇第 1–2 段）
- 核心业务目标：把电站管理变成「大而易管、易管且安全、安全且全面领先」，
  让运营管理层与运维作业层通过三维场景高效联动（来源：同上）
- 具体能力目标：1:1 镜像还原物理电站；对电站/分区/子阵/设备四级精细化管理；
  在线动态巡视；应急处理沙盘推演；重大事件 3D 实景指挥调度（来源：同上 §1 电站三维建模设计）
- 三句口号式目标：「定向追踪虚实互通、智能感知云边共施、工单集成告警智能」（来源：开篇第 2 段）
- `[空白]` **成功标准没有量化**。资料里唯一的数字全是建模精度（2m / 3m / 1.5m / 1m / 10% / 20% / 5m），
  没有一条是「系统上线后达成什么业务结果」。人效提升、消缺时长下降、隐患发现率这类效益指标完全没有。
- `[推断]` 开篇提到的「沙盘推演」「3D 实景指挥调度」在正文中**没有任何对应设计**，
  更像是能力口号而非本期交付内容（→ Q17）

## 业务规则与约束

**已明确的规则**（来源：§1 三维实体模型、§2 数字孪生业务功能设计）：

- 模型分四类（建筑、发电设施、绿化、其他），各分 LOD1 / LOD2 / LOD3 三档
- 建筑模型精度：体块模型平面约 2m、高度约 3m（高层可放宽至 5m）；标准模型约 1.5m；精细模型约 1m
- 发电设施体模型：高度精度小于模型自身高度的 10%；其他类基础模型：小于 20%
- 绿化基础模型：树木高度与实际误差在 5m 以内
- 场景分层加载顺序：区域中心 → 电站 → 分区 → 子阵 → 设备
- 可视化与导航的最小粒度：**组串**（实时数据查看、告警着色、路径导航三处均写明到组串）
- 电力设施模型的对象清单：光伏板、集中式/组串式逆变器、电表、环境监测仪、交直流汇流箱、
  箱变、组件、支架、升压站、断路器、主变、中控室
- 编码体系：KKS，参考 GB/T 50549-2010 与 QSPI 9720-2016
- 视频联动规则：点击设备模型 → 摄像头转向该设备；运维人员到达作业范围 → 摄像头开启录像

**边界情况缺失**（这是本资料最系统性的短板）：

- `[空白]` **模型精度分类表与正文对不上**。表里建筑模型 LOD1/2/3 = 体块/基础/标准，
  正文却写体块/标准/精细；绿化表里是通用符号/基础/标准，正文写基础/标准/精细；
  「其他模型」正文只有两档。**四类模型没有一类能完整对齐**——
  各类模型到底交付到哪一档，无法确定（→ Q4）
- `[空白]` 「1:1 镜像还原」与「建筑体块模型平面精度约 2m」**是两个互斥的口径**。
  前者不可验收，后者可验收但远达不到「1:1」。验收时按哪个说了算，资料没写（→ Q4）
- `[空白]` 人员定位相关功能（位置同步、路径回放、到岗自动录像、人员属性弹窗展示姓名与联系方式）
  **完全没有提及知情同意、留存期限、查询权限**——这是敏感个人信息，属合规红线（→ Q5）
- `[空白]` 无人机航拍与遥感形成的 DEM / DOM 属测绘成果，**涉密审查与存储要求一字未提**（→ Q6）
- `[空白]` 电子围栏「实现进出报警」，但**报警发给谁、怎么处置、与既有周界安防如何共存**没写（→ Q14）
- `[空白]` 告警着色的**上游告警从哪来**没写。本平台不产生告警，只做渲染；

## 技术与集成现状

**技术选型与数据链路**（来源：§1.1 基础地理模型、§2.1 三维可视化、§2.2 运行可视化）：

```
遥感卫星 / 无人机航拍 ──→ DEM / DOM / 倾斜摄影 / 矢量数据 ──→ 空间数据引擎（关系数据库）
                                                                    ↓
生产运行智能管理系统 ──（统计/人员/设备/实时数据）──→ 数字孪生平台 ──→ WebGL 自有 3D 引擎（浏览器）
                                                          ↑↓
                                  视频安防系统 · 移动端 GPS · 工单系统（一键派单）
```

- 渲染：基于 WebGL 协议开发的**自有 3D 引擎**，在浏览器内展示 3D 场景与模型（来源：§2.1）
- 地理数据存储：统一使用基于关系数据库系统的空间数据引擎，不再单独建属性表与索引表（来源：§1.1）
- 设备编码：KKS（来源：§1.2 设备与模型关联设计）
- 定位：GPS 位置 + 坐标系转换 + 空间分析，在三维场景中同步人员位置（来源：§2.7）

**外部依赖清单**——共 6 项，每一项都是进度风险点：

| 依赖 | 交互内容 | 来源 |
| --- | --- | --- |
| 生产运行智能管理系统 | 统计数据、人员数据、设备数据、实时数据（运行可视化的唯一数据源） | §2.2 |
| 视频安防系统（摄像头） | 摄像头调控、预置点、定位巡视、越界录像、到岗录像 | §2.5、§2.8 |
| 移动端应用 | 人员 GPS 位置采集，承载站内导航 | §2.7 |
| 工单系统 | 「一键派单」的接收方（资料只提动作，未点名系统） | §2.7 |
| 遥感 / 无人机数据采集 | DEM、DOM、倾斜摄影模型的原始数据 | §1.1 |
| 智能终端（边缘计算设备） | 边缘计算与实时 AI 能力的载体 | 开篇第 2 段 |

- `[空白]` **6 项依赖，没有一项说明了接口是否已具备、由谁提供、当前可用状态**（→ Q9、Q10）
- `[空白]` 「生产运行智能管理系统」是运行可视化全部功能的**唯一**数据来源，
  而资料对它的描述只有名字（→ Q9）
