## Why

看板现在只能看:用户在预览里发现"这段太抽象""这个结论不对",只能自己切到终端、
重新描述一遍是哪篇文档的哪一段、再让 AI 改 —— **每一次反馈都要人肉复述一遍上下文**,
而看板明明已经知道这段话在哪个文件的第几个字节。不做这件事,看板就一直停在
"结果展示器",AI 协作的回路永远缺最后一环。

## What Changes

- **预览里可以选中并批注。** 在阅读器的 markdown 预览上划选任意内容,写下想法,
  攒成一批(像一次代码评审),而不是一条一发。
- **批注带着源码坐标。** 每条批注记的是「哪个文件的哪个字节区间 + 选中的原文」,
  不是"页面上某处"。
- **一键复制成完整提示词。** 把整批批注组装成可直接粘贴给本机 agent 的提示词:
  文件路径、每段选中的原文、源码区间、用户的意见、可改动范围。用户自己粘到
  已经开着的 agent 会话里,**看板不起任何子进程**。
- **产物回流不用新写代码。** agent 在工作空间里改完文件,现有的目录监听(SSE)
  会捕获到,预览自己刷新。
- **批注是一次性的评审批次。** 复制不自动清空;检测到这篇文档被改动过时,
  在批注面板上提示"可能已处理,是否清空",由用户点。不做跨版本重锚。

v0 明确不做:起 agent 子进程、原型页(iframe 里的任意 HTML)的批注、浏览器扩展、
ACP 协议层、批注共享与协同。

## Capabilities

### New Capabilities
- `preview-annotation`: 预览层的选中 → 锚点 → 批注批次 → 组装成提示词复制出去。
  包括锚点怎么算、批注存在哪、提示词里放什么、什么时候清空。

### Modified Capabilities
（无。`rich-doc-convert` 不受影响。）

## Impact

**这是一个纯前端改动。**

| 平面 | 影响 |
| --- | --- |
| 前端 `src/app/**` | 新增批注层与批注面板;阅读器的 markdown 分支要挂锚点数据 |
| 服务端 `src/server/**` | **不动** |
| 契约 `src/app/lib/api.ts` | **不动** |
| CLI `bin/cli.mjs` | 不动 |
| `templates/` | 不动 |

**依赖:** 不引入任何新依赖。锚点用现有 `react-markdown` 管线加一个仓内的 rehype 插件。

**存储:** 批注落浏览器本地存储,复用 `hooks/usePins.ts` 已有的
「模块级 store + `useSyncExternalStore` + localStorage,按工作空间分键」模式。

**只读红线:** 不需要任何调整。看板不起子进程、不写工作空间、连服务端注册表都不写 ——
唯一改动工作空间的仍然是用户自己在终端里跑的 agent,那本来就不归看板管。
`AGENTS.md` 第 1 节保持原样。

**兼容性:** 服务端不动,所以不存在新旧进程配合的问题,也不需要重启常驻服务。
