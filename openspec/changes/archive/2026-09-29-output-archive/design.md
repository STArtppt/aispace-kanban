## Context

`output/` 下的三个目录(`analysis/` `docs/` `decisions/`)只会单调变长。
`scan.mjs` 的 `scanOutput` 递归收齐三个组名下的所有文件,按 `mtime` 排好给前端,
陈旧的分析、被取代的文档、已推翻的决策和当下在用的东西平铺在同一个时间序里。

人还能靠搜索凑合,**AI 是全量读**。这正是 `output/questions/` 那张表当年被放弃的机制:
两百多条、一半标「高」,最后整份没人看。产出物走到同一个量级只是时间问题。

`output-item-record` 刚落地,给了「哪些已经不作数了」一个可判断的依据:
每份产出物有一份 `output/records/I<编号>.md`,带 `kind` 分化的三套状态机。
但状态只是标记 —— 文件还在原地,列表还是那么长。**缺的是把它们移走的动作。**

移动文件是 `rename`。看板自己绝对不能做:第六条窄例外的第①款写死「只改已存在的记录文件,
**不新建、不删除、不改名**」,归档正好撞在最硬的那个字上。
所以本 change 的形状是**看板只 `spawn`,工作空间脚本写盘** ——
与 `ingest.py`(`startIngest`)、`workspace-sync.mjs`(`startProtoSync`)、
`web_ingest.py --inbox`(`startWebIngest`)同构,不是 `records.mjs` 那种服务端直写。

## Goals / Non-Goals

**Goals:**

- 列表长度可控:不作数的产出物从主列表分出去,不再占位置。
- 分出去之后**可达性一点不降**:照样能搜、能预览、能被 AI 按需读取。
- 归档只移动,不删除 —— 别处的会议纪要、决策记录可能正写着「见某某文档」。
- 二次归档的交接靠一份文件,冷启动的 agent 独立读得懂。
- 看板一个字节都不写工作空间,第七条窄例外的边界写死在 spec 与 AGENTS.md 里。

**Non-Goals:**

- **不做任何形式的「始终无需再读」清单**(2026-09-22 已拍板)。
  一份自动生成的不读清单会影响此后所有 AI 会话的行为面,而它是 AI 的单向判断、会判错,
  错一条的代价是某份资料从此没人再看。归档降低的是**读取频率与成本**,不是**可达性**。
- **不按状态自动归档**。`superseded` 不等于该移走 —— 那是人的判断。
- **不做取消归档 / 移回来**。移回去同样是 `rename`,本轮不开这个口子;
  用户在文件系统里自己移,看板下一次扫描就跟上。
- **不动 `output-item-record` 的三套状态机**。归档是位置不是状态(那三套 spec 里已经写死
  「MUST NOT 包含已归档」),混进去会让状态机和目录布局两边都失真。
- **不做批量归档**。一次一份,从列表行的「更多」里发起。

## Decisions

### 1. 归档目录在各子目录**内部**:`output/<组>/一次归档/`

放在组内,`scan.mjs` 的 `listFiles` 本来就是递归的 —— 归档项照样扫得到、读得到、搜得到,
不用给可达性做任何额外的事。这就是「分出去但不藏起来」的实现方式。

备选 A:`output/archive/` 统一一个归档目录。不选 —— 归档项会丢掉它原本属于哪一组的信息,
而「这是被取代的交付文档」和「这是过时的中间产物」在二次归档时是完全不同的两堆。
而且那样需要在 `scanOutput` 里额外加一次遍历,归档项的组别还要另存一份,凭空多一处要对齐的口径。

备选 B:移出 `output/` 之外(比如 `.archive/`)。不选 —— 那是「降低可达性」,
`listFiles` 跳过点开头的目录,归档之后看板与 AI 都读不到了,直接违反 Goals 第二条。

目录名用中文「一次归档」:这个目录是给人和工作空间 agent 看的,
与 `output/` 下其它中文语境一致。

### 2. 请求只带「组名 + 文件名」,本轮只支持组根目录下的文件

请求带 `group`(`analysis` / `docs` / `decisions` 三选一,枚举校验)与 `name`(文件基名)。
`name` 里出现路径分隔符、`..`、或任何目录成分一律 400。脚本自己算落点。

代价是明确的:**组内子目录里的文件本轮不支持归档**,菜单项置灰并说清理由。
`templates/pm-aispace` 的产出物本来就平铺在组根,这个限制现在不咬人。

备选:带「组内相对路径」+ `resolveInside()` 校验。不选 —— 「请求不接受任何路径」是第三、
五、六条例外反复守住的同一句话。一旦开成「带路径但我们会校验」,下一个功能就会照着
「反正已经校验过了」推广,而那几条例外里最贵的资产就是这句话本身没有例外。

### 3. 真正写盘的是工作空间的 `scripts/archive_output.py`

看板只 `spawn`,与 `startIngest` 同构:脚本不存在时返回 400 并说清
「用模板新建的工作空间自带归档脚本;自己 mkdir 的目录需要自己装脚本,或在终端里自己移」。
老工作空间因此**不会**半可用 —— 要么脚本在、功能全,要么脚本不在、菜单项置灰说明原因。

脚本负责:建 `一次归档/`(不存在时)、`rename` 那一份、维护 README 交接单。
它 MUST NOT 删除任何文件;落点已有同名文件时加日期后缀,不覆盖。

备选:用 Node 写成 `scripts/archive_output.mjs`。不选 —— `pm-aispace` 的脚本清一色 Python
(`ingest.py` / `web_ingest.py` / `check_markdown.py`…),多引一门语言的运行时要求只为了一个
`os.rename`,不划算。`workspace-sync.mjs` 是 Node 那是因为它属于**原型工作区**,不是这套模板。

### 4. 归档是同步的一次调用,不做任务态

`startIngest` 那套 `running/done/error` 轮询是给「大 PDF 要跑几分钟」准备的。
移一个文件是毫秒级,给它配一套任务态和一个轮询接口只是复制代码。

决定:接口同步等脚本退出(带超时),返回结果;写盘会被 `watchWorkspace` 的 SSE 捕获,
列表自己刷新。超时按错误处理,并说明文件可能已经移走了、刷新看一眼。

### 5. `一次归档/README.md` 是异步交接单,只由脚本追加

看板不能调 AI(`preview-annotation` 已经定过调子:用户自己粘到开着的会话里,
看板不起任何子进程),所以交接靠一份冷启动的 agent 也能独立读懂的文件。

README 分两块:

- **已归档清单**:用一对标记注释包住,脚本**只在块内追加行**(日期、原名、一句话来由)。
  包起来是为了让脚本有一个确定的插入点,而不必重写整份文件 —— 这份文件人和 agent 也会改。
- **二次归档提示词**:只在文件不存在时写一次,之后脚本不再碰它。
  用户按自己的语境改过的提示词,不该被下一次归档覆盖回去。

### 6. 二次归档的产出是「分堆 + 每堆一份短索引」

工作空间 AI 读 README 里的提示词,把一次归档的内容按主题或阶段分堆:
`output/<组>/一次归档/<主题短名>/`,每堆一份 `INDEX.md`,内容是**这堆是什么、
当初为什么产生、什么情况下需要回来翻**,几百字。

目的是让人和 AI 用一份短索引代替翻几十份文档 —— 降低读取成本,不是禁止读。
提示词 MUST 显式写明:**不得产出任何「始终无需再读」的清单**,
也不得往工作空间的 `AGENTS.md` 或技能里写跳过规则。

分堆是 `rename`,由同一个脚本(或 agent 自己在终端里)做,看板一如既往不参与。

### 7. 「是否已归档」由服务端判定并下发,前端不自己解析路径

`scan.mjs` 给每个产出项加 `archived?: boolean`(路径里含 `<组>/一次归档/` 段),
前端按这个字段把它们分出去。

备选:前端自己从 `item.path` 里找「一次归档」。不选 —— 同一个判据实现两遍,
将来目录名一改就是两处要同步,而本仓一贯是「口径只写一处」。
代价是**旧服务进程 + 新前端**时没有这个字段,归档项会照旧留在主列表里 ——
那正好等于「功能没启用,行为与改动前一致」,是可接受的降级,写成场景验。

计数口径:`stats` 里的三组数字**只数主列表**(不含归档),另加 `archived` 计数。
「产出总数」突然变小会让人以为文件没了,所以界面上归档计数要与主列表计数一起出现。

### 8. 归档项仍然计入溯源反链

`attachReferences` 照常收归档项的正文。归档不降低可达性,反链是**事实陈述**:
一份资料确实被那篇文档引用过,把它移进 `一次归档/` 不会让这件事变成没发生。

代价是归档前后「被 N 篇产出引用」这个数字不变,看不出归档发生过 —— 那是对的,
那个数字回答的是「这份资料有没有人用」,不是「有没有人正在用」。

### 9. 短索引在界面上就是归档区顶部的一行

已归档分区里,某个堆目录下有 `INDEX.md` 时,它排在那一堆的最前面并标成「堆索引」。
不为它做专门的渲染组件 —— 它就是一份 Markdown,点开走现成的预览。

### 10. 记录索引里派生一个「目标已归档」标记,不进状态机、不写盘

`output-item-record` 的索引项加一个派生字段(由 `target` 路径里有没有 `一次归档/` 算出来),
让 ⌘K 工作台的产出物页也能一眼看出这份已经移走了。

它**不是状态**:不写进 front-matter、不进三套状态机、不因此改任何记录文件。
`target` 在归档后会指向旧路径,由 agent 跟进(`target` 是 AI 写区),
跟进之前记录会显示「指向丢失」—— 这是**正确**的提示,不是 bug:
文件确实不在那里了,该有人去改。归档脚本 MUST 在 README 的清单行里写上原路径,
让 agent 有据可查。

## Risks / Trade-offs

**[归档之后记录的 `target` 悬空]** → 记录会显示「指向丢失」直到 agent 跟进。
缓解:归档脚本在 README 清单里记原路径与新路径;`pm-output-record` 技能里加一句
「归档后跟进 `target`」。承认剩余风险:agent 不跟进的话,工作台里那条会一直标着丢失 ——
但那是**准确**的显示,不会误导。

**[「一次归档」是中文目录名]** → 跨平台文件名编码、以及用户在 Windows 上的表现要验。
缓解:验收闸里单独点名验一次;`resolveInside()` 与 `listFiles` 对中文路径已经在跑
(`input/raw/` 下本来就全是中文文件名)。

**[归档项仍然被 AI 全量读,等于白归档]** → 归档本身不阻止读取(这是设计)。
真正降低成本的是二次归档的短索引,而那一步依赖用户去粘提示词。
承认这是个**半自动**的闭环:看板只能把交接单放好,不能替人执行。

**[脚本不在的老工作空间]** → 菜单项置灰 + 一句说明,不做半可用状态。

**[同名文件冲突]** → 落点已有同名文件时加日期后缀,MUST NOT 覆盖。
两份同名产出物归档后在目录里能分清。

**[归档被误用成删除]** → 文案上一律写「归档」不写「移除」,并在确认提示里写明
「文件不会被删除,仍然可以搜到和预览」。

## Migration Plan

1. 模板侧先上:`archive_output.py` + `一次归档/README.md` 模板 + 二次归档技能。
   老工作空间不受影响(没有脚本 = 功能不可用,菜单项置灰)。
2. 服务端上 `archived` 标记与 `spawn` 入口,**重启进程**。
3. 前端上归档入口与已归档分区。
4. 回退:停用前端入口即可。已经移走的文件留在 `一次归档/` 下照常可读 ——
   归档只移动不删除,没有不可逆的一步。

## Open Questions

- 二次归档的分堆动作由谁执行:脚本(用户在终端里跑一条命令)还是 agent 自己 `rename`?
  写 tasks 时定。倾向脚本 —— agent 直接移文件没有任何约束兜着。
- 二次归档的短索引要不要也建一份产出物记录(`output/records/`)?
  倾向不建 —— 它是归档产物的目录,不是产出物本身,建记录会让记录目录跟着归档量一起涨。
