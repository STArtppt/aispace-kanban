# questions/ —— 未决问题，一问一文件

这个目录取代了旧的 `output/questions/_原表快照.md` 单表格。
**本文件是问题文件的唯一字段契约**，技能、迁移脚本、校验脚本、看板都以它为准。

## 为什么不再用一张表

旧结构只有入口没有出口：模板里 9 个技能往表格里追加，没有任何技能负责取出。
两个月就会长成「两百多条、一半标『高』、平均 200 字挤在一个表格单元格里」的样子，
最后被整份放弃 —— 而它恰恰是接手阶段最有价值的产物之一。

三处结构上的改动，各针对一个症状：

| 症状 | 改法 |
| --- | --- |
| 单条在长胖（溯源锚点挂在分节上，条目只能把上下文抄进自己的单元格自救） | 一问一文件，`source` / `context` 挂在**条目**上 |
| 「高/中/低」是自我评估，必然通胀到一半标「高」 | 取消优先级，排序轴换成 `blocks`（这条阻塞哪个在途交付物） |
| 只有「被回答」一种出口，AI 延伸出的「要不要考虑 X」只能一直躺着 | 四个标准答案（`human_answer`），一次点击就能消解一条 |

## 文件布局

```
output/questions/
├── README.md        ← 本文件
├── Q0001.md
├── Q0002.md
└── …
```

- 文件名 `Q<四位编号>.md`，编号在一个工作空间内**唯一且只增不减**。
- 关闭的问题**保留文件**，不删除、不复用编号 —— 编号是外部引用的锚点
  （会议纪要、决策记录、别的分析文档都会写「见 Q0134」）。
- 新增时取当前最大编号加一。
- **目录为空不等于从 `Q0001` 开始。** 整批问题随阶段结束归档（删文件）之后目录就是空的，
  这时候从头编号会让此前所有外部引用指向一条内容无关的新问题 —— 那比悬空引用危险得多，
  因为它看起来完全正常。**编号只增不复用**，空目录先查历史用过的最大编号：

  ```bash
  git log --all --name-only --pretty=format: -- 'output/questions' 'output/analysis/questions' | grep -o 'Q[0-9]\{4\}' | sort -u | tail -1
  ```

  查不到（真的是新工作空间）才从 `Q0001` 开始。
- **分叉编号**：末尾允许一个小写字母（`Q0016b`），**只有迁移脚本会用** ——
  旧表格里存在 `16b` 这种「从第 16 条分叉出来的」编号，重新编号会让别处写着「见 Q16b」的
  引用全部指错。新问题一律用纯数字编号，不要自己造分叉。

## front-matter 字段

front-matter **必须是扁平的**：只用 `key: value` 与 `key:` + `  - item` 两种形态，
**不用嵌套对象**。这不只是为了迁就解析器 —— 扁平限制强制 `title` 是一句话、
`blocks` 是一个交付物名，**条目长度由结构管住，不靠自觉**。长文一律进正文。

```markdown
---
id: Q0134
title: 洪水预报数据何时能从水调系统接入？接口形式是什么？
status: open
blocks: SC-01交底包
asked_of: 甲方水调 / 信息化
source: output/analysis/2026-07-31-SC-01测点与指标梳理.md
context: 梳理原型第 9 列洪水预报字段时发现三条预警规则都依赖它
created: 2026-07-31
updated: 2026-09-20
human_answer:
human_note:
due:
evidence:
ai_conclusion:
ai_source:
flows_to:
---

## 为什么需要

原型的洪水预报列、洪峰影响预估、WR-03 / WR-04 两条预警规则全部依赖它。
需求文档 §9.3 标为「待接入」，没有接入时间就无法排交底包的日程。

## 结论

（由 agent 填。一句话摘要写进 front-matter 的 `ai_conclusion`，展开写在这里。）

## 人工反馈

（人在看板上保存标准答案时追加。）

## 轮次记录

（对结论不满意重开一轮时，上一轮的结论与反馈搬到这里，**不覆盖**。）
```

### 必填

这五个键**必须存在**，缺一个校验脚本就报错。

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `id` | 问题编号 | 必须与文件名一致（`Q0134.md` → `Q0134`） |
| `title` | **一句话**问题 | 清单只显示它；超过 60 字校验脚本会警告 —— 那说明该拆条或该把上下文挪进正文 |
| `status` | 状态 | 见下面的状态机，五个值之一 |
| `blocks` | 这条阻塞哪个**在途交付物** | 键必须在；**值可以空**（= 待归类，迁移出来的都是这样）；不阻塞任何在途交付物写 `backlog` |
| `asked_of` | 该问谁 | 自由文本；对内决策写「我方」 |
| `source` | 触发这条问题的**文档路径** | 工作空间内相对路径。溯源锚点挂在条目上，不挂在分节上 |

### 可选

| 字段 | 含义 |
| --- | --- |
| `context` | 触发时在做什么，一句话。和 `source` 一起回答「这条问题当初是怎么冒出来的」 |
| `created` / `updated` | `YYYY-MM-DD` |

### 人写区 —— 看板可写，agent 约定上不写

| 字段 | 取值 |
| --- | --- |
| `status` | 见状态机 |
| `human_answer` | `verify` / `decide` / `drop` / `ask` 四个标准答案之一，见下节 |
| `human_note` | 人的补充说明，**一两句**。要写长文说明这条该拆 |
| `due` | 最迟答复日期 `YYYY-MM-DD`。`human_answer: ask` 时**必填** |

### AI 写区 —— agent 写，**看板一律不写**

| 字段 | 取值 |
| --- | --- |
| `evidence` | 凭据，四值之一，见下节。**这是唯一的凭据字段，没有 `ai_evidence`** |
| `ai_conclusion` | 结论**一句话摘要**；展开写进正文「## 结论」 |
| `ai_source` | 结论的依据出处（路径，可以是列表） |
| `flows_to` | 这条结论该回流到哪份正文的哪一节，如 `output/analysis/现状基线.md#技术与集成现状`；可以是列表 |

**为什么要分区**：并发不是意外而是常态 —— 流程本身就是「人在看板上点保存 → 立刻复制 prompt
→ agent 开始改同一条」，两者会在几秒内动同一个文件。
分区让它们**物理上落在不同字段**，不需要锁，比检测冲突再让用户处理更简单也更可靠。
看板服务端会硬拒绝载荷里带 AI 写区字段的请求。

## 状态机

| `status` | 含义 | 可流转到 |
| --- | --- | --- |
| `open` | 未处理 | `pending_ai`、`answered`、`dropped` |
| `pending_ai` | 人已反馈，AI 还没更新 | `answered`、`dropped`、`open`（再问一轮） |
| `answered` | 已消解，有结论 | `open`（对结论不满意，重开） |
| `dropped` | 本期不做 / 不相关 | `open` |
| `conflict` | 正文与状态不一致（迁移时识别出的存量脏数据），**待人裁定** | `open`、`answered`、`dropped` |

`pending_ai` 是整个闭环的枢纽 —— 它标记「prompt 已经可以发出去 / 发了还没回来」。
它必须是一个能筛出来的独立状态，不能只体现为一个计数。

重开一轮时**不覆盖**上一轮：把上一轮的 `ai_conclusion` / 人工反馈搬进正文的「## 轮次记录」，
再把 `status` 置回 `open`。

## 四个标准答案（`human_answer`）

它们不是平级的终点，走向四条不同的路：

| 值 | 界面文案 | 它其实是 | 后续 |
| --- | --- | --- | --- |
| `verify` | 资料里应该有，待查证 | 派给 AI | → `pending_ai`，复制查证 prompt 交给 agent |
| `decide` | 我方自行决定 | 要产出决策 | → `pending_ai`，agent 生成 `output/decisions/` 草稿 |
| `drop` | 本期不做 / 不相关 | 真终态 | → `dropped`，**不出现「复制 prompt」** |
| `ask` | 确需对方答复 | 派给人（对外） | → 进会议清单，**必须填 `due`** |

`ask` 不填 `due` 就没有任何机制逼它到期 —— 存量那批积压问题就是这么来的。
其余三个不要求 `due`。

## 凭据（`evidence`）：推断不能关闭问题

| 值 | 含义 | 能关闭问题吗 |
| --- | --- | --- |
| `客户确认` | 对方书面或会上明确答复 | 能 |
| `资料实证` | 资料里查得到，`ai_source` 指得出来 | 能 |
| `我方决策` | 我方拍板，有决策记录 | 能 |
| `我方推断` | 查不到依据，只能推 | **不能** |

**`evidence: 我方推断` 的问题不允许置为 `answered`**，只能停在 `open` 并作为待验证假设。
看板给它一个显眼的橙色角标。

这条约束是正面针对「AI 把未知伪装成确定事实」的。把推断和实证放在同一栏里、长得一模一样，
正是存量数据里出现状态冲突的原因。查不到就写 `我方推断`，**不要编**。

`status: answered` 而 `evidence` 为空，同样是非法组合 —— 凭什么关的必须写出来。

## 正文四节

正文是自由 markdown，但这四个二级标题是约定俗成的位置，看板与技能都按它找内容：

| 小节 | 谁写 | 写什么 |
| --- | --- | --- |
| `## 为什么需要` | 提出这条问题的技能 | 不回答会卡住什么。这是判断轻重的依据，不是背景铺陈 |
| `## 结论` | agent | 展开的结论与推导；一句话摘要同步进 `ai_conclusion` |
| `## 人工反馈` | 看板（人点保存时追加） | 人的判断与补充 |
| `## 轮次记录` | agent | 被重开的上一轮内容，按时间倒序追加 |

## 校验

```bash
python3 scripts/check_questions.py            # 默认查 output/questions/
python3 scripts/check_questions.py --json     # 给程序用
```

查这些：缺必填键、`status` / `evidence` / `human_answer` 取值不在枚举、
`我方推断` + `answered`、`answered` 而 `evidence` 空、`ask` 而 `due` 空、
`due` 不是 `YYYY-MM-DD`、`id` 与文件名不符。有错误时退出码非零并逐条打印原因。

## 从旧表格迁移

```bash
python3 scripts/migrate_questions.py --dry-run   # 先看会生成什么，不落盘
python3 scripts/migrate_questions.py --write     # 确认后再落盘
```

迁移**只搬运与标记，不推断**：`blocks` 与 `evidence` 一律留空交人工过一遍 ——
自动填出来的凭据本身就是虚假确定性，而这个字段存在的全部意义就是防止它。

脚本会额外输出一份 `MIGRATION-REVIEW.md` 待人工裁定清单：
正文写着「已解决 / 不再阻塞 / 已定案」但编号没划掉的条目（置 `conflict`）、
疑似根本不是问题的条目、以及分叉编号（`16b`）这类需要人看一眼的条目。

原 `open-questions.md` **正文不删**：整份搬进本目录改名 `_原表快照.md`，
开头加一句指向新结构的说明 —— 留着回滚。

**为什么快照要跟进本目录，而不是留在 `analysis/` 或者删掉。** 它不是可丢的残渣：
41 条问题的 `source` 直接指向它（那些问题的出处**就是**原表，没有更深的来源），
231 条正文里都有一句「来自原表第 N 行」。删掉等于一次弄断 272 处引用，
正好踩中「溯源是硬要求」。留在 `analysis/` 又会一直占着分析产物清单的位置 ——
搬进来两头都解决：引用照样点得到，列表里看不见它。

迁完 `blocks` 与 `evidence` 还是空的（迁移不推断），用工作表批量补：

```bash
python3 scripts/triage_questions.py --plan          # 出 TRIAGE.md，按分节填 blocks、按条填 evidence
python3 scripts/triage_questions.py --apply --write # 落盘
```

`blocks` 按分节整片填（几十个决定，不是几百个），手头没在做的写 `backlog`；
`evidence` 只有已关闭的那些缺，表里会把当初的闭包原句引出来供判断。
`MIGRATION-REVIEW.md` 与 `TRIAGE.md` 都是过程件，裁定完可以删；
`_原表快照.md` 不一样，**它是被引用的溯源终点，不要删**。

本目录里这四份过程件都不是问题：文件名不匹配 `Q<四位编号>.md` 的一律不进弹窗，
`check_questions.py` 与看板 `questions.mjs` 共用同一份跳过名单，改一处要同步另一处。
