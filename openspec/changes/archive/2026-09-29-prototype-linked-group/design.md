## Context

原型工作区的同步脚本往工作空间写的布局见 proposal。实测一份已登记原型的 dry-run 输出：
1 个离线包 zip、1 份 `meta.json`、13 份拷贝的 md（主规格 1 + 页面级规格 9 + 文档（docs/）2 + 标注 JSON 1）、
2 份生成的 md（`标注汇总.md`、`SYNC.md`）。同一工作空间里还有一份此前用「贴 URL 导入」手工建的
url 卡片，链接和同步写的 `meta.json` 只差一个 `#page=…` hash。

现状下看板会给这份原型出 3 张卡片，资料 md 没有入口。

`SYNC.md` 是给人读的 Markdown 表格，行标签固定（`源仓库提交`、`本地最近改动`、`同步时间`、
`离线 HTML 包`、`在线链接`），值是 ISO 时间或一行说明。
`meta.json` 由同一脚本写，字段：`kind` `title` `target` `publishedAt` `publishTarget` `source` `syncedAt`。

## Goals / Non-Goals

**Goals：** 一份原型在界面上只出现一次；资料可点开阅读；需要人处理的两种状态（在线版落后、离线包没更新）一眼可见；新旧进程任意组合都不白屏。

**Non-Goals：** 在看板里触发同步 / 发布；渲染 JSON 原件；把同步契约写进工作空间模板。

## Decisions

### 1. 用 `SYNC.md` 作为「已接入」的判据

- **选**：镜像目录里有 `SYNC.md` 就认作已接入。脚本自己也用它判断「这个目录是不是我建的」（没有 `SYNC.md` 却有同名子目录时拒绝写入），两边判据同源。
- **备选 A**：看 `meta.json` 的 `source === 'axhub-make-sync'`。不选：没发布过的原型脚本不写 `meta.json`，这种原型会被漏认。
- **备选 B**：约定一个新的机读文件（如 `sync.json`）。不选：要改原型工作区的脚本，跨仓协调成本高；而且 `SYNC.md` 已经够用，解析失败只是少标状态，不影响聚合。以后真需要机读字段再加，看板优先读它、读不到退回 `SYNC.md`。

### 2. 离线包按 `<目录名>-html.zip` 精确匹配

- **选**：只认 `<slug>-html.zip`。这是 Axhub 导出的默认文件名，也是脚本写死的名字。
- **备选**：按 zip 里 `index.html` 的 `<title>` 与镜像目录标题模糊匹配。不选：标题会撞、会改，猜错了会把别的包并进来，比多一张卡更糟。

### 3. 「在线版落后」只在两个时间都解析出来时才标

- **选**：`SYNC.md` 的「本地最近改动」晚于 `meta.json.publishedAt` 才标 `onlineStale: true`。任一侧缺失或不是合法时间就不下发这个字段。
- **备选**：在 `SYNC.md` 里找「在线版落后」字样。不选：那是给人读的文案，改个措辞就失效，且无法算出落后多少天。

### 4. 被并入的条目照旧下发，只加 `groupedInto`

- **选**：zip 和重复 url 卡片仍在 `items` 里，带 `groupedInto: <镜像目录 slug>`；新前端过滤掉，旧前端视而不见。
- **备选**：服务端直接从 `items` 删掉。不选：新服务配旧前端时，离线包卡片会凭空消失，而旧前端没有展示聚合行的能力 —— 违反「退回改动前的行为」。

### 5. 重复判定用规范化后的链接全等

- **选**：只比 `origin + pathname`（丢掉 hash 与查询串），与脚本提示「重复卡片」用的 `normalizeUrl` 逐字同口径 —— 口径不同就会出现脚本说重复、看板却没合并。末尾 `/` 不做归一，原因同上。只并**不带** `SYNC.md` 的 url 目录；两份都带 `SYNC.md` 的各自成组。
- **备选**：只比 host + path 前缀。不选：同一域名下多份原型会被误并。

### 6. 资料只列 `.md`，打开走现有 `/file` 与阅读器

- **选**：服务端给每份 md 下发工作空间相对路径 + 分组 + 显示名；前端拼成 `FileItem` 调现有的 `onOpen`。`/file` 已经过 `resolveInside`，不新增接口。
- **备选**：新开 `/proto-doc` 接口。不选：多一个要过穿越检查的入口，没有收益。
- **显示名**：`spec/spec.md` → 「主规格」；`spec/pages/<页面>/…` → 页面目录名（同一页面目录下有多份时再带文件名）；其余取文件名去扩展名。只做字符串处理，不读 md 正文取标题（一次扫描多读十几个文件没必要）。

### 7. 界面：已接入原型用「行」，其余保留卡片网格

- **选**：已接入原型信息多（两个入口、三格状态、四组资料），一行占满宽度；未接入的照旧 3 列卡片。两段各有小标题和计数。
- **备选**：扩展 `ShowcaseCard`，把资料塞进卡片展开区。不选：卡片宽度只有 1/3，资料路径放不下，展开会把网格撑乱。
- **配色**：只有「在线版落后」「离线包没更新」「存在重复卡片需要人处理」三处用 `--destructive`，其余黑白灰。

## Risks / Trade-offs

- **`SYNC.md` 文案变更** → 行标签改名后状态格退化为「—」，聚合与资料照常。缓解：解析集中在一个函数，注释写明对应的脚本版本。
- **资料很多的原型（上百份页面规格）** → 列表过长。缓解：v0 每组默认展示前 12 条 + 「展开全部」；扫描只 `readdir` + `stat`，不读正文。
- **每次 scan 多读 N 份 `SYNC.md` / `meta.json`** → 都是 KB 级小文件，和现有 `readMeta` 同量级，可接受。
