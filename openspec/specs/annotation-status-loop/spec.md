# annotation-status-loop

## Purpose

约定批注落进工作空间之后的那条闭环:一份产出物一个批注文件
(`output/records/notes/I<编号>.md`,编号与它的产出物记录一致),多轮评审追加进同一份;
每条批注带自己的状态,由工作空间的 agent 逐条回写 `- 状态：` 与 `- 回执：` 两行;
看板只在新一批落盘时追加,追加之后这一条一个字都不再改。
看板配置目录 `note-history/` 从主落点降级成两个角色:产出物没有记录时的退路、
存量批注的只读回退源。本能力由 `annotation-workspace-loop` 与 `docx-front-matter-and-deai` 变更落地,
是 `preview-annotation` 里「复制提示词」动作的下游。
交付稿(`output/delivery/`)上的批注按镜像路径挂到原稿那份记录,批次写明对象;回执可以带规则沉淀标记。

## Requirements

### Requirement: 批注落在工作空间,挂在产出物记录上

一份产出物的批注 MUST 落在 `output/records/notes/I<编号>.md`,编号与它的产出物记录
(`output/records/I<编号>.md`)一致。一份产出物一个批注文件,多轮评审追加进同一份,
MUST NOT 按批次拆成多个文件。

批注文件 MUST NOT 出现在产出视图的三组列表里,也 MUST NOT 出现在产出物记录索引里 ——
`notes/` 是目录,记录扫描只收 `output/records/` 根上的文件,结构上就不会收到它。

#### Scenario: 第一次给一份文档写批注

- **WHEN** 用户在 `output/docs/某份文档.md` 的预览里写了批注并复制提示词,该文档的记录是 `I0007`
- **THEN** 工作空间里出现 `output/records/notes/I0007.md`,里面是这一批批注
- **AND** `output/docs/某份文档.md` 与 `output/records/I0007.md` 一个字节都没有变化

#### Scenario: 同一份文档的第二轮评审

- **WHEN** 同一份文档上又写了一批批注并复制提示词
- **THEN** 新的一批追加在 `output/records/notes/I0007.md` 末尾,已有条目一个字都没改
- **AND** 没有产生第二个批注文件

#### Scenario: 批注文件不挤占任何列表

- **WHEN** `output/records/notes/` 下有大量批注文件,用户打开产出视图与 ⌘K 工作台
- **THEN** 产出视图三组列表与计数、工作台的产出物清单,与没有这个目录时完全一致

### Requirement: 每条批注有自己的状态,由 agent 回写

每条批注 MUST 带一个状态,取值 MUST 是下列四者之一:

| 状态 | 含义 | 回执要求 |
| --- | --- | --- |
| `pending` | 待处理 | 落盘时的初始值,回执为空 |
| `adopted` | 已采纳,正文照这条改了 | 写改了什么 |
| `rejected` | 未采纳 | MUST 写原因 —— 没有原因的拒绝等于没有回答 |
| `unclear` | 看不懂 / 需要人确认 | 写卡在哪 |

状态 MUST 由 agent 明确回写,系统 MUST NOT 从「文档被改动过」推断任何一条的状态 ——
改了六条和改了十条在文件系统上长得一模一样,推断出来的那四条是假的。

看板写入时状态 MUST 一律是 `pending`,看板 MUST NOT 写入其它三个值:
回写是 agent 在用户终端里做的事,不经过看板。

#### Scenario: agent 处理完一批

- **WHEN** agent 按提示词改完正文,回到批注文件逐条回写
- **THEN** 采纳的那几条状态是 `adopted`、回执写明改了什么;没采纳的是 `rejected` 并带原因
- **AND** 没被处理的那几条仍然是 `pending`

#### Scenario: 文档变了但没人回写

- **WHEN** 文档在磁盘上被改动,而批注文件里的状态一条都没变
- **THEN** 这些批注 MUST 仍然是 `pending`,MUST NOT 被自动置成 `adopted` 或任何别的值

#### Scenario: 拒绝但不给原因

- **WHEN** 某条批注被回写成 `rejected` 而回执为空
- **THEN** 校验 MUST 报告这一条

### Requirement: 批注文件的格式与两边的写区

批注文件 MUST 是 Markdown,一批一个 `##` 小节(带日期与批次序号),
一条批注一个 `###` 子节。子节 MUST 包含:批注编号与结构类型(标题行)、
`- 状态：`、`- 回执：`、`- 源码区间：`、选中原文的引用块、以及用户写的意见。

写区 MUST 按**行**物理隔开,这本身就是并发方案,不引入锁:

| 区 | 内容 | 谁写 |
| --- | --- | --- |
| 看板写区 | 整条批注的**追加**(一次写完) | 看板,追加之后这一条一个字都不再改 |
| agent 写区 | 每条的 `- 状态：` 与 `- 回执：` 两行 | 工作空间的 agent |

看板 MUST NOT 改写任何已存在的条目,MUST NOT 删除条目,MUST NOT 改写 `- 状态：` 与
`- 回执：` 两行以外的任何已有内容。

#### Scenario: 人与 agent 同时动同一份批注文件

- **WHEN** 用户在看板上复制新一批批注(触发追加),同时 agent 在回写上一批的状态
- **THEN** 两边写的是不相交的行,不需要加锁,最后两边的改动都在

#### Scenario: 看板试图改已有条目

- **WHEN** 写入请求要求修改一条已经落盘的批注的意见或原文
- **THEN** 接口 MUST 返回 400,MUST NOT 落盘任何改动(已发出去的批注就是已发出去了)

### Requirement: 批注编号在一份产出物内唯一且只增不复用

落盘的每条批注 MUST 有一个 `N<四位编号>`,在该产出物的批注文件内唯一、只增不复用。
页面标记点上的序号(当前这一批的 `1..n`)与它是**两套编号**,MUST NOT 互相覆盖:
页面序号回答「这一批里的第几条」,`N` 编号回答「这份文档上的哪一条」。

回写 MUST 按 `N` 编号定位。批注文件里 MUST NOT 出现页面序号作为唯一标识 ——
第二批的「批注 1」与第一批的「批注 1」会撞名,agent 改错行时没有任何东西拦得住。

#### Scenario: 第二批的编号接着第一批往下走

- **WHEN** 第一批落了 `N0001`–`N0003`,第二批有两条
- **THEN** 第二批是 `N0004`、`N0005`,页面上它们仍然显示为「批注 1」「批注 2」

#### Scenario: 删掉一条之后再写

- **WHEN** 用户手工从批注文件里删掉了 `N0002`,之后又写了一条新批注
- **THEN** 新的一条取当前最大编号加一,MUST NOT 复用 `N0002`

### Requirement: 落盘的时机是用户点「复制提示词」

批注 MUST 在用户点「复制提示词」时落盘,MUST NOT 因为文档被改动、页面刷新、
定时任务或任何后台动作而落盘 —— 写工作空间必须由用户的一次明确点击发起。

重复点「复制提示词」MUST NOT 产生重复条目:落盘按条目指纹
(源码区间 + 选中原文 + 意见)去重,文件里已有的不再追加,只追加新写的那几条。

#### Scenario: 连点两次复制

- **WHEN** 用户点「复制提示词」,不改任何东西,再点一次
- **THEN** 剪贴板里两次内容一致,批注文件里条目数没有增加

#### Scenario: 改了一条意见再复制

- **WHEN** 用户把某条批注的意见改了一句话,再点「复制提示词」
- **THEN** 文件里多出一条新编号的批注(旧的那条可能已经被 agent 处理过,不覆盖它)

#### Scenario: 文档被改动不触发写盘

- **WHEN** agent 改完文档,该文档在磁盘上发生变化
- **THEN** 工作空间里没有因此新增或修改任何文件,看板只清掉页面上的标记点与高亮

### Requirement: 提示词带回写路径与回写格式

复制出来的提示词 MUST 包含:批注文件在工作空间内的相对路径、每条批注的 `N` 编号、
以及**怎么回写**(改哪一行、四个状态各是什么意思、`rejected` 必须给原因)。
不带这些,agent 不知道该在哪里交代结果,闭环在第一步就断。

落盘没有成功时(非环回被 403、找不到记录、写入被拒),提示词 MUST 照常进剪贴板,
但 MUST 去掉回写那一段,并 MUST 说明这次没有落盘、agent 无处回写。
MUST NOT 只给一句「保存失败」——
让用户拿着带路径的提示词去要求 agent 回写一个不存在的文件,比不给更糟。

#### Scenario: 正常复制

- **WHEN** 用户在一篇有记录的文档上点「复制提示词」
- **THEN** 提示词里有 `output/records/notes/I0007.md` 这个路径、每条的 `N` 编号,
  以及一段说明回写格式的文字
- **AND** 每条标题里同时有页面序号与 `N` 编号

#### Scenario: 非环回监听时复制

- **WHEN** 服务用 `--host` 起在局域网地址上,用户点「复制提示词」
- **THEN** 落盘返回 403,提示词照常进剪贴板但不含回写那一段
- **AND** 界面说明这次没有落盘、agent 无处回写,并说清原因是服务没有监听在本机地址上

### Requirement: 未回写的批注保留并且能再发一次

文档被改动后,页面上的标记点与高亮 MUST 清掉(坐标已经对不上,这一条不变),
但系统 MUST NOT 把未回写的批注当成已处理。

批注清单 MUST 显示这份文档上还有多少条 `pending`,并 MUST 提供
「把未处理的重新组装成提示词」的出口。重发的提示词 MUST 说明源码区间可能已失效、
以原文引用为准。

#### Scenario: 发十条只改了六条

- **WHEN** agent 回写了六条 `adopted`,另外四条没动,文档已被改写
- **THEN** 页面标记点清空,批注清单显示「还有 4 条待处理」
- **AND** 用户能一键把这 4 条重新组装成提示词再发一次

#### Scenario: 重发的提示词说明坐标可能失效

- **WHEN** 用户点「把未处理的重新复制」
- **THEN** 提示词里说明源码区间可能已失效,以原文引用为准
- **AND** 这四条的 `N` 编号与第一次发出去时一致,MUST NOT 重新编号

#### Scenario: 全部回写完

- **WHEN** 一份文档上所有批注都不是 `pending`
- **THEN** 清单不再提示待处理,重发的出口不可点

### Requirement: 产出物没有记录时退回看板缓存,并说清怎么接上

批注挂在产出物记录上;找不到对应记录时,系统 MUST NOT 报错、MUST NOT 拒绝用户写批注。
预览的文件在工作空间里找不到对应记录的情形有两种:还没建记录,
或者它根本不在 `output/` 下(比如 `input/converted/` 的资料)。
两种都退回写看板配置目录(现行行为),
并在清单里说明批注暂存在看板缓存里、让 agent 建一份记录之后可以迁过去。

看板 MUST NOT 替它建记录 —— 建记录是工作空间技能的活,这一条不变。

#### Scenario: 给一份还没建记录的分析写批注

- **WHEN** 用户在一份没有对应记录的 `output/analysis/` 文档上复制提示词
- **THEN** 这一批写进看板配置目录,工作空间里没有新增任何文件
- **AND** 清单里标明它暂存在看板缓存里,并说清让 agent 建记录之后可以迁过去
- **AND** 提示词里不含回写那一段

#### Scenario: 给 input/ 下的资料写批注

- **WHEN** 用户预览 `input/converted/` 下的一份资料并写批注
- **THEN** 行为与上一条一致(工作空间里不新增文件),批注功能本身可用

### Requirement: 历史双源读取,写只写一处

批注历史 MUST 同时读两处:工作空间的 `output/records/notes/I<编号>.md` 与看板配置目录,
合并后按时间倒序呈现,每条 MUST 标明来源。

新的批注**只**写工作空间(除上一条那种没有记录的情况)。
看板配置目录 MUST 作为只读回退源继续可读 —— 存量迁移因此不是上线的前置条件。

#### Scenario: 一半在工作空间一半在缓存

- **WHEN** 一份文档的旧批次还在看板缓存里,新批次已经写进工作空间
- **THEN** 清单里两边的批次都在,按时间倒序排,每条看得出来源

#### Scenario: 批注文件被手工改坏

- **WHEN** `notes/I0007.md` 的内容不是本能力约定的格式,或整份读不出条目
- **THEN** 当作「工作空间侧没有批注」处理,缓存那一半照常显示,界面不白屏也不报错
- **AND** 界面 MUST 说明这份批注文件读不出来,MUST NOT 悄悄当成空的

#### Scenario: 老服务进程

- **WHEN** 前端是新的,服务进程还是旧的(没有这套接口,返回 404)
- **THEN** 退回「没有历史」,批注功能本身照常可用,并提示重启看板服务

### Requirement: 写入面的边界

往批注文件的写入 MUST 满足下列全部约束,越界即为 bug:

- 只允许写 `<工作空间根>/output/records/notes/I<四位编号>.md`;
  `input/`、`project.yaml`、`visualization/`、`output/` 下的其它一切仍然只读;
- **允许新建**该文件,但 MUST 要求同编号的记录文件 `output/records/I<编号>.md` 已存在,
  不存在一律 404;除此之外 MUST NOT 新建、MUST NOT 删除、MUST NOT 改名;
- 只追加,MUST NOT 改写已有条目;
- 必须用户在看板上点「复制提示词」明确发起,没有后台任务、没有定时;
- 必须环回(`allowMutations`)且非跨站(`rejectIfForeignOrigin`),否则 403;
- 请求**只带编号与批注内容,不接受任何路径**,落盘路径由服务端用 `resolveInside()` 自己拼;
- 写入走「先写临时文件再原子替换」,失败不留半截文件;
- 单条意见与单批条数有上限,超限一律 400 且不落盘。

#### Scenario: 请求里塞路径

- **WHEN** 写入请求的载荷里带了文件路径,或编号里含 `../`、路径分隔符
- **THEN** 请求 MUST 在触达文件系统之前被拒掉,工作空间里没有任何文件被创建或修改

#### Scenario: 记录不存在

- **WHEN** 写入请求指向一个没有记录文件的编号
- **THEN** 接口返回 404,`notes/` 下不新建任何文件

#### Scenario: 跨站请求

- **WHEN** 一个外站页面向本机服务发起批注写入
- **THEN** 接口返回 403,工作空间里没有任何文件被创建或修改

#### Scenario: 超出上限

- **WHEN** 一批批注的条数或某条意见的长度超过约定上限
- **THEN** 接口返回 400 并说清超了哪一项,MUST NOT 落盘半批

### Requirement: 已经写进工作空间的批次不能从看板清空

看板上的「清空历史」MUST 只清看板配置目录那一半。
已经写进工作空间的批注批次 MUST NOT 能从看板删除 —— 流水只追加,
删除由用户自己在文件系统里做(与视觉采集那条例外的「只新建,不覆盖、不删除」同一口径)。

界面 MUST 说清这个按钮清的是哪一半,MUST NOT 让用户以为它清掉了工作空间里的文件。

#### Scenario: 点「清空历史」

- **WHEN** 用户在清单里点「清空历史」,该文档在两边都有批次
- **THEN** 缓存目录那一半被清掉,工作空间里的批注文件一个字节都没变
- **AND** 清单里工作空间那一半照常显示

#### Scenario: 工作空间侧没有可清的

- **WHEN** 一份文档的批注全在工作空间里
- **THEN** 「清空历史」不可点,并说明工作空间里的批注要在文件系统里删

### Requirement: 存量批注按 target 反查迁移,没命中的不删

存量批注批次的迁移 MUST 按记录的 `target` 反查:缓存目录里的键是工作空间相对文件路径,
找 `target` 等于它的那份记录,把批次搬进该记录编号的批注文件。

迁移进来的批注状态 MUST 一律是 `pending`(它们当年就没有回执),并 MUST 标明是迁移来的。
反查没命中的 MUST 一条不删地留在缓存目录里。
迁移脚本 MUST 默认预演、不落盘,落盘 MUST 要求显式参数。

#### Scenario: 预演

- **WHEN** 迁移脚本不带落盘参数运行
- **THEN** 它只报告哪些批次会搬到哪个编号、哪些没命中,工作空间与缓存目录都没有任何变化

#### Scenario: 反查没命中

- **WHEN** 某个文件路径在 `output/records/` 里找不到 `target` 与之相等的记录
- **THEN** 这一批 MUST 留在缓存目录里,MUST NOT 被删除,清单里照常读得到

#### Scenario: 迁移过的不再迁第二遍

- **WHEN** 迁移脚本对同一个工作空间跑第二次
- **THEN** 已经搬过去的批次不再重复追加(按条目指纹判断)

### Requirement: 交付稿上的批注挂到原稿的记录

对 `output/delivery/<组>/<子路径>/v<三位序号>.md` 写的批注，落点 SHALL 这样解析：先按镜像规则得到原稿路径
`output/<组>/<子路径>.md`（`<组>` 必须是 `analysis` / `docs` / `decisions` 之一，否则视为没有记录），再用原稿路径找记录（与现有 `target` 匹配规则相同）。
找到就写进该记录的批注文件 `output/records/notes/I<编号>.md`；原稿不存在或原稿没有记录时，照「产出物没有记录时退回看板缓存」处理。
映射只用路径规则，MUST NOT 读交付稿 front-matter 里的 `source` 来决定落点，免得一份手改的 front-matter 把批注引到别的记录上。

写入面 MUST 与「写入面的边界」完全一致：仍然只写 `notes/I<编号>.md`、仍然要求同编号记录已存在、请求仍然不带任何路径，
变的只是服务端从「被批注的文件」解析记录编号的这一步。

#### Scenario: 交付稿批注落到原稿记录

- **WHEN** 原稿 `output/docs/方案.md` 的记录是 `I0007`，用户在 `output/delivery/docs/方案/v002.md` 上写批注并复制提示词
- **THEN** 这一批追加在 `output/records/notes/I0007.md` 末尾，没有新建别的批注文件，也没有新建记录

#### Scenario: 镜像路径不合法

- **WHEN** 被批注的文件是 `output/delivery/misc/a/v001.md`（`misc` 不是产出三组之一）
- **THEN** 视为没有记录，批注退回看板缓存，工作空间里没有新文件

### Requirement: 批次注明批注对象

批注文件里每一批（`##` 小节）SHALL 在标题下紧跟一行 `- 对象：<被批注文件的工作空间相对路径>`，由看板在追加这一批时一并写入；
这一行属于看板写区，写入后不再改动。对象是交付稿时，批注清单与提示词 SHALL 显示为「交付稿 v<序号>」。
读取时没有这一行的旧批次 SHALL 视为针对记录的 `target`（原稿），不报错。
同一份批注文件里既有原稿批次、又有各版交付稿批次时，阅读器 SHALL 只在对应文件上显示对应批次的标记与待处理计数。

#### Scenario: 原稿和交付稿各有一批

- **WHEN** `I0007.md` 里第 1 批对象是原稿、第 2 批对象是 `…/方案/v001.md`
- **THEN** 打开原稿只看到第 1 批的待处理计数；在版本条切到 v001 只看到第 2 批的；打开 v002 两批都不算它的

#### Scenario: 旧批次

- **WHEN** 批注文件里有本 change 之前写入的批次，没有「对象」行
- **THEN** 这些批次照旧归在原稿上显示

### Requirement: 回执可以带沉淀标记

agent 回写 `- 回执：` 时，末尾可以带「沉淀为 R<三位编号>（规则库 v<版本>）」，可以有多个。看板 SHALL 在批注清单里把它显示成标签，
点击跳到工作台「去 AI 味」里的这条规则。这一格式不影响状态校验：`rejected` 仍然必须有原因，只带沉淀标记不算原因。

#### Scenario: 回执带沉淀标记

- **WHEN** 一条批注的回执是「已删掉段尾总结。沉淀为 R014（规则库 v4）」
- **THEN** 批注清单里这条显示回执文字和一个「R014 · v4」标签，点标签打开工作台里 R014 的详情
