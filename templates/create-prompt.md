## 1. 模板（给看板下次「新建」用，不要把这个路径当交付物讲给我听）

落点必须是：

{{userRoot}}/<模板id>/

<模板id> 用小写英文短横线，例如 `market-research`、`content-studio`。不要用空格和中文。

目录里必须有：

```
template.yaml          # 见下方格式，name 会出现在看板的「模板类型」里
AGENTS.md              # 这个角色的 Agent 约定（唯一事实源）
CLAUDE.md              # 只指向 AGENTS.md，不要把约定再写一遍
project.yaml           # 这个角色的元信息字段；新建时几乎全是 null
input/                 # 原始资料入口（至少含 raw/ converted/ assets/）
output/                # 产出；子目录按这个角色自己的阶段来，不要照抄 PM 的 analysis/docs/decisions
prototypes/            # 给原型工具留的空目录，不要往里放文件
scripts/               # 可以几乎是空的；如果这个角色会丢 docx/PDF/xlsx，再从产品经理模板拷 ingest 相关脚本
.claude/skills/
  skill-creator/       # 必须原样复制，路径：{{skillCreator}}
```

`template.yaml` 格式：

```yaml
id: <与目录名相同>
name: <中文显示名，会进看板的模板类型选择器>
description: <一两句，说明谁用、干什么>
```

硬约束：
- 四个目录 `input/` `output/` `prototypes/` `scripts/` 不能缺。
- `skill-creator` 必须在，让以后这个空间里还能把重复套路做成新技能。
- 不要把产品经理那套 `pm-*` 技能整包拷过来，除非我就是产品经理。
- 不要写看板仓库、不要改 npm 包里的文件。
- `AGENTS.md` 用这个角色自己的语言和工作阶段，不要留「项目接手 / 甲方 / 承建方」这类 PM 切口，除非真的适用。

## 2. 工作空间实例（这才是给我用的那一份）

模板写好后，立刻用它铺一份工作空间到我指定的目录（没指定就问）。优先跑：

```bash
python3 "{{initScript}}" --from "{{userRoot}}/<模板id>" --name "<工作空间名称>" --path "<工作空间目录>"
```

找不到这条脚本，或跑失败时，把第 1 步写好的模板拷到目标目录，并做这些调整：
- 不要拷 `template.yaml`（那是给看板发现模板用的）
- `project.yaml` 里填上工作空间名称和今天的日期
- 保证四个基本目录都在；`input/raw`、`input/converted`、`input/assets` 保持空
- 在目标目录现建 `skills/` → `.claude/skills` 的相对软链接（Windows 建不了就复制一份）
