# preview-annotation

## Purpose

约定 markdown 预览窗里的批注交互:由「批注」按钮显式进入模式,用「选取元素 / 选中文字」
两种选法把用户意见锚定到源文件的字节区间,按文档攒成待发送批次,再组装成可直接粘贴给
agent 的提示词。锚点契约 A2(`data-source-file` + `data-source-range`)是对外协议,
不是本仓内部细节,外部工具靠它把页面选区映射回源文件。当前批注放浏览器本地;
用户点「复制提示词」时落盘,写进工作空间的 `output/records/notes/I<编号>.md`
(该产出物没有对应记录时退回看板配置目录),逐条状态与回写规则见 `annotation-status-loop`。
本能力原由 `annotate-to-agent-loop` 落地,落点从看板配置目录改到工作空间由
`annotation-workspace-loop` 收口。

## Requirements

### Requirement: 批注是一种模式,激活之后才存在

批注交互 MUST 由阅读器标题栏的「批注」按钮显式激活。激活后 SHALL 出现一条工具栏胶囊,
形态与相邻仓 annotation-collect 的采集款一致(贴右下角的水平胶囊、仅图标按钮 + tooltip、
按功能分组用竖线隔开)。**未激活时预览 MUST NOT 有任何批注入口** —— 划选文字只是划选,
不出现浮动的「批注」按钮。收起胶囊 MUST 把描边、待写的批注框、清单一起收掉。

#### Scenario: 没激活时划选只是划选
- **WHEN** 用户没点「批注」,直接在预览里划选一段文字
- **THEN** 选区旁不出现任何批注入口,界面无变化

#### Scenario: 点「批注」进入批注模式
- **WHEN** 用户点阅读器标题栏的「批注」
- **THEN** 右下角出现工具栏胶囊,默认停在「选取元素」
- **AND** 胶囊上按顺序有三组:选取元素 / 选中文字、复制提示词 / 清空、批注清单 / 收起

#### Scenario: 非 markdown 的预览不提供批注
- **WHEN** 用户打开的是图片、表格、原型 HTML 或图库预览
- **THEN** 标题栏没有「批注」按钮,阅读器行为与改动前一致

### Requirement: 两种选法 —— 默认拾取元素,可切到选中文字

激活后 SHALL 有两种选法,由胶囊第一组切换,默认 `选取元素`:

- **选取元素**:鼠标扫过正文时,当前元素 MUST 描一圈虚线并标出标签名与尺寸;
  点一下即选中该元素(实线框),它声明的源码区间就是这条批注的锚点。
  此时 MUST NOT 触发正文里链接的跳转。
- **选中文字**:划选一段文字,松手即打开批注框。选区为空或只有空白字符时 MUST NOT 打开。

两种选法产出的批注形状一致(同一套字节区间 + 原文引用),下游的提示词组装不区分来源。

#### Scenario: 拾取一个段落
- **WHEN** 用户在「选取元素」下把鼠标移到一个段落上,再点一下
- **THEN** 该段落先描虚线、点后转实线,批注框贴着它打开,标题写明选中的是 `<p>` 与结构类型
- **AND** 写完保存后,这段在预览里带上高亮,左上角出现一枚编号标记点

#### Scenario: 切到选中文字划一段
- **WHEN** 用户点「选中文字」,再在正文里划选几个字
- **THEN** 松手即打开批注框,标题写明选中的原文
- **AND** 不再额外画一圈外接矩形(浏览器自己的选区高亮已经在了)

#### Scenario: 空选区不给入口
- **WHEN** 用户只是单击、或划选到的全是空白
- **THEN** 不打开批注框,界面无变化

### Requirement: 标记点即入口 —— 定位与修改与 annotation-collect 一致

每条批注 SHALL 在预览里画一枚编号标记点,钉在它所批那块的左上角。
点标记点 MUST 把这条的批注框原地重新打开(带着已写的正文,按钮是「改好了」),并补一圈实线框。
批注清单里每条 MUST 有「定位 / 改 / 删」:定位滚到那块并短暂加重高亮,改在滚过去之后把框打开。
原位置在当前文档里已经找不到时,MUST 给一句提示说明批注内容还留着,MUST NOT 硬开一个存不回去的框。

#### Scenario: 点标记点改一条
- **WHEN** 用户点预览里的编号标记点
- **THEN** 批注框在原地打开,里面是已经写过的内容,按钮是「改好了」

#### Scenario: 从清单定位
- **WHEN** 用户在批注清单里点某一条的「定位」
- **THEN** 预览滚到那一块并短暂加重它的高亮

#### Scenario: 原位置已经找不到
- **WHEN** 文档被改写,某条批注的字节区间在当前正文里对不上任何位置
- **THEN** 定位与修改给一句提示,说明这一条的原位置失效、批注内容还在
- **AND** 预览本身不受影响

### Requirement: 批注必须锚定到源文件的字节区间

每条批注 MUST 记录:所属文件在工作空间内的相对路径、源文件中的起止字节偏移、
以及选中的原文引用。锚点 MUST 满足两条:切出来的源码片段完整包含用户选中的内容;
片段内的行内标记(强调、行内代码、链接、图片)MUST 成对完整,不能被从中间切断。

#### Scenario: 选区落在纯文本中间
- **WHEN** 用户选中一个段落中间的若干字
- **THEN** 批注记录的区间切出来的源码,就是这几个字

#### Scenario: 选区跨过行内标记
- **WHEN** 用户的选区起点或终点落在强调、行内代码或链接的内部
- **THEN** 区间向外扩到该标记的完整边界,切出来的源码是成对完整的
- **AND** 切出来的源码完整包含用户选中的可见文字

#### Scenario: 文本节点没有位置信息
- **WHEN** 选区落在代码块内(其文本节点由渲染管线合成,不带源码位置)
- **THEN** 退回到最近的、带位置信息的祖先元素的区间
- **AND** 批注仍然可以保存,不报错

#### Scenario: 锚点算不出来
- **WHEN** 选区两端都找不到任何带位置信息的祖先
- **THEN** 不保存批注,并提示这段内容暂时不支持批注
- **AND** 预览本身不受影响

### Requirement: 源码位置按契约 A2 声明到 DOM 上

markdown 预览渲染时,带源码位置的节点 MUST 把位置以**契约 A2** 的形状声明到 DOM 属性上:
`data-source-file` 是相对工作空间根的文件路径,`data-source-range` 是源文件的**字节**区间、
**左闭右开**、写成 `起,止`。两个属性 MUST 同时存在才算一次有效声明;缺任一个 MUST 被视为
没有声明,由锚点算法退回上一级兜底。

这是一条**对外协议**(annotation-collect 的 `AGENTS.md` §4 定稿),不是本仓的内部实现细节:
外部工具(浏览器扩展等)靠读这两个属性就能把页面上的选区映射回源文件,无需了解看板的渲染管线。
属性名与语义 MUST NOT 自行改写。

#### Scenario: 带位置的元素声明了两个属性
- **WHEN** 预览渲染 `output/方案.md`,某个段落在源码里占字节区间 1204 到 1876
- **THEN** 该段落对应的元素上有 `data-source-file="output/方案.md"` 与
  `data-source-range="1204,1876"`

#### Scenario: 只有一个属性时不算声明
- **WHEN** 某个节点只盖上了 `data-source-range` 而没有 `data-source-file`
- **THEN** 锚点算法不把它当作有位置的节点,退回最近的、两个属性齐全的祖先

#### Scenario: 外部工具可据此定位
- **WHEN** 一个不了解看板渲染管线的外部工具读取预览页 DOM
- **THEN** 仅凭这两个属性就能得到「哪个文件的哪个字节区间」,不需要看板提供额外接口

### Requirement: 批注按文档攒成一个待发送批次

同一篇文档上的批注 SHALL 攒成一个待发送批次。批次发送前,用户 MUST 能逐条修改和删除,
也能整批丢弃。批次 MUST 在页面刷新、切换文档、切换工作空间之后仍然保留。

#### Scenario: 攒多条再一起发
- **WHEN** 用户在同一篇文档上写了三条批注
- **THEN** 批注清单显示这三条,胶囊上给出「复制提示词」这个出口

#### Scenario: 未发送的批注刷新后还在
- **WHEN** 用户写完批注后刷新页面,重新打开同一篇文档
- **THEN** 之前的批注和高亮都还在,批次仍然是未发送状态

#### Scenario: 整批丢弃
- **WHEN** 用户点「清空批注」
- **THEN** 该文档下所有未发送批注被删除,预览里的高亮同时消失

### Requirement: 文档被改动后清掉标记,批注不因此落盘

复制提示词 MUST NOT 自动清空当前批注。系统检测到该文档在磁盘上被改动过、
且这篇文档还有当前批注时,MUST 清掉页面上的标记点与高亮 ——
理由只有一条:字节区间已经对不上了。系统 MUST NOT 尝试把旧批注重新贴回被改写后的文档。

清标记 MUST 是纯前端动作,MUST NOT 因此往工作空间或看板配置目录写任何东西:
批注在用户点「复制提示词」时就已经落盘了(见 `annotation-status-loop`),
文档改动这一刻没有任何新东西要存。

清掉标记 MUST NOT 等于「这批处理完了」。清单 MUST 显示这份文档上还剩多少条待处理,
并提供把它们重新组装成提示词的出口。

#### Scenario: 复制之后当前批注还在

- **WHEN** 用户点「复制提示词」
- **THEN** 提示词进入剪贴板,当前批注与高亮原样保留,用户可以再复制一次

#### Scenario: 文档被改动后清标记

- **WHEN** 该文档在磁盘上发生变化且这篇文档还有当前批注
- **THEN** 页面上的标记点与高亮消失
- **AND** 工作空间与看板配置目录都没有因此新增或修改任何文件
- **AND** 清单里显示这份文档上还有几条待处理

#### Scenario: 这一批从没复制过就赶上文档变化

- **WHEN** 用户写了批注但一次都没点过「复制提示词」,文档就被改动了
- **THEN** 标记点照样清掉,并明确告诉用户这一批没有落过盘、已经无法找回
- **AND** MUST NOT 悄悄丢弃、MUST NOT 假装它进了历史

#### Scenario: 用户点清空当前批注

- **WHEN** 用户点「清空批注」
- **THEN** 该文档下所有当前批注被删除,预览里的高亮同时消失,已落盘的批注不受影响

### Requirement: 当前批注在浏览器本地,落盘的批注跟工作空间走

当前正在写的批注 MUST 存放在浏览器本地存储里,按工作空间分键 —— 这一条不变。

落盘的批注 MUST 写进工作空间的 `output/records/notes/I<编号>.md`
(产出物有记录时),格式与状态见 `annotation-status-loop`。
找不到对应记录时 MUST 退回看板配置目录(`note-history/`),并在界面上说清楚它暂存在哪儿。

写工作空间 MUST 过 `allowMutations` 与 `rejectIfForeignOrigin`:非环回或跨站一律 403。
这比改动前更严 —— 原先写的是看板配置目录,不受这两道闸约束。

历史 SHALL 出现在批注清单里供查看,来源(工作空间 / 看板缓存)MUST 看得出来。
**已经写进工作空间的批次 MUST NOT 能从看板清空**:清空历史只清缓存那一半,
工作空间里的删除由用户自己在文件系统里做。

#### Scenario: 写当前批注不动磁盘

- **WHEN** 用户新建、修改、删除当前批注
- **THEN** 工作空间目录内没有任何文件被创建或修改

#### Scenario: 落盘写进工作空间

- **WHEN** 一批批注在用户点「复制提示词」时落盘,该文档有对应记录 `I0007`
- **THEN** 内容写进 `output/records/notes/I0007.md`
- **AND** 该产出物文件本身、`output/records/I0007.md`、`input/`、`project.yaml` 一个字节都没变

#### Scenario: 非环回监听时落盘被拒

- **WHEN** 服务用 `--host` 起在局域网地址上,用户点「复制提示词」
- **THEN** 落盘返回 403,提示词照常进剪贴板但不含回写那一段,界面说清原因

#### Scenario: 本地存储的内容坏了

- **WHEN** 本地存储里的批注数据不是合法 JSON,或结构对不上
- **THEN** 当作「没有当前批注」处理,界面正常展示文档,不白屏也不报错

#### Scenario: 换一个浏览器打开

- **WHEN** 用户在另一个浏览器或无痕窗口里打开同一个工作空间
- **THEN** 看不到之前没落盘的当前批注(本地存储的已知代价)
- **AND** 已经落盘的批注照常看得到,因为它们在工作空间里

#### Scenario: 换一台机器打开同一个工作空间

- **WHEN** 用户把工作空间同步到另一台机器,在那里打开看板
- **THEN** 已经落盘到工作空间的批注照常看得到(这正是搬家的目的)
- **AND** 留在看板缓存里的那一半看不到,界面对这两半的区别有说明

### Requirement: 把一个批注批次组装成可直接粘贴的提示词

批注胶囊 SHALL 提供一个把整批批注组装成提示词并复制到剪贴板的动作。
这个动作同时是**落盘的触发点**(见 `annotation-status-loop`):先落盘,再组装提示词。

提示词 MUST 包含:目标文件在工作空间内的相对路径、每条批注选中的原文引用、
对应的源码字节区间、这段区间在文档结构上是什么(段落 / 表格行 / 列表项 / 跨块)、
用户写的意见、**这条批注的 `N` 编号**、**批注文件的相对路径**、
以及**怎么回写状态**(改哪一行、四个状态各是什么意思、`rejected` 必须给原因)。
提示词 MUST 说明:先按批注意见修改,改完后做好全文口径同步,避免出现自相矛盾。
提示词 MUST 按源码区间**倒序**排列批注 —— 先改后面的,前面的坐标才不会失效。
倒序只改处理顺序,每条标题里的「批注 N」MUST 与页面标记点和清单里的编号一致,
MUST NOT 按处理顺序重新编号;`N` 编号与页面序号 MUST 同时出现,两者是两套编号。

落盘没有成功时(非环回被 403、找不到记录、写入被拒),提示词 MUST 照常进剪贴板,
但 MUST 去掉回写那一段并说明这次没有落盘、agent 无处回写。

#### Scenario: 复制一批批注

- **WHEN** 用户在有三条批注的文档上点「复制提示词」,三条在页面上编号为 1、2、3,其中第 3 条在文件最靠后
- **THEN** 这三条先落盘,拿到各自的 `N` 编号
- **AND** 剪贴板里是一段可直接粘贴给 agent 的完整提示词,三条按源码区间从后往前排列
- **AND** 靠后那条仍标为「批注 3」,不得被重编成「批注 1」,并同时带着它的 `N` 编号
- **AND** 提示词里有批注文件的相对路径和回写格式说明
- **AND** 提示词要求先按批注意见改、再做全文口径同步,而不是"未提及的一概不动"
- **AND** 界面给出复制成功的反馈

#### Scenario: 剪贴板接口不可用

- **WHEN** 页面不在安全上下文里(例如服务用 `--host` 起在局域网地址上,走的是普通 http)
- **THEN** 退回展示一个已全选、可直接手动复制的文本框,并说明原因
- **AND** MUST NOT 只报一句"复制失败"就完事

#### Scenario: 落盘失败但还是要给提示词

- **WHEN** 落盘返回 403 或 404,用户点的是「复制提示词」
- **THEN** 提示词照常进剪贴板,但不含批注文件路径与回写那一段
- **AND** 界面说清这次没有落盘、agent 无处回写,以及原因是什么

#### Scenario: 没有批注时不给复制

- **WHEN** 当前文档一条批注都没有
- **THEN** 胶囊上的「复制提示词」与「清空」不可点,清单显示空态
