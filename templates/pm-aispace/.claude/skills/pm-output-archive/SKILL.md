# 二次归档：分堆 + 短索引

看板「产出文档」列表行的「更多 → 归档」会把一份产出物移进同组的 `一次归档/`
（真正写盘的是 `scripts/archive_output.py`，看板只起它）。
一次归档只是「先挪开」：它让主列表变短，但归档区攒到十几份之后，平铺着仍然要一份份翻。

二次归档把它们**按主题或阶段分堆，每堆写一份短索引**。
读一份几百字的索引就知道这一堆要不要打开 —— **降低读取成本，不是禁止读**。

手写 Markdown 的写法见工作空间 `AGENTS.md` 的「Markdown 写法」一节，这里不复述。

## 先看清现场

1. 读 `output/<组>/一次归档/README.md`：清单里每一行是「日期 · 原路径 → 新路径 · 来由」，
   这是你判断每份为什么被归档的第一手线索。README 底下那段提示词可能被用户按自己的语境改过，
   **以用户改过的为准**。
2. 列目录。已经在某个堆子目录里的文件是上一轮分好的，**不动**；只处理平铺在 `一次归档/` 根上的。
3. 平铺的文件少于五六份时，先问用户要不要分 —— 三份文件分三堆，索引比正文还长，没有意义。

## 怎么分堆

按**主题或阶段**分，不按文件类型、不按日期分：

- 主题：同一个模块 / 同一个议题的几轮稿子（「计费模块」「对接方案」）
- 阶段：同一个阶段的中间产物（「接手摸底」「第一轮评审」）

每堆一个子目录 `output/<组>/一次归档/<主题短名>/`，短名用几个字的中文，不带日期前缀。
**一份文件只进一堆。** 实在两头都沾，放进它最初产生的那一堆，在另一堆的 `INDEX.md` 里用相对路径链过去。

移动只用 `mv`（或 `git mv`），**不删除任何文件，不改文件内容，不改文件名**。
只在 `output/<组>/一次归档/` 之下移动，不跨组、不移出 `一次归档/`。

## 每堆一份 `INDEX.md`

几百字，回答三件事，缺一不可：

```markdown
---
title: 计费模块 · 旧稿
created: 2026-09-23
updated: 2026-09-23
---

# 计费模块 · 旧稿

## 这堆是什么

三份计费口径的早期分析与一份被取代的需求说明。列出文件并各用一句话说清：

- [计费口径初稿](计费口径初稿.md) —— 按 30 天滚动的第一版口径分析
- …

## 当初为什么产生

接手第一周对齐财务口径时写的；后来口径改成自然月（见 `output/decisions/0001-…`），这几份随之作废。

## 什么情况下需要回来翻

- 有人问「当初为什么没按 30 天滚动算」时，第一份里有当时的对比数据；
- 做历史订单迁移时，初稿附录里有旧口径的边界样例。
```

- `analysis/` 与 `decisions/` 下的 `INDEX.md` 要带 `title` / `created` / `updated` 三个扁平字段
  （体检脚本会查）；`docs/` 下不强制，写了也无妨。
- 「什么情况下需要回来翻」写**具体情形**，不写「一般不需要」。写不出具体情形，
  说明你还没读懂这堆东西，回去读完再写。
- 文件链接用相对路径，看板里点得开。

看板的归档区会把每堆的 `INDEX.md` 排在那一堆最前面、标成「堆索引」，不用做别的。

## 移完之后跟进记录的 `target`

`output/records/` 里 `target` 指着被移动文件的记录要跟进到新路径 ——
一次归档之后它们指着组根目录下的旧路径，二次归档之后又变一次。做法与 `pm-output-record`
的「产出物改名或移动时跟进 `target`」同一套：

```bash
grep -rl "output/<组>/一次归档/某文件.md" output/records/
grep -rl "output/<组>/某文件.md" output/records/        # 一次归档后还没跟进的
```

只改 `target` 与 `updated`，**不改 `status`** —— 归档改变的是位置，不是产出物的状态。

`一次归档/README.md` 的清单是历史，**已有的行不要改写**。
想记一笔「这一轮分成了哪几堆」，在清单标记**之外**另起一段写。
**不要删掉清单的那两行标记注释**，归档脚本靠它们追加，找不到就拒绝归档。

## 不要做的事

- **不产出任何形式的「始终无需再读」「可以跳过」清单。**
  那是 AI 的单向判断、会判错，错一条的代价是某份资料从此没人再看。
- **不往 `AGENTS.md`、技能、`CLAUDE.md` 或任何会影响后续会话的地方写跳过规则**
  （「归档目录不用读」「一次归档/ 下的忽略」都算）。
  归档降低的是读取频率与成本，不是可达性 —— 每一份归档文件都必须仍然能被搜到、被读到。
- 不删除、不合并、不改写归档文件的内容；不把文件移出 `一次归档/`。
- 不给堆索引建产出物记录（`output/records/`）—— 它是归档区的目录说明，不是产出物本身。
