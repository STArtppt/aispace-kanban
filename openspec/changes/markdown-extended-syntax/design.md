## Context

`src/app/components/Markdown.tsx` 的管线是 `react-markdown` + `remark-gfm`（关掉单波浪删除线）+ `rehype-raw`。没有 Obsidian 扩展。用当前的 `remark-parse` 实测（合成样例，不是某份真实文档）：

- `[[链接]]`、`%%注释%%`、段尾 `^id`、`$公式$` 都是普通文本节点，原样出现在段落里。
- `> [!note] 标题` 加下一行正文，解析成一个 blockquote，文本是 `[!note] 标题\n正文`。标记露在引用里。
- `#标签`（`#` 后没有空格）是**段落**，不是 H1。`# 标题` 才是 H1。写法规范里「行首标签会被当成 H1 混进目录」这句话，对现在的渲染器不成立；标签的实际问题是裸文本，不是目录污染。目录仍由渲染后的 `h1`–`h4` 生成，标题 id 在布局后写成 `doc-h-N`。

阅读器把相对链接交给 `urlTransform`：以**当前文件所在目录**为基准拼成 `/api/projects/:id/file?path=`。wikilink 只要产出这种相对地址，点开的路径就和现在的 `[文本](../x.md)` 同一条。

`workspace-markdown-convention` 当初不接插件，是因为全库文件名唯一这个前提不成立：`input/converted/` 镜像着原始资料，同名文件会重复。这个前提现在仍然不成立。本变更要解禁语法，但不能靠「猜一个同名文件」来解禁。

## Goals / Non-Goals

**Goals:**

- 七类语法在预览里按 proposal 的规则显示，标记不再当正文露出来。
- 能点的链接走现有 `urlTransform`，不新开接口。
- 写法规范、校验脚本、网页提取的剥除逻辑和渲染能力对齐。存量按子集写的文档不用改。

**Non-Goals:**

- 全库文件名 / 别名表 / 反向链接。
- 把另一份 Markdown 的正文嵌进当前页。
- 改 `doc-h-N`，或让 `#标题` 在打开后滚动到位。
- 把未决问题、帮助页里的 Markdown 改成另一套管线。它们走同一个 `Markdown` 组件，有 `sourceFile` 才按工作空间路径解析 wikilink。

## Decisions

### 决策一：wikilink 产出相对路径，不建文件名索引

**选择**：remark 插件把 `[[目标]]` 换成普通链接节点，`href` 相对当前文件目录，交给已有的 `urlTransform`。

- `./` 或 `../` 开头：相对当前文件。
- 含 `/` 且不是点相对：从工作空间根算，再折成当前文件的相对路径。折的时候要用 `sourceFile`（阅读器已经传入，给批注锚点用）。没有 `sourceFile` 时（帮助页、问题正文）含 `/` 的目标原样交给 `urlTransform`，和那里今天的相对链接一样，不额外保证能打开。
- 没有 `/`：只认同一目录下的文件。没有扩展名就补 `.md`。
- `[[目标#标题]]` 的标题放进链接文字（没有 `|别名` 时），**不写进 href**。写进 href 会被 `resolveRelative` 当成路径的一部分，文件名后面粘上 `#标题`，点开就 404。
- `http(s):` 目标原样当外链。

**备选一：按 basename 在扫描结果里找，唯一才链接。** 不选。扫描结果不含全部可点文件（问题单、脚本不在里面），而且「唯一」会随 `input/converted/` 里新出现的同名分表而变，昨天能点的链接今天可能变瞎。同目录这一条是稳定的。
**备选二：先做别名表再解禁 wikilink**（`reader-internal-links` 的开放问题里提过）。不选。别名表要动服务端和 `api.ts`，而路径形态的 wikilink 现在就能点。别名仍是以后的事，不挡这次。

### 决策二：文档嵌入只做图片

**选择**：`![[x.png]]` 这类图片扩展名产出 `img`。其它 `![[文档]]` 产出带 `md-embed` 的链接，不请求、不递归渲染那份文件。

**备选：把目标 Markdown 拉进来再套一层 `Markdown`。** 不选。要处理循环引用、相对路径基准变了、以及批注锚点算在哪一份文件上。链接已经能点开，嵌入正文是另一项功能。

### 决策三：callout / 标签 / 注释 / 块锚点用自己的 remark 插件

**选择**：一个树变换插件，在 `remark-gfm` 之后跑。

- callout：blockquote 的首段文本以 `[!type]` 开头就换成带类名的 `div`（折叠形态用 `details`）。warning、caution、attention、failure、fail、missing、danger、error、bug、important 加「需要注意」的类，只用现有的 `--destructive`。其余灰底加边框。不引入绿 / 蓝。
- 行首 `#标签`：段落文本在行首（字符串开头或换行后）匹配 `#` 紧跟非空格时，换成小标签。不碰 `# 标题`，那已经是 heading 节点。
- `%%...%%`：从文本节点里删掉，可跨段落。代码块不是文本节点，围栏里的 `%%` 保留。
- 段尾 `^id`：从段落末尾删掉。不指望它成为可跳转锚点；标题上的 id 会被目录逻辑改写成 `doc-h-N`，写了也会丢。

**备选：装 `remark-wiki-link` 一类现成包。** 不选。它们的默认行为就是决策一拒绝的全库文件名解析，callout 包也经常带一套彩色图标。自己写的变换只覆盖上面这几条，输入输出都看得到。

### 决策四：数学用 remark-math + rehype-katex

**选择**：`remark-math` 在解析期认 `$...$` 和 `$$...$$`，`rehype-katex` 在 `rehype-raw` 之前把公式节点换成排版结果。非法公式不抛错，颜色用 `currentColor`，不另加彩色。katex 的字体文件随样式打进页面包。

**备选：继续禁用数学，只解禁 wikilink 和 callout。** 不选。禁用表里这七项是同一批「看板渲染不了」，只放行其中两条，校验脚本和规范还得留着半张禁用表，下一轮还是同一件事。
**备选：自己画公式或用图片。** 不选。公式排版不是这个看板要维护的东西。

插件顺序：`remark-math`（语法）→ `remark-gfm` → 自写树变换。注释先于 wikilink，避免 `%%[[x]]%%` 变成链接；wikilink 先于行首标签，避免 `[[#标题]]` 被当成标签。

### 决策五：规范与校验一起放行，不留「渲染了但仍报错」

**选择**：`AGENTS.md` 把七项挪进「现在可用」，并单列「不要依赖」：全库裸文件名、正文嵌入、打开后滚动。`check_markdown.py` 删除对应的错误。`web_ingest.py` 的 `sanitize_markdown` 不再剥这些语法，多个 H1 降级保留——那条和渲染无关。

**备选：渲染照做，校验继续报错。** 不选。脚本的文档字符串写着「契约变了这里要跟着变」。渲染已经接受的写法再报错，agent 会把刚写对的 callout 改回去。

## Risks / Trade-offs

**[裸文件名链到同目录，作者以为会全库匹配] →** 规范里写明，链接文字用目标自己的名字，点开落空时就是同目录没有这个文件，而不是打开了另一份同名文档。

**[`$100` 和 `$200` 写在同一行会被当成公式] →** 这是 `$...$` 语法的既有代价。金额用「100 元」或代码跨度包起来即可。rehype-katex 配置为失败不抛错，坏公式显示源文本，不把整篇预览打白。

**[katex 增大页面包] →** 只在前端依赖里，服务端打包不跟着装。接受，换的是公式不用再改写成图片或代码块。

**[自写插件改了文本节点，批注的字符偏移会偏] →** 拆开文本节点时按原节点的 `position.offset` 往下切，剩下的片段仍盖得上源码区间。注释和块锚点是从正文里拿掉的字符，那段源码不再有对应的文本节点，批注若正好框住 `%%...%%` 会落空。可以接受：注释本来就不是要批的正文。

**[帮助页和问题正文没有 sourceFile] →** 含 `/` 的 wikilink 不按工作空间根折算。这两处今天的相对链接本来也没有阅读器那条 `urlTransform`。不在本变更里补。

## Migration Plan

纯前端加模板约定：`pnpm build` 后刷新即生效，不用重启服务，没有新字段。回滚即撤销提交。

已经按禁用表写的文档继续用相对路径和普通引用，行为不变。没有迁移脚本要跑。
