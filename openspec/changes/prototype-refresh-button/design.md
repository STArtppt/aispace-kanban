## Context

`prototype-linked-group` 落地后，看板能把原型工作区同步过来的镜像目录聚合成一行，并标出「在线版落后」「离线包没更新」。
但数据只在同步脚本跑过之后才变：实测一次在 Make 里重新发布后，发布记录已在原型工作区落盘，
工作空间镜像的 `meta.json` 仍停在上一次发布时间，看板如实显示「在线版落后」—— 用户以为是看板的 bug。

同步脚本随后扩成双向：默认拉取（原型 → 工作空间镜像），`--push` 把工作空间 `input/ output/ project.yaml`
在时间窗内的变更清单写进原型目录的 `.workspace-inbox.md`，`--both` 先拉再推，`--status` 只读看两边差什么。
一次 `--both` 实测：导出离线包约 5 MB、拷贝十余份 md、推送百余条变更路径，耗时十几秒；Make 管理端没开时导出失败但退出码仍为 0。

看板已有两处「用户点按钮 → 起工作空间脚本 → 立即返回 + 轮询」：资料转换（`startIngest`）与数据源 schema 采集（`startSourceIngest`）。
区别在于：那两个脚本**在工作空间里**（`scripts/*.py`），这次的脚本在**工作空间之外的另一个仓库**。

## Goals / Non-Goals

**Goals：**
- 在看板上一键完成双向同步，完成后原型行自动反映新状态。
- 不让工作空间里的任何文件（包括被篡改的 `sync.json`）能诱导看板执行任意脚本。
- 新旧服务 / 前端 / 镜像任意组合都不白屏，缺条件时说清原因。

**Non-Goals：**
- 在看板里触发云发布（对外动作，Make 要求单独确认）。
- 单独的「只拉」或「只推」按钮、`--status` 预览面板。
- 在看板里配置或发现同步脚本（没有 `sync.json` 就提示去原型工作区跑一次）。
- 未接入的原型（普通卡片）的刷新。

## Decisions

### 1. 脚本定位：镜像里的 `sync.json` + 回指校验

- **选**：同步脚本每次拉取在镜像目录写 `{ "schemaVersion": 1, "script": "<绝对路径>/workspace-sync.mjs", "protoDir": "<绝对路径>" }`。
  看板读它，并校验：文件名 `workspace-sync.mjs` 且存在；`protoDir` 存在；`protoDir/.workspace-link.json` 的 `workspace` 与当前工作空间根 `realpath` 相等。
  回指是关键：伪造的 `sync.json` 能指向任意脚本，但指不到一个**反过来声明属于本工作空间**的原型目录，除非攻击者同时能写原型仓 —— 那已经不是看板能防的边界。
- **备选 A**：从 `SYNC.md` 的「原型源目录」行按 `<根>/<org>/src/prototypes/<id>` 往上推 `standards/`。
  不选：把某个私有工作区的目录布局硬编码进开源看板；布局一变按钮就静默失效。
- **备选 B**：在注册表 `projects.json` 里给每个工作空间手配脚本路径。
  不选：最安全但多一步配置，且一个工作空间可能对应多份原型、多个原型仓，配置形状变复杂；回指校验已经把风险收到可接受。

### 2. 参数固定、只接 itemKey

- **选**：请求体只有 `{ item: <itemKey> }`，服务端在当次扫描结果里找带 `linked.refresh.available` 的条目；命令固定为 `[process.execPath, script, protoDir, '--both']`，`spawn` 不经 shell。
- **备选**：`sync.json` 里带 `args` 让脚本自定义参数。不选：等于让工作空间文件决定命令行，校验面变大，且目前没有需求。

### 3. 用 `process.execPath` 起 node

- **选**：用运行看板的那个 node，不查 PATH。看板要求 Node ≥ 20，脚本用到的 `fetch`、`AbortSignal.timeout` 都在范围内；三平台一致，不需要进 `platform.mjs`。
- **备选**：`spawn('node')`。不选：GUI 启动或 nvm 环境下 PATH 里可能没有 node，Windows 还要处理 `node.exe` 解析。

### 4. 任务表独立、沿用 ingest 形状

- **选**：新增 `protoSyncJobs`，与 `ingestJobs` / `sourceJobs` 并列不共锁（刷新原型不该挡资料转换）；形状照抄 `{ status, message, startedAt, finishedAt, exitCode, log }` 再加 `item`。
  10 分钟看门狗（脚本自身导出超时 5 分钟，留一倍余量）超时 `kill` 并记 error。
- **备选**：复用 ingest 的任务表。不选：两件事互相 409 没有道理，界面上也不在一处。

### 5. 结果摘要直接用脚本的符号行

- **选**：脚本输出约定 `✓ / ! / · / ✗` 开头的行。退出码 0：`message` 取所有 `!` 行（没有就取 `✓` 行）；非 0：取最后一条 `✗` 行。原文照搬，看板不改写。
- **备选**：看板解析 JSON 输出。不选：要给脚本加一套机读输出模式，而这些行本来就是写给人看的中文。

### 6. 导出失败不另起错误态

- **选**：退出码 0 就是 `done`；离线包是否更新交给刷新后 `SYNC.md` 解析出的既有 `offlineStale` 呈现，结果行额外列出那条 `!`。
- **备选**：看板识别「连不上 Make」单独报 error。不选：文档与在线链接确实已更新，报 error 会误导；两处 orange 口径也会分叉。

### 7. 按钮位置与呈现

- **选**：`variant="outline"` 的「刷新」+ 旋转图标，放在两个打开按钮之前；运行中禁用并显示「正在刷新…导出离线包可能要一两分钟」；结果行放在行底现有提示区（成功灰、失败 orange，符合「orange 只给需要注意」）。不可用时按钮置灰 + `title` 说明原因，不在行里占额外高度。
- **备选**：放进行底提示区当文字链接。不选：用户明确要求和打开按钮并列、直接点。

## Risks / Trade-offs

- [看板开始执行工作空间外的代码] → 三道校验 + 固定参数 + 只接 itemKey + 环回且同源；AGENTS.md 新增例外条款写清范围，越界即 bug。
- [用户同时在终端里跑同一脚本] → 两个进程都整份覆盖同一批文件，最后写的赢；脚本的 zip 先写临时文件再改名，不会留下半个包。不做跨进程锁，接受。
- [推送清单写进另一个仓库，看板 SSE 看不到] → 推送结果只在任务结果行里展示（文件数），不指望自动刷新。
- [服务进程重启丢任务状态] → 与 ingest 相同：任务表在内存，重启后 `idle`；子进程随父进程退出与否不影响脚本幂等性，再点一次即可。
- [旧版同步脚本不写 `sync.json`] → 按钮置灰并提示先在原型工作区跑一次同步；原型工作区脚本升级是本 change 的前置外部依赖。
- [`sync.json` 含本机绝对路径] → 它在用户自己的工作空间里，不进本仓；本仓产物与代码注释只写占位形态。

## Migration Plan

1. 原型工作区同步脚本先加写 `sync.json`（外部，不在本仓）；跑一次同步生成它。
2. 本仓按 tasks 实施；重启 `pnpm dev` 生效。
3. 回滚：前端移除按钮即可；服务端接口保留无副作用（不被调用就不执行）。
