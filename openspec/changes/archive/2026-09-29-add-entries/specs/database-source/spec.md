## MODIFIED Requirements

### Requirement: 数据源靠 input/sources/*.yaml 发现,没配就完全不存在

看板 MUST 通过扫描 `<工作空间根>/input/sources/` 下的 `*.yaml` 来发现数据源,
不做任何自动探测、不猜连接串、不读工作空间的 `.env`。
扫描结果 MUST 作为 `Scan.input` 上的**可选**字段返回。
**该字段的缺省判据是「工作空间没有 `input/sources/` 目录」,不再是「一份 `*.yaml` 都没配」**——
目录存在但还没有任何源时,MUST 返回空数组,使「数据库源」tab 出现在一个空态上,
用户能在那里点到「添加数据库源」。否则第一个源永远加不进来:没源就没 tab,没 tab 就点不到入口。
单份 yaml 解析失败 MUST NOT 影响其它源,也 MUST NOT 让扫描整体失败 ——
坏的那份以「配置读不出来」的形态列出来,让用户看得见。

#### Scenario: 跟数据库无关的工作空间
- **WHEN** 工作空间里没有 `input/sources/` 目录
- **THEN** `GET /api/projects/<id>/scan` 的响应里没有数据源字段
- **AND** 界面上不出现「数据库源」tab,输入资料视图仍是三个 tab

#### Scenario: 模板铺出来、还一个源都没配
- **WHEN** 工作空间有 `input/sources/` 目录,里面只有说明文件和 `example.yaml.txt`
- **THEN** 扫描结果里的数据源字段是空数组
- **AND** 「数据库源」tab 出现,空态里说明还没有数据源,并能点到「添加数据库源」按钮

#### Scenario: 配了一份数据源
- **WHEN** 工作空间里有 `input/sources/warehouse.yaml`,引擎是 PostgreSQL 或 MySQL
- **THEN** 扫描结果里出现这个源,带它的显示名、引擎类型、库名
- **AND** 「数据库源」tab 出现,位置在 待转换 / 已转换 / 图片资料 **之后**

#### Scenario: 配了本轮不支持的引擎
- **WHEN** yaml 里写的引擎不是 PostgreSQL 或 MySQL
- **THEN** 该源以「暂不支持这个引擎」的状态列出来,点采集时给出中文说明
- **AND** 不影响同目录下其它可用的源

#### Scenario: yaml 写坏了
- **WHEN** `input/sources/` 下有一份语法错误的 yaml,和一份正常的
- **THEN** 扫描仍然成功返回,正常那份可用
- **AND** 坏的那份以「配置读不出来」的状态列在 tab 里,标注文件名

#### Scenario: 旧服务进程 + 新前端
- **WHEN** 用户跑着改动前的常驻服务,但浏览器加载了新前端
- **THEN** 前端读不到数据源字段,不显示「数据库源」tab,其余功能不受影响
- **AND** 界面不报错、不白屏

#### Scenario: 新服务进程 + 旧前端
- **WHEN** 服务已经会为空目录返回空数组,浏览器里还是改动前的前端
- **THEN** 旧前端按「没有数据源」处理,tab 不出现,行为与改动前一致

### Requirement: schema 快照是 KB 级摘要,采集不得压垮生产库

采集 MUST 产出 `input/converted/_sources/<源名>/_manifest_<源名>.md`:表清单、每表列名与类型、
可取到的列注释、主外键、行数**量级**、以及受行数上限约束的少量样例行。
行数 MUST 取 `information_schema` 一类的**估算值**,MUST NOT 对业务表执行 `count(*)`。
采集 MUST 只发只读语句,MUST 设置语句超时,MUST 在结束时断开连接 ——
不留常驻连接、不建连接池。
表数量超过阈值时,manifest MUST 退化为"表清单 + 一句话用途",
单表列明细 MUST 拆进 `_sources/<源名>/SplittingObject/<表>.md`,沿用既有的拆分产物约定。

**表数量再上一个量级(几百到上千张)时,那份表清单 MUST NOT 是一张逐表一行的大表格。**
它 MUST 改成按表名前缀分组的紧凑清单:每组一节,给出组名、组内表数,组内每表一行
(表名、列数、有表注释时带上注释),明细链接照旧。表注释 MUST 保留 —— 它是整份快照里
对 AI 最有价值的一列。表名分不出前缀分组时,MUST 退回按首字母分段的单一清单,
MUST NOT 造出大量只含一张表的「组」。
摘要 MUST 保持「一份能整体读进 AI 上下文」的体量,这是它存在的理由。

**PostgreSQL 侧按 schema 白名单过滤时,查询 MUST 对白名单参数做显式数组转型。**
不转型时,PostgreSQL 兼容库(如 KingbaseES)推不出参数类型,**不报错、直接返回 0 行**,
快照会被写成「0 张表」而日志显示成功。
**采到 0 张表 MUST 被当作失败**:MUST NOT 写盘,MUST 保留上一份快照,
MUST 给出「一张表都没读到」的中文说明 —— 与「连不上时保留上一份」是同一条纪律。

#### Scenario: 采集一个中等规模的库
- **WHEN** 对一个几十张表的库跑一次 schema 采集
- **THEN** 生成的 `_manifest_<源名>.md` 体积在 KB 量级,单份可整体读进上下文
- **AND** 采集期间没有对任何业务表执行 `count(*)`

#### Scenario: 表特别多
- **WHEN** 库里的表数超过 manifest 的单份阈值
- **THEN** manifest 里每张表只剩名字和一句话用途
- **AND** 每张表另有一份 `_sources/<源名>/SplittingObject/<表>.md` 记完整列明细
- **AND** 看板把它们按既有拆分产物的形态展示,不平铺成几百个条目

#### Scenario: 上千张表
- **WHEN** 对一个近千张表的库跑一次 schema 采集
- **THEN** manifest 是按表名前缀分组的紧凑清单,不是一张上千行的 Markdown 表格
- **AND** 带表注释的表在清单里仍然能看到注释
- **AND** 每一组给出组名与组内表数,便于按业务模块定位

#### Scenario: 表名没有前缀规律
- **WHEN** 库里的表名分不出有意义的前缀分组
- **THEN** manifest 退回按首字母分段的单一清单
- **AND** 不出现大量只含一张表的分组

#### Scenario: 兼容库上的 schema 白名单
- **WHEN** 对一个 PostgreSQL 兼容库按 `schemas` 白名单采集,而该库确实有表
- **THEN** 采集读到真实的表数,不是 0
- **AND** 同一条查询在原生 PostgreSQL 上行为不变

#### Scenario: 一张表都没读到
- **WHEN** 采集跑完却一张表都没读到(白名单写错、兼容性问题、权限不足)
- **THEN** 采集报失败并说明一张表都没读到、请检查 schema 白名单
- **AND** 上一次成功的快照**原样保留**,不被覆盖成空快照

#### Scenario: 库连不上
- **WHEN** 目标库不可达或凭据失效,用户点「刷新 schema」
- **THEN** 采集在超时内失败,给出中文原因
- **AND** 上一次成功的 schema 快照**原样保留**,不被清空或截断
- **AND** 该源在 tab 里以 orange 标出"需要处理"

## ADDED Requirements

### Requirement: 大库的单表明细不进扫描载荷

拆分了的 schema 快照,其扫描结果 MUST 带一个可选的表数字段(数字)。
表数超过拆分阈值时,扫描结果 MUST NOT 再逐条下发单表明细文件清单 ——
那份数组前端只用来数个数,却会占满整份扫描载荷,而 `input/` 每有一次变动都会经 SSE 重发一遍。
表数不超过阈值时,MUST 照旧下发该清单,使小库行为一字不变。
前端 MUST 优先读表数字段,缺省时回落到清单长度;两者都没有时 MUST 不显示这行副文本,
MUST NOT 报错或白屏。

#### Scenario: 近千张表的源
- **WHEN** 工作空间里有一个近千张表的数据源,`curl` 扫描接口
- **THEN** 响应里带着这个源的表数,但不含逐条的单表明细清单
- **AND** 响应体积不随表数线性膨胀

#### Scenario: 几十张表的源
- **WHEN** 源的表数没超过拆分阈值
- **THEN** 扫描结果与改动前一致,单表明细清单照旧下发

#### Scenario: 界面上的表数
- **WHEN** 用户打开「数据库源」tab
- **THEN** 快照那一行仍然显示「N 张表的明细」,N 与库里的表数一致

#### Scenario: 旧服务进程 + 新前端
- **WHEN** 用户跑着改动前的常驻服务,浏览器加载了新前端
- **THEN** 前端拿不到表数字段,回落到清单长度,显示与改动前一致

#### Scenario: 新服务进程 + 旧前端
- **WHEN** 服务已经不给大库下发单表明细清单,浏览器里还是改动前的前端
- **THEN** 大库的快照那一行少显示「N 张表的明细」这句副文本,其余照常
- **AND** 界面不报错、不白屏
