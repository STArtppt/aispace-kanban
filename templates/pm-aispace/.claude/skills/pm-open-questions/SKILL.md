# 未决问题的入口与出口

问题清单是接手阶段最有价值的产物之一，也是最容易烂掉的一份。
烂掉的方式很固定：**九个技能往里追加，没有一个负责取出**。
两个月就能长成「两百多条、一半标『高』、平均 200 字挤在一个表格单元格里」，
然后被整份放弃。

这个技能是那个缺失的出口。它管四件事：**落一条**、**取出来问**、**关掉**、**体检**。

手写 Markdown 的写法（front-matter 形态、标题层级、文档间链接、哪些语法现在先别用）见工作空间 `AGENTS.md` 的「Markdown 写法」一节，这里不复述。问题字段契约仍以 [`output/questions/README.md`](../../../output/questions/README.md) 为准。

## 先认工作空间的形态

动手前先看一眼 `output/`：

| 看到什么 | 这是什么形态 | 怎么做 |
| --- | --- | --- |
| 有 `output/questions/` 目录 | 新结构，一问一文件 | 照本技能往下做 |
| 只有 `analysis/open-questions.md` | 旧结构，单表格 | 先问用户要不要迁移（见最后一节）。**用户不迁就别擅自迁**，照旧往表格里追加 |
| 两个都有 | 已迁移 | 只动 `output/questions/`。`open-questions.md` 是留着回滚的快照，**不要再往里加行** |
| 只有 `analysis/questions/` 目录 | 迁过、但还在旧位置 | 提议 `git mv output/analysis/questions output/questions`。留在 `analysis/` 下会把分析产物清单淹掉 |

旧工作空间不会因为模板更新就自动获得新结构，这个判断每次都要做。

## 字段契约

**唯一事实源是 [`output/questions/README.md`](../../../output/questions/README.md)。**
下面只是够你干活的摘要，取值和边界以那份为准，有出入按那份走。

```markdown
---
id: Q0134                 # 必填，与文件名一致，四位补零
title: 一句话问题          # 必填。清单只显示它，超过 60 字就该拆条
status: open              # 必填。open / pending_ai / answered / dropped / conflict
blocks: SC-01交底包        # 必填（键）。阻塞哪个在途交付物；不阻塞任何交付物写 backlog
asked_of: 甲方水调         # 必填。该问谁；对内决策写「我方」
source: output/analysis/2026-07-31-测点梳理.md   # 必填。触发这条问题的文档路径
context: 核对第 9 列洪水预报字段时发现            # 触发时在做什么，一句话
created: 2026-09-20
updated: 2026-09-20
human_answer:             # 人写区，你不要动：verify / decide / drop / ask
human_note:               # 人写区，你不要动
due:                      # 人写区，你不要动
evidence:                 # 你写：客户确认 / 资料实证 / 我方决策 / 我方推断
ai_conclusion:            # 你写：结论一句话摘要，展开写正文
ai_source:                # 你写：依据出处路径
flows_to:                 # 你写：这条结论该回流到哪份正文的哪一节
---

## 为什么需要
## 结论
## 人工反馈
## 轮次记录
```

两条硬约束，违反了校验脚本会当场报错：

1. **`evidence: 我方推断` 不能配 `status: answered`。** 查不到依据就停在 `open` 当待验证假设，
   **不要编**。把推断写成结论是这份清单最贵的一种坏法 —— 它会被下游当事实引用。
2. **人写区（`status` / `human_answer` / `human_note` / `due`）你不要动。**
   人在看板上点保存的同时你可能正在改同一个文件，分区让你俩物理上不打架。
   （`status` 在你给出结论时可以改，但不要覆盖人刚填的 `human_answer` 与 `due`。）

## 落一条新问题

别的技能发现待澄清问题时走这一步。**这是入口的唯一形状**，不要自己另发明一套。

1. 取当前最大编号加一：`ls output/questions/Q*.md | tail -1`。
   **目录空不等于从 `Q0001` 开始** —— 整批归档过的工作空间目录就是空的，
   先查历史：`git log --all --name-only --pretty=format: -- 'output/questions' 'output/analysis/questions' | grep -o 'Q[0-9]\{4\}' | sort -u | tail -1`，查不到才从 `Q0001` 起。编号只增不复用，理由见契约。
2. 按上面的骨架写一个文件。`evidence` / `ai_*` 一律留空 —— 问题刚提出来时你还没查证。
3. **`source` 和 `context` 必须填。** 溯源锚点挂在**条目**上，不挂在分节上 ——
   挂在分节上正是存量条目「每条 200 字」的成因：条目找不到自己的上下文，
   只好把上下文抄进自己的单元格里自救。
4. `blocks` 填一个**在途交付物名**。判断不了就写 `backlog`，**不要瞎填一个**：
   错的分组不会被人看见，空的会。

### 双通道：正文归正文，问题归问题

生成分析文档时，**分析结论进文档、延伸出的未决问题进问题文件，两个通道不许互串**：

- 文档正文里**不要**再放一张「待确认问题」表格 —— 那就是旧病复发，
  同一条问题两处存在，很快就会对不上。文档里要提就写一句「见 `questions/Q0134`」。
- 问题条目里**不要**抄分析正文。`title` 一句话，背景写进「## 为什么需要」，
  长推导留在分析文档里用 `source` 指过去。

## 取出来：按 `blocks` 生成会议清单

用户要跟对方对齐时用这个。**按 `blocks` 分组，一次只给一个交付物的几条** ——
跨交付物混在一起，对方和你的注意力都会散掉。

1. 扫 `output/questions/`，读每份的 front-matter。
2. 只取 `human_answer: ask` 且 `status` 不是 `answered` / `dropped` 的（这些是确需对方答复的）。
   用户要更宽的范围就把 `status: open` 的也带上，但**要说清楚哪些是还没定要不要问的**。
3. 按 `blocks` 分组，`backlog` 一组放最后或直接不出。
4. 每组里按 `due` 升序，**没有 `due` 的排最前并标出来** —— 没有最迟答复日期的条目
   不会被任何机制催到期，存量那批积压就是这么来的。

产出落 `output/analysis/<日期>-<对齐对象>对齐清单.md`：

```markdown
# 2026-09-25 与甲方水调对齐清单

> 由 pm-open-questions 从 questions/ 生成。答复后回填到各自的问题文件，不要只改本文件。

## SC-01交底包（3 条，最早到期 2026-10-15）

### Q0134 洪水预报数据何时能从水调系统接入？接口形式是什么？
- 最迟答复：2026-10-15 ｜ 问谁：甲方水调 / 信息化
- 不回答会卡住：原型第 9 列、洪峰影响预估、WR-03 / WR-04 两条预警规则
```

清单是**派生物**，答复回来要回填到问题文件，不是改清单了事。

## 关掉一条

有答案了才关。关之前逐条对下面四项：

| 检查 | 不过关怎么办 |
| --- | --- |
| `evidence` 是四值之一 | 空着就补上 |
| `evidence` 不是 `我方推断` | 是推断就**不能关**，`status` 留 `open` |
| `ai_conclusion` 一句话写清结论 | 长推导写正文「## 结论」，摘要留 front-matter |
| `flows_to` 指出该更新哪份正文的哪一节 | 想不出就说明这条结论没有去处，先别关，问用户 |

`flows_to` 不是可有可无的：**问题关掉了但知识没回流到正文**，是「只有入口没有出口」的另一面 ——
清单干净了，文档还是旧的。看板会专门统计 `flows_to` 空着的已消解条目。

关的时候：`status: answered`，填 `evidence` / `ai_conclusion` / `ai_source` / `flows_to`，
展开结论写进正文「## 结论」。**人写区一个字不动。**

### 消解不等于回答

`dropped`（本期不做 / 不相关）是一个正当的终态，不是失败。
AI 延伸出来的「要不要考虑 X」大量属于这一类 —— 它们不需要问任何人。
没有这条出路，它们就会一直躺着还占着位置。**但 `dropped` 由人来定**，
你只在用户说「这条不做了」时改，不要自己判。

### 再问一轮

结论不满意要重开时：`status` 回 `open`，**上一轮的 `ai_conclusion` 与人工反馈搬到正文
「## 轮次记录」，不要覆盖**。覆盖掉就没法回答「上次为什么这么答」。

## 体检

```bash
python3 scripts/check_questions.py
```

查非法组合（推断关闭问题、已关闭却没凭据）、缺必填字段、`ask` 缺 `due`、取值不在枚举内。
退出码非零就逐条按提示改。**每次批量改完问题文件都跑一遍**，
这个脚本是字段契约唯一能自动执行的那一半。

同类问题会归并打印（刚迁移完会有两百多条同类），`--json` 给程序用，输出逐条不归并。

## 迁移旧表格

工作空间只有 `open-questions.md` 时，问用户要不要迁移。要，就：

```bash
python3 scripts/migrate_questions.py            # 预演，不落盘
python3 scripts/migrate_questions.py --write    # 确认后落盘
```

迁移**只搬运和标记，不推断**：`blocks` 与 `evidence` 一律留空。
自动填出来的凭据本身就是虚假确定性，而这个字段存在的全部意义就是防止它。

落盘后会多一份 `questions/MIGRATION-REVIEW.md` 待人工裁定清单：状态冲突、
疑似不是问题的条目、被截断的标题、分叉编号。**这份清单交给用户过，不要自己裁** ——
「已解决 / 部分解决 / 改写升级为另一条」这些语义机械判定必错。

原 `open-questions.md` 只在开头加一句指向说明，**正文一个字不删**，留着回滚。

### 迁移之后：补 `blocks` 与 `evidence`

刚迁完这两个字段全是空的，两百多条逐个开文件改没人改得完。走工作表：

```bash
python3 scripts/triage_questions.py --plan             # 出 questions/TRIAGE.md
#   —— 用户在表上填 ——
python3 scripts/triage_questions.py --apply            # 预演
python3 scripts/triage_questions.py --apply --write    # 落盘
```

**表要用户填，不是你填。** 你负责的是：解释每一节大概是什么、手头在做的交付物叫什么、
以及把 B 段那些闭包原句念给用户听帮他判。**不要替他把空的凭据填上** ——
这个字段存在的全部意义就是防止「自动填出来的确定性」。

两件事分开，都不用逐条看两百多遍：

- **A 段按分节定 `blocks`**，一节一个交付物名。旧表格的分节本来就是按交付物攒的，
  大半看名字就知道。手头没在做的整片写 `backlog`，**这是决定不是偷懒** ——
  它们搜得到、能拉回来，只是不在主视图占位置。
- **B 段只有已关闭的缺 `evidence`**，当初为什么关的就引在每条下面，一条扫两秒。
  填 `我方推断` 的，落盘时 `status` 会被退回 `open`。

`--apply` 只逐行替换 `blocks` / `evidence`（和被退回的 `status`），
正文与其它字段一个字节不动；已有值的默认跳过，重跑安全。
