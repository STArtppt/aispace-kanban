## Context

「输入资料 → 原始资料」列出 `input/raw/` 下的文件，树由前端按路径拼出来。行上能转换、忽略、打开产物、在文件管理器里显示。没有改名，也没有把文件拖进别的目录。

这些路径被别处拿来对账：

- `input/INDEX.md` 的表格以 `input/raw/…` 为键，产物列链到转换产物；`## 人工批注` 以下是人写的，重跑转换要保住。
- `templates/pm-aispace/scripts/layout.py` 把产物放在 `output/converted/`，目录与 `input/raw/` 同构。单文件用 `single_target`，表格拆分和现场实测数据（一份文件一个库）用 `split_paths`，点表整目录合并用 `merge_paths`。产物 front-matter 的 `source` 写回原件路径，`source_sha256` 记原件摘要，「原件已改」靠它判断（`scan.mjs`）。
- 点表集只认 `input/raw/` 的**直接子目录**：`pointtable.py` 的 `collect_pointtable_dirs` 只看根下一层，`ingest.py` 按 `rel.parts[2]` 记账。点表是逐个文件按格式识别（`is_pointtable`），不是按目录名。
- 转换产物的 Word 成品在 `output/delivery/converted/<子路径>/<基名>.docx`，落点按产物路径镜像（不变量 1 第九条）。
- 文档里抽出的图片在 `input/assets/<安全化的文件名>/`，散图在 `input/assets/未分类/`。链接相对产物所在目录计算。
- `input/.ingestignore` 的模式相对 `input/` 写（如 `raw/批次甲`）。
- 产出文档、问题、复制到产出组的稿子（`copied_from`）里会有指向原件或产物的链接。

产出原稿已经有第十一条：看板 spawn `scripts/rename_output.py`，先预览再执行，用指纹防止预览之后磁盘又变了。那条不碰 `input/` 和 `output/converted/`。

模板写明 `input/raw/` 只读、不改不删。本变更提议的第十三条还没有拍板。未同意前不实现。

## Goals / Non-Goals

**Goals:**

- 在原始资料里重命名文件和目录，并把文件或目录移到 `input/raw/` 下的另一个目录。
- 同一次确认里跟进台账、镜像产物、字面忽略规则，以及解析后指向旧路径的链接。
- 看板不写工作空间。请求不带路径。旧进程、缺脚本、产物还在旧位置时，界面退回今天的样子。

**Non-Goals:**

- 删除、新建空目录、复制、多选、覆盖、移出 `input/raw/`、改原件字节。
- 移动 `input/assets/` 里的文件。
- 为这次整理重跑 `ingest.py`。
- 在转换产物或产出三组上做同样的拖拽。产出改名仍走第十一条。
- 自动改写带通配符的忽略规则。
- 把整理后留下的空目录删掉。

## Decisions

### 1. 一个脚本同时做改名和移动

新增 `templates/pm-aispace/scripts/move_raw.py`。改名是「同一父目录、新基名」，移动是「新父目录、基名不变」。一次调用只做其中一种：两个参数都有或都没有则脚本退出 4。

备选：改名、移动各写一个脚本。拒绝原因：跟进的关联是同一套，两份会漂移。

备选：看板自己 `rename`。拒绝原因：不变量要求这种成套改写走 spawn，看板不留第二套写盘实现。

### 2. 身份用扫描下发的键，不用客户端路径

`scan.mjs` 给每个原始文件可选字段 `organizeKey`（工作空间相对路径的 SHA-256 前 16 位，只在本功能的查找表里用，不能拿去调用产出重命名或转 Word）。另给可选 `rawDirs`：`{ path, organizeKey }[]`，只含「下面至少有一个已列出文件」的目录。`input/raw` 根不进这个数组，请求里用固定值 `root`。

服务端收到键后重扫反查，再 `resolveInside()`，结果必须在 `input/raw/` 之内，且不是 `input/raw` 自己。反查失败 400。

备选：请求带相对路径，服务端再校验。拒绝原因：归档、转 Word、产出改名都明确不接受「带路径但会校验」。目录键多一个数组，旧前端忽略即可。

备选：空目录也下发，让树里出现空文件夹。拒绝原因：本次不做新建目录；空目录只是移走文件后的残留，不值得改树的构成规则。移入目标只可能是根或仍有文件的目录。

### 3. 放下不写盘，确认才写

树形视图里拖到目录行或列表顶部的「放到 input/raw」区域，只打开和菜单「移动到…」相同的预览。预览成功前「确定」不可点。执行时脚本重算计划，指纹不一致退出 3，服务端转 409，磁盘不动。服务端不保存预览。

指纹覆盖：将改名的路径；被移动的原件（移动目录时是其下全部文件，含隐藏文件）的相对路径、大小和 mtime；将改写的文件及处数，以及这些文件的大小和 mtime。这样预览之后原件被改过、目录里新放进或拿走了文件，都会对不上。只改 mtime、内容没变的情况（检出、同步）也会对不上，这是和产出改名相同的代价。

备选：松手就移动，关联在后台补。拒绝原因：写入面宽，而且不变量要求用户明确点下去。桌面文件夹没有「将更新 N 处链接」这一步，这里必须有。

备选：筛选或搜索时也允许拖。拒绝原因：目标目录可能被滤掉，人会拖错。筛选不是「全部」或搜索框非空时，拖动手势关闭；「重命名」「移动到…」仍可用，选择器列出全部目录，不跟随筛选。

### 4. 产物按「现有 source」找，按 layout 算新落点

脚本对每个被移动的原件：

- 从台账行和产物 front-matter 的 `source` 找出属于它的产物（含 `_manifest_*.md` 及其正文目录、整目录合并的摘要和 `MergedObject/`）。
- 新落点调用 `layout.py` 的 `single_target` / `split_paths` / `merge_paths`，不手写镜像规则。
- 新落点已存在且不是该产物自己，整批退出 2。
- 用目录重命名移动原件和产物目录，不读不写原件字节，从而保留 mtime。跨设备导致 `rename` 失败时整批退出 4，不改成复制。

只在产物 front-matter 里改 `source`（以及清单里的 `sources` 项）。相对链接因产物换了目录而用 `layout.rel_path` 重算，包括指向 `input/assets/` 的图片。`input/assets/` 的文件留在原地。`input/assets/未分类/_manifest.md` 里列出的原件路径改成新路径，不移动图片。

新落点的镜像父目录不存在时按需新建，记下本次新建的目录，失败退回时删掉（只删本次新建且仍为空的）。整理后旧位置留下的空镜像目录不删。

原件没有产物（待转、或忽略且从未转过）时，只移动原件并改写对得上的链接和忽略规则。

产物的 Word 成品 `output/delivery/converted/…` 不搬。产物换位置后，看板按新路径算落点，显示「未转 Word」；旧成品留在原处，不删不改名。

备选：把 Word 成品一起搬。拒绝原因：写入面要再扩到 `output/delivery/`，而成品随时能按新路径重新转出来，代价小于多开一块写入面。

备选：移动后调用 `ingest.py` 让它自己重建台账和产物。拒绝原因：内容没变也会重转；`write_index` 会按「源路径还在不在」清行，人工批注虽然有保留逻辑，但没必要让一次改名走完整条转换。

备选：连 `input/assets/<文件名>/` 一起改名。拒绝原因：目录名是安全化之后的结果，和原件基名不是一一对应；别的产物可能链到同一目录。只重算链接。

### 5. 点表集只能在根上原地改名

点表集是 `input/raw/` 的直接子目录，由其中逐个按格式识别出的点表文件决定（见 Context）。按这个规则：

- 点表集目录**重命名**：允许。按 `merge_paths` 把合并摘要与 `MergedObject/` 一起搬到新镜像位置，更新摘要的 `source` / `sources` 和台账里 `input/raw/<名>/` 那一行。
- 点表集目录**移动**到别的目录下：退出 4。移进去之后它不再是直接子目录，下次转换会把新的父级顶层目录整个当成点表集合并，连带卷进别的资料。
- 含点表文件的目录（不论多深）移动后，会让新的顶层目录变成点表集：同样退出 4。判定是「被移动的子树里有 `is_pointtable` 为真的文件，且移动改变了它所属的顶层目录」。
- 点表文件**单个**改名或移动：退出 4，说明请整理整个点表集。
- 判定调用 `ingest.py` 的 `is_pointtable`（它复用 `pointtable.detect`），不另写一套。

现场实测数据是一份文件一个库（`split_paths`），不按目录成套，按普通的一源多产物整理，不在此限。

备选：允许单文件移出，只把清单里的路径改掉。拒绝原因：合并正文仍是按原集合生成的，界面会显示「已转」，内容却和目录对不上。

备选：允许点表集移进子目录，同时改 `pointtable.py` 让它往深处找。拒绝原因：要改点表的成集规则，超出本次范围。

### 6. 关联改写的范围

允许改写的文本：

- `input/INDEX.md`：只改表格里 `source` 对得上的那几行的原件单元格和产物链接。`## 人工批注` 整段保留，其中只改解析后指向旧路径的链接，不改普通句子。
- `input/.ingestignore`：见决策 7。
- 被移动的产物：`source` / `sources`，以及正文里因换目录而失效的相对链接。
- `output/**` 的 `.md` / `.yaml` / `.yml`（含 `output/converted/` 里其他产物、问题、记录、`copied_from`）和根 `project.yaml` / `project.yml`。
- `output/docx-template/**` 里的文本（`profile.json`、`spec.md` 等）：JSON / YAML 只改「整个标量等于旧路径」的值；Markdown 只改解析后的链接。

链接四种写法与第十一条相同：工作空间根路径、镜像前缀、相对链接、wikilink。解析规则与 `src/app/lib/markdownSyntax.ts` 一致。交付稿 `v*.md` 只改 front-matter 里的路径字段，正文不改。

产出三组的原稿因为链接改写而内容变了时，其交付稿里原本对得上的 `source_sha` 换成新摘要，否则看板会误报「原稿已变更」。做法与 `rename_output.py` 的第二轮相同，直接复用。

不改：`input/assets/` 的文件字节、`input/sources/`、`visualization/`、`.claude/`、二进制（含 `.docx`）、记录「## 状态流水」里的历史条目。预览不列出排除范围内的命中。

实现上导入 `rename_output.py` 已有的解析函数。若今日不能导入，抽到 `templates/pm-aispace/scripts/mdlinks.py`，`rename_output.py` 改为调用，对外行为不变，并用现有 `pnpm test:rename` 守住。

备选：复制一份链接解析。拒绝原因：产出改名和原始资料整理会各认各的，同一种链接改出两个结果。

备选：和产出改名一样完全不碰 `output/converted/`。拒绝原因：产物自己的 `source` 和相对链接不改的话，整理之后列表对不上，下次转换会当成新文件。

### 7. 忽略规则只改字面命中的

模式相对 `input/`。`layout.is_ignored` 先做字面前缀匹配（`rel == pat` 或 `rel` 以 `pat + "/"` 开头），再做 glob。分类跟着这个顺序走，**不看规则里有没有 `* ? [`**：

- 字面命中：规则整行等于某个被移动的旧路径，或按路径段是它的前缀。按路径段改前缀：`raw/批次甲` 匹配 `raw/批次甲` 和 `raw/批次甲/说明.docx`，不匹配 `raw/批次甲乙`。看板「忽略」追加的就是这种；文件名里带 `[ ]` 的（如 `raw/资料[终版].docx`）也属于这一类，照样改写。
- 只靠 glob 命中：不改。预览里单列「这些规则含通配符，整理后可能不再套用，脚本不会改」。用户看到之后仍然点「确定」，就按这个结果执行。

改写后的规则只会被字面分支命中，即使新名字里带 `[`，字面分支也先于 glob 生效，不会改变含义。

备选：用现有的 glob 匹配把通配符规则也重写。拒绝原因：一次替换很容易把无关规则改坏，忽略状态会成片翻转。

备选：只要存在可能失效的通配符规则就拒绝整次操作。拒绝原因：人会改用文件夹手挪，链接断得更干净。预览已经把后果写出来了。

### 8. 名字规则比产出改名松

新基名是一层：1 到 200 个 Unicode 码位；不含 `/`、`\` 和空字符；不是 `.` 或 `..`；首尾不是空白或 `.`；不以 `.` 开头（以点开头的文件转换会跳过，改完就从列表消失）。允许空格、中文、`#`、`[`、`]`。与现在的基名相同，或移动到当前父目录，退出 4。

落点已存在退出 2，不覆盖。大小写不敏感的文件系统上只改大小写时，落点和来源是同一个文件（`os.path.samefile`），放行，与 `rename_output.py` 一致。

备选：沿用产出改名对 `# [ ]` 的禁止。拒绝原因：原始文件名本来就带这些字符，整理时反而改不回去。

### 9. 失败怎么退回

分三段，能保证的程度不同：

1. **暂存**：要改的文本写成临时文件，放在各自当前目录里，后面目录改名时跟着走。写失败就删掉已写的临时文件，磁盘没有变化。
2. **改名**：按需新建镜像父目录，再依次改名原件、镜像目录、`SplittingObject/<名>/`、`MergedObject/` 所在目录等。任一步失败：已改的名字倒序改回，删掉本次新建且仍为空的目录，删掉临时文件。改回也失败的路径如实列出。
3. **替换**：把临时文件原子替换到最终位置。到这一步改名都已完成，个别文件替换失败时**不再回滚**（再改一次名只会更乱），如实列出哪些文件里的链接没更新。这和 `rename_output.py` 的 `apply` 相同。

`rename_output.py` 的 `do_renames` 只跟踪一个镜像目录下临时文件的去向。这次一次会改好几个目录，要改成「按改名列表逐个换算临时文件路径」。若改成通用函数，抽到 `mdlinks.py` 一起复用，并用 `pnpm test:rename` 守住。

不删除用户的文件。进程在中途被杀掉时，可能留下临时文件或停在半途，这和第十一条相同，脚本不另做崩溃恢复日志。

符号链接不整理，退出 4。

### 10. 接口与降级

`POST /api/projects/:id/raw-organize/preview` 与 `POST /api/projects/:id/raw-organize`。都要求环回且非跨站。请求体只有 `key`，外加 `name` 或 `destKey` 其中一个。`destKey` 为 `root` 或某个目录键。

spawn 时服务端把自己反查到的相对路径传给脚本。脚本再校验一次必须在 `input/raw/` 内。超时与产出改名相同，超时 504。退出码：2 → 409，3 → 409，4 → 400，脚本的中文说明原样返回。

`layout.ensure_layout()` 会拒绝时（产物仍在 `input/converted/`），不 spawn，400，说明先迁移。

scan 可选字段：

- `canOrganizeRaw: boolean`，脚本存在且产物不在旧位置时为 true。
- `organizeRawBlock`: `"no-script"` 或 `"legacy-converted"`，仅在不能整理时出现。

前端：

- 字段缺失：菜单置灰，提示重启看板服务，不启用拖放。
- `false` 且 `no-script`：提示更新模板。
- `false` 且 `legacy-converted`：提示先把转换产物迁到 `output/converted/`。
- 工作空间目录丢失：置灰，提示重新关联。

树的拖放做成 `FileTree` 的可选回调。产出清单和转换产物不传回调，行为与现在相同。

成功响应带旧路径到新路径的对照。前端据此改收藏置顶和当前打开的条目。原件与被搬走的产物都要跟。

备选：缺字段时隐藏菜单。拒绝原因：新旧进程混跑时，人看不出是版本问题还是没有这个功能。置灰并写原因，和产出改名一致。

### 11. 模板里的只读说法

`templates/pm-aispace/AGENTS.md` 改为：原件内容不改、不删；改名和移动目录只走看板或 `scripts/move_raw.py`，不要在文件夹里手改，智能体也不要手改路径。这条随模板发出去。

模板里说 `input/raw/` 只读的有两处，都要改：目录表那一行（「只读，永不改动删除」）和后面权限表那一行（「不碰 / 原件只读」）。

## Risks / Trade-offs

- [通配符忽略规则整理后不再套用，大量文件重新变成待转] → 预览单列这些规则，脚本不猜怎么改。字面规则按路径段改写。
- [链接解析改到不该改的句子] → 只改解析成功的链接和「整段标量等于旧路径」的字段，不按子串替换。交付稿正文不动。
- [`safe_component` 后的新产物路径与已有文件相撞] → 整批 409，不覆盖。
- [点表识别和 `ingest.py` 以后分叉] → 脚本调用同一函数，不复制判断。
- [点表成集规则以后放宽到深层目录] → 决策 5 的拒绝条件要跟着改；回归里有「点表集不能移进子目录」一条，规则一变就会红。
- [产物搬走后 Word 成品显示「未转 Word」，旧成品成了孤儿] → 已接受，见决策 4。
- [替换阶段个别文件失败] → 不回滚，如实列出没更新的文件，见决策 9。
- [拖放只在树形、且未筛选时可用] → 平铺列表和筛选状态下用「移动到…」，目标是全部目录。
- [杀进程会停在半途] → 与产出改名相同，不新增恢复日志。正常失败路径会退回。
- [已整理过的工作空间，把看板版本退回去也不会把文件移回] → 迁移说明里写明。回滚的是功能，不是某次整理。

## Migration Plan

1. 拍板第十三条之前不改代码。
2. 拍板后先落地脚本和 `pnpm test:raw-move`，再接服务端和前端。
3. 已有工作空间没有脚本时界面置灰，更新模板后出现。不自动整理历史路径。
4. 撤回本功能：去掉入口和脚本即可。已经移动过的文件保持新路径。
