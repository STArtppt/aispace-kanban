# output/delivery/ —— 去 AI 味后的交付稿

原稿（`output/analysis/`、`output/docs/`、`output/decisions/` 下 AI 起草的 `.md`）去掉「AI 味」之后的版本放这里，
逐版保存。怎么去味、怎么按批注改、规则库怎么沉淀，见技能 `pm-deai-writing`（`.claude/skills/pm-deai-writing/SKILL.md`）。

## 落点：镜像原稿路径，一版一个文件

```
output/docs/方案/总体设计.md                      ← 原稿，一个字节都不动
output/delivery/docs/方案/总体设计/v001.md        ← 第一版交付稿（去味）
output/delivery/docs/方案/总体设计/v002.md        ← 按 v001 上的批注改出来的下一版
```

- 目录 = 原稿在 `output/` 下的相对路径去掉 `.md`；文件名 `v<三位序号>.md`，序号取已有最大序号加一，**不覆盖已有版本**。
- **每一版写出后不再改动。** 要改就出下一版；看板上「与上一版对比」看到的就是这一轮改了什么。
- **改交付稿走批注**：在看板阅读器里打开原稿，版本条切到那一版，进入批注模式写批注、复制提示词给 AI。
  批注落在原稿那份记录的批注文件里（`output/records/notes/I<编号>.md`），批次注明针对哪一版。
  直接改文件看板会标「被直接改过」，而且这些改动不会沉淀成规则。
- 转 Word 时选**交付稿**（阅读器版本条上的「转成 Word」），成品落在交付稿旁边（`v002.docx`），原稿目录不动。
- 这个目录不进看板的产出列表、全局搜索和完整度统计，只从原稿的阅读器版本条进入。

## front-matter（必填，扁平）

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `source` | 原稿的工作空间相对路径 | `output/docs/方案/总体设计.md` |
| `source_sha` | 原稿全文的 SHA-256 前 16 位（换行先规范成 `\n`） | `3f2a9c0d1e4b5a67` |
| `version` | 本版序号 | `v002` |
| `based_on` | 由哪一版修订而来；去味首版写 `source` | `v001` |
| `notes` | 本版处理的批注编号，去味首版留空 | `N0004, N0005` |
| `rules_version` | 改写时规则库的版本 | `4` |
| `created` | 写出日期 | `2026-10-08` |
| `body_sha` | 写出时正文（front-matter 之后）的 SHA-256 前 16 位 | `9b8c7d6e5f4a3b2c` |
| `hits` | 各规则命中次数，一行字符串 | `R001×13, R004×40` |
| `note` | 一句话说明本版重点 | `按批注删掉段尾总结` |

看板用 `source_sha` 判断「原稿已更新」（原稿在这一版之后又改过），用 `body_sha` 判断「被直接改过」。
两个摘要的算法写在技能里，与看板一致。

## 事实不变

交付稿的数字、日期、专有名词、表格数据必须与原稿一致，只改说法；删掉的依据引用集中到文末「编制依据」一节。
