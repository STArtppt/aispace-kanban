## ADDED Requirements

### Requirement: 一次归档把产出物移进组内的归档目录

一次归档 SHALL 把一份产出物从 `output/<组>/` 移进 `output/<组>/一次归档/`,
`<组>` 是 `analysis` / `docs` / `decisions` 三者之一。

归档目录 MUST 在各组**内部**,MUST NOT 放在 `output/` 根上、也 MUST NOT 移出 `output/`:
组内的位置让递归扫描照常收得到它(可达性不降),也保住了「这份原本属于哪一组」这个信息 ——
被取代的交付文档与过时的中间产物在二次归档时是完全不同的两堆。

归档目录不存在时由脚本建立。

#### Scenario: 归档一份交付文档

- **WHEN** 用户在 `output/docs/` 的列表行里点「归档」
- **THEN** 该文件被移到 `output/docs/一次归档/` 下,文件名不变
- **AND** `output/analysis/`、`output/decisions/`、`input/`、`project.yaml` 一个字节都没变

#### Scenario: 归档目录还不存在

- **WHEN** 某一组第一次归档
- **THEN** `output/<组>/一次归档/` 被建立,并同时生成它的 `README.md` 交接单

### Requirement: 归档只移动,不删除、不覆盖

归档 MUST 只做移动。MUST NOT 删除任何文件 —— 别处的会议纪要、决策记录可能正写着
「见某某文档」,与 `questions/` 的「关闭的问题保留文件、编号只增不减」同一条理由。

落点已经有同名文件时 MUST NOT 覆盖:加日期后缀另存,两份在目录里分得清。

#### Scenario: 落点已有同名文件

- **WHEN** `output/docs/一次归档/` 下已经有一份同名文件,又归档了一份同名的
- **THEN** 新归档的那份带上日期后缀存进去,原有那份一个字节都没变

#### Scenario: 归档不改内容

- **WHEN** 一份产出物被归档
- **THEN** 它的内容逐字节不变,只有路径变了

### Requirement: 看板只 spawn,写盘的是工作空间脚本

真正移动文件与维护 README 的 MUST 是工作空间自己的 `scripts/archive_output.py`。
看板 MUST 只 `spawn` 它,自己 MUST NOT `write` / `rename` / `unlink` 任何一个字节 ——
与资料转换、原型刷新、参考收件箱同构。

工作空间没有这个脚本时,接口 MUST 返回 400 并说清怎么办
(用模板新建的工作空间自带脚本;自己建的目录需要自己装脚本,或在终端里自己移),
MUST NOT 退化成「看板替你移一下」。

#### Scenario: 老工作空间没有归档脚本

- **WHEN** 用户在一个没有 `scripts/archive_output.py` 的工作空间里触发归档
- **THEN** 接口返回 400 并说清原因与出路,工作空间里没有任何文件被移动或创建

#### Scenario: 脚本自己退出非零

- **WHEN** 脚本运行失败(权限、目标被占用等)
- **THEN** 接口如实返回脚本的错误输出,界面照原文说明,MUST NOT 只给一句「归档失败」

### Requirement: 归档的写入面边界

归档 MUST 满足下列全部约束,越界即为 bug:

- 看板只 `spawn`,自己不写、不 `rename`、不 `unlink` 任何一个字节;
- 必须用户在列表行点「归档」明确发起,MUST NOT 有后台自动跑、定时任务,
  MUST NOT 按状态自动归档(`superseded` 不等于该移走 —— 那是人的判断);
- 必须环回(`allowMutations`)且非跨站(`rejectIfForeignOrigin`),否则 403;
- 请求**只带组名与文件名,不接受任何路径**:组名必须是三个组名之一,
  文件名里出现路径分隔符、`..` 或任何目录成分一律 400;落点由脚本自己算;
- 脚本只允许在 `output/<三个组名>/一次归档/` 下写;
  `input/`、`project.yaml`、`visualization/`、`output/records/`、`output/questions/`
  以及三个组根目录下的其它文件仍然只读;
- 脚本**只移动与追加 README**,MUST NOT 删除任何文件。

#### Scenario: 请求里带路径

- **WHEN** 请求的文件名是 `../../etc/passwd` 或 `子目录/某文件.md`
- **THEN** 接口返回 400,脚本根本没有被起起来,工作空间里没有任何变化

#### Scenario: 组名不在三者之内

- **WHEN** 请求的组名是 `questions` 或 `records`
- **THEN** 接口返回 400,MUST NOT 去移动那两个目录里的任何东西

#### Scenario: 非环回监听

- **WHEN** 服务用 `--host` 起在局域网地址上,收到归档请求
- **THEN** 接口返回 403,工作空间里没有任何变化

#### Scenario: 跨站请求

- **WHEN** 一个外站页面向本机服务发起归档
- **THEN** 接口返回 403,工作空间里没有任何变化

### Requirement: 本轮只归档组根目录下的文件

本轮 MUST 只支持归档 `output/<组>/` **根目录下**的文件。
组内子目录里的文件 MUST NOT 可归档,入口 MUST 置灰并说清理由 ——
这是「请求不接受任何路径」换来的代价,把它明说出来,而不是让用户点了没反应。

已经在 `一次归档/` 下的文件 MUST NOT 再次可归档。

#### Scenario: 子目录里的产出物

- **WHEN** 用户打开一份在 `output/analysis/某子目录/` 下的文档的「更多」菜单
- **THEN** 「归档」这一项不可点,并说明本轮只支持归档组根目录下的文件

#### Scenario: 已归档的文件

- **WHEN** 用户打开一份已经在 `一次归档/` 下的文档的「更多」菜单
- **THEN** 「归档」这一项不可点

### Requirement: 一次归档目录下有一份 README 交接单

`output/<组>/一次归档/README.md` MUST 由归档脚本维护,它是看板与工作空间 AI 之间的
**异步交接单** —— 看板不能调 AI,所以交接靠一份冷启动的 agent 也能独立读懂的文件。

它 MUST 包含两块:

- **已归档清单**:每归档一份追加一行,写明日期、原路径、新路径、一句话来由。
  清单 MUST 用一对标记包住,脚本 MUST 只在标记之间追加,MUST NOT 重写整份文件 ——
  这份文件人和 agent 也会改。
- **二次归档提示词**:说清要做什么、产出是什么形态。
  它 MUST 只在文件不存在时写一次,之后脚本 MUST NOT 再覆盖它 ——
  用户按自己语境改过的提示词,不该被下一次归档改回去。

#### Scenario: 第一次归档生成 README

- **WHEN** 某一组第一次归档
- **THEN** `一次归档/README.md` 被创建,包含已归档清单(一行)与二次归档提示词

#### Scenario: 第二次归档只追加一行

- **WHEN** 同一组又归档了一份
- **THEN** 清单标记之间多出一行,提示词那一段与用户手改过的任何内容逐字不变

#### Scenario: 用户改过提示词

- **WHEN** 用户按自己的语境改写了 README 里的提示词,之后又归档了一份
- **THEN** 改写后的提示词原样保留

### Requirement: 二次归档的产出是分堆加短索引

二次归档 SHALL 把一次归档的内容按主题或阶段分堆:`output/<组>/一次归档/<主题短名>/`,
每堆一份 `INDEX.md`。

`INDEX.md` MUST 回答三件事:**这堆是什么、当初为什么产生、什么情况下需要回来翻**,
篇幅在几百字量级。目的是让人和 AI 用一份短索引代替翻几十份文档,
把读取成本降下来 —— **而不是禁止读**。

#### Scenario: 把一次归档分成三堆

- **WHEN** 工作空间 AI 按 README 里的提示词处理 `output/analysis/一次归档/`
- **THEN** 归档项被移进若干个主题子目录,每个子目录下有一份 `INDEX.md`
- **AND** 没有任何文件被删除

#### Scenario: 短索引说清什么时候回来翻

- **WHEN** 读一份 `INDEX.md`
- **THEN** 它说清这堆是什么、当初为什么产生、什么情况下需要回来翻

### Requirement: 不产出任何「始终无需再读」的清单

二次归档 MUST NOT 产出任何形式的「始终无需再读」「可以跳过」清单,
MUST NOT 往工作空间的 `AGENTS.md`、技能或任何会影响后续会话行为面的地方写跳过规则。
README 里的提示词 MUST 把这一条明写出来。

理由:那是 AI 的单向判断、会判错,而错一条的代价是某份资料从此没人再看。
归档要降低的是**读取频率与成本**,不是**可达性**。

#### Scenario: 提示词里明写禁止

- **WHEN** 读 `一次归档/README.md` 里的二次归档提示词
- **THEN** 它明确写着不得产出「无需再读」清单、不得往 AGENTS.md 或技能里写跳过规则

#### Scenario: 归档后仍然可被读取

- **WHEN** 工作空间的 agent 需要查一份已归档的文档
- **THEN** 它照常能搜到、能读到,没有任何规则告诉它不要读

### Requirement: 归档后可达性不降

归档后的一切 MUST 仍然可搜索、可预览、可被 AI 按需读取。
归档项 MUST 仍然计入溯源反链(`attachReferences`)——
一份资料确实被那篇文档引用过,把它移进 `一次归档/` 不会让这件事变成没发生。

#### Scenario: 搜索能搜到归档项

- **WHEN** 用户在产出视图里搜一份已归档文档的标题
- **THEN** 它出现在结果里(在已归档那一侧),点开能预览

#### Scenario: 归档不改变反链计数

- **WHEN** 一份 `input/converted/` 的资料只被某份产出物引用,而那份产出物被归档了
- **THEN** 这份资料 MUST 仍然显示为「被 1 篇产出引用」,MUST NOT 退回「还没有产出引用它」
