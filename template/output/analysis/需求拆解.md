## 电站三维建模

### R-建模-001 基础地理场景数据采集与入库

- **谁**：三维数据工程师
- **要做什么**：采集并入库 DEM、DOM、倾斜摄影模型、矢量地理数据，形成基础地理场景
- **为什么**：基础地理模型是整个三维场景的底座，没有它其余功能无处安放（来源：§1.1 基础地理模型）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §1.1 基础地理模型
- **优先级**：P0（必须有）——全部功能的前置
- **依赖**：无
- **验收标准**：
  1. 四类地理数据齐备：DEM、DOM、倾斜摄影模型、矢量地理数据集，覆盖全部在建场站
  2. DOM 采用 GeoTIFF（带坐标的 tif）格式；倾斜摄影产出 OSGB / OBJ / FBX / STL 之一
  3. 矢量数据采用 SHP，至少含 `.shp` / `.shx` / `.dbf` 三个文件，坐标系文件 `.prj` 齐备
  4. 全部地理数据存入基于关系数据库系统的空间数据引擎统一管理，**不单独建属性表与索引表**
  5. 每个场站的地理数据可独立更新，单站重采不影响其他站的场景可用性
- **未决**：`⛔ 阻塞于 Q6` ——航拍与遥感成果的测绘资质、涉密审查、存储要求未定，
  验收标准需在合规要求明确后补充留存与保密条款。另：采集作业是否含在本项目范围内（→ Q11）

### R-建模-002 电力设施与建筑三维实体模型建模

- **谁**：三维建模工程师
- **要做什么**：按分级标准建立建筑模型与电力设施模型，达到约定的精度档位
- **为什么**：设备模型是「点模型看数据」这条主线的载体（来源：§1.2 三维实体模型）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §1.2 三维实体模型
- **优先级**：P0（必须有）
- **依赖**：R-建模-001
- **验收标准**：
  1. 电力设施模型覆盖资料列出的全部对象：光伏发电板、集中式逆变器、组串式逆变器、电表、
     环境监测仪、交流汇流箱、直流汇流箱、箱变、组件、支架、升压站、断路器、主变、中控室
  2. 发电设施采用体模型，根据实测尺寸与外业纹理精细建模，**高度精度小于模型自身高度的 10%**
  3. 建筑模型按约定档位交付，精度满足：体块模型平面约 2m / 高度约 3m（高层可放宽至 5m）；
     标准模型约 1.5m；精细模型约 1m
  4. 纹理贴图细节清晰，能真实反映各部位几何特征、样式、高度、分布、位置、质地、色彩
  5. 取舍掉的细部结构须以纹理辅助表现，不得直接缺失
  6. `⛔ 阻塞于 Q4` ——**各类模型分别交付到哪一档 LOD 未定**，且「1:1 镜像还原」与精度表
     互斥，验收口径确定后本条才能形成可执行的验收条款
- **未决**：抽检方式（抽多少、怎么量、谁量）？返工判定标准？`[空白]`（→ Q21）

### R-建模-003 模型与设备的 KKS 编码关联

- **谁**：三维数据工程师、生产技术人员
- **要做什么**：用 KKS 标识编码建立三维模型与设备业务数据之间的唯一映射
- **为什么**：三维场景里所有数据访问都要通过点击模型实现，没有唯一标识就点不出数据（来源：§1.2 设备与模型关联设计）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §1.2 设备与模型关联设计
- **优先级**：P0（必须有）——运行可视化全部功能的前置
- **依赖**：R-建模-002
- **验收标准**：
  1. 每个可交互的三维模型对应唯一一条 KKS 编码，不重不漏
  2. 编码符合《GB/T 50549-2010 电站标识系统编码标准》与
     《QSPI 9720-2016 光伏发电站标识系统（KKS）编码规范》
  3. 模型属性数据与设备业务数据通过该编码关联，关联结果可查询、可校验
  4. 存在未关联模型或未关联设备时，系统提供差异清单，不得静默忽略
  5. `⛔ 阻塞于 Q8` ——正文引用的「附录 D 模型编码规范」资料未附；
     既有电站是否已有 KKS 编码库、编到哪一级（是否到组串）未知
- **未决**：编码库由谁维护？新增设备的编码如何生成与下发？`[空白]`

### R-建模-004 绿化与其他类模型建模

- **谁**：三维建模工程师
- **要做什么**：建立绿化模型与其他类模型，按档位达到精度要求
- **为什么**：场景真实感的组成部分，但不承载业务数据
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §1.2 三维实体模型（绿化模型、其他模型）
- **优先级**：P2（可以有）——不影响业务功能，可在主线稳定后补齐
- **依赖**：R-建模-001
- **验收标准**：
  1. 绿化基础模型采用单面片 / 十字面片 / 多面片形式，树木高度与实际误差在 5m 以内
  2. 绿化标准模型与精细模型参考现场照片反映形态、高度、分布、位置、种类及色彩
  3. 其他类基础模型高度精度小于模型自身高度的 20%；体模型小于 10%
  4. 绿化模型以行道树和景观树为主
- **未决**：同 R-建模-002，档位对应关系待 Q4 确定

## 三维可视化

### R-可视-001 三维场景分层加载与基本操作

- **谁**：运营管理人员、运维作业人员
- **要做什么**：在浏览器里按层级加载并浏览电站三维场景
- **为什么**：场景是整个系统的容器，为实时监控、设备定位等功能提供虚拟环境（来源：§2.1 三维可视化）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.1 三维可视化
- **优先级**：P0（必须有）
- **依赖**：R-建模-002
- **验收标准**：
  1. 基于 WebGL 的 3D 引擎，在主流浏览器中直接展示 3D 场景与模型，不装插件
  2. 按 **区域中心 → 电站 → 分区 → 子阵 → 设备** 五级分层加载，逐级下钻
  3. 支持各类资源图层的加载与管理，图层可独立开关
  4. 提供放大、缩小、平移三项基本操作
  5. 站内常规设备提供精细化模型的渲染展示
  6. 加载过程中给出进度反馈；某一层级数据缺失时显式提示缺哪一层，不静默留空
- **未决**：`⛔ 阻塞于 Q2` ——首屏加载时间、渲染帧率、支持的并发在线人数全部未定义，
  验收标准 1–5 目前只有功能性、没有性能性条款

### R-可视-002 场景效果动态变换

- **谁**：运营管理人员
- **要做什么**：模拟并切换昼夜场景与天气场景效果
- **为什么**：让虚拟场景与实际场地情况一致（来源：§2.1 场景效果动态变换）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.1 三维可视化 · 场景效果动态变换
- **优先级**：P2（可以有）——观感增强，不影响业务判断
- **依赖**：R-可视-001
- **验收标准**：
  1. 支持昼夜场景效果模拟与实时切换
  2. 支持天气场景效果模拟与实时切换
  3. 切换过程不中断场景中的实时数据展示
- **未决**：`⛔ 阻塞于 Q13` ——天气是接真实气象数据自动切换还是仅手动切换？
  前者需新增气象数据源接口，工作量差一个数量级

### R-可视-003 飞行视角巡视

- **谁**：运营管理人员、运维班组长
- **要做什么**：按定制飞行路线，以上帝视角或第一视角自动巡视电站
- **为什么**：替代人到现场的全站巡视，实现在线动态巡视（来源：§2.3 飞行视角模拟）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.3 飞行视角模拟
- **优先级**：P1（应该有）
- **依赖**：R-可视-001
- **验收标准**：
  1. 支持上帝视角与第一视角两种飞行浏览方式
  2. 飞行路线可定制，可覆盖电站、分区、子阵各层级
  3. 巡视过程中可查看途经分区、子阵下的设备运行状态
  4. 支持随时开启和关闭飞行浏览，关闭后停留在当前视角，不跳回初始位置
- **未决**：巡视结果是否要形成巡视记录 / 报告？资料只写「在线巡视」，未提产物 `[空白]`

### R-可视-004 能量流向模拟

- **谁**：运营管理人员
- **要做什么**：在场景中模拟从光伏区到升压站的能量流动效果
- **为什么**：直观感受电站当前的生产运行状态（来源：§2.4 能量流向模拟）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.4 能量流向模拟
- **优先级**：P1（应该有）
- **依赖**：R-可视-001、R-运行-002（流动效果需实时功率驱动）
- **验收标准**：
  1. 集电线杆塔与场内输电线路按 1:1 还原并在场景中可见
  2. 能量流动效果覆盖「光伏区 → 升压站」全链路
  3. 流动效果由实时数据驱动，出力为零时不得仍显示流动
- **未决**：流动速度 / 粗细是否要映射实际功率大小？映射规则由谁定？`[空白]`
  另：风电场的能量流向如何表达，正文未涉及（→ Q3）

### R-可视-005 告警状态模型着色

- **谁**：运维值班人员
- **要做什么**：把设备实时告警映射到对应三维模型，以变色方式提醒
- **为什么**：在场景里一眼看出哪里出了问题，缩短定位时间（来源：§2.6 设备实时告警映射）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.6 设备实时告警会映射到对应模型
- **优先级**：P1（应该有）——有替代手段（在原监控系统看告警列表）
- **依赖**：R-建模-003、R-运行-002
- **验收标准**：
  1. 着色粒度支持到**组串级**
  2. 提供数字孪生配置界面，可为不同级别、不同类型的告警分别设置模型渲染颜色
  3. 告警恢复后模型颜色自动复原，不需要人工清除
  4. 同一模型同时命中多条告警时，按级别取最高级着色，并在悬停提示中列出全部告警
  5. **颜色不作为唯一区分手段**：模型旁需同时给出文字标识，避免色觉障碍与大屏色偏下漏判
- **未决**：`⛔ 阻塞于 Q15` ——上游告警从哪个系统来、级别如何定义、映射规则谁配置，均未说明。
  验收标准 5 是我方提出的可访问性建议，资料未涉及，需甲方确认

## 运行可视化

### R-运行-001 设备属性查看

- **谁**：运营管理人员
- **要做什么**：点击场景中的设备模型，弹窗展示该设备的最新详情信息
- **为什么**：把设备台账信息带进三维场景，免去在多个系统间来回切换（来源：§2.2 运行可视化）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.2 运行可视化 · 设备属性查看
- **优先级**：P0（必须有）——「点模型看数据」是数字孪生的核心交互
- **依赖**：R-建模-003、R-集成-001（生产运行智能管理系统接口，⛔ 阻塞于 Q9）
- **验收标准**：
  1. 点击设备模型弹出详情窗，至少展示：KKS 编码、设备名称、设备类型、厂商名称、
     安装日期、运行日期、接入状态
  2. 弹窗中同时展示该设备的维护记录与维护人员
  3. 数据取自生产运行智能管理系统，展示时标注数据更新时间
  4. 设备未接入或无台账数据时显式提示「未接入 / 无数据」，不得展示空白弹窗
- **未决**：维护记录展示多少条、按什么排序？设备台账的权威源是哪个系统？`[空白]`（→ Q9）

### R-运行-002 组串级实时数据查看

- **谁**：运维值班人员
- **要做什么**：查看设备实时监控数据明细，最小可下钻到组串
- **为什么**：实时掌握设备运行情况是运行可视化的核心诉求（来源：§2.2 设备实时数据查看）
- **来源**：`新能源场站数字孪生集成平台方案建议书.md` §2.2 运行可视化 · 设备实时数据查看
- **优先级**：P0（必须有）
- **依赖**：R-运行-001
- **验收标准**：
  1. 实时数据可查看的最小单元为**组串**
  2. 至少展示设备状态与电气量明细（有功功率、无功功率、功率因数、电网频率等），
     具体数据项以生产运行智能管理系统实际提供的为准
  3. 数据带时间戳；超过约定时限未更新时显式标注「数据过期」，不得沿用旧值伪装成实时
  4. 数据源不可达时明确提示故障，区分「数据源故障」与「查询故障」
- **未决**：`⛔ 阻塞于 Q2` 刷新周期未定；`⛔ 阻塞于 Q16` 组串总量未知，
  直接决定数据量与查询性能设计
