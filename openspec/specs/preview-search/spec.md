# preview-search

## Purpose

在预览窗内容区左上角提供悬浮的整份内容检索入口。markdown / 摘要 / 校验说明 / 纯文本对**已经读进内存的这一份正文**做本地模糊搜索;表格「数据」页与单份 csv/tsv 走服务端整表扫描(见 `table-scan-search`)。检索只针对当前这一份内容,不跨文件;本地路径不发起网络请求。高亮不改动正文 DOM(批注锚点依赖正文结构,结构一变批注位置就错)。入口与本地检索由 `reader-content-search` 落地,表格整表检索由 `table-full-scan-search` 改写,
xlsx/xlsm 表格预览与代码类高亮预览的可搜性由 `preview-code-xlsx` 补齐。

## Requirements

### Requirement: 搜索入口只在"此刻有文字可搜"时出现

预览内容区左上角 MUST 悬浮一颗搜索图标按钮,不随正文滚动,MUST NOT 放进标题栏。
收起态是一颗方钮(圆角边框、实底、搜索图标);点开后输入框向右展开。

按钮的左缘 MUST 与预览顶栏标题左缘对齐;顶缘 MUST 与左侧清单标题行
(「产出列表」/「输入列表」)垂直居中。表格转换包带「摘要 / 数据」tab 时,
按钮 MUST 下移到 tab 条下方,仍贴该内容区左上角。

这颗按钮 MUST 只在预览窗当前正在渲染**可读文本**时出现,即下列情形:

- markdown 正文;
- 表格包的「摘要」页(摘要已读到)与「数据」页;
- 单份 csv/tsv 表格预览(含分析中间产物里的纯 csv);
- 单份 xlsx/xlsm 表格预览(当前选中的那一张 sheet);
- HTML 原型停在「校验说明」页且说明已读到;
- 纯文本预览,以及按语言高亮的代码类文本(yaml / json / xml / sql / py 等)。

表格「数据」页、单份 csv/tsv 与单份 xlsx/xlsm 的检索范围 MUST 是**整张表**
(xlsx 即当前 sheet),由服务端扫描完成(见 `table-scan-search`)。
看板 MUST NOT 为了检索把整张表拉进浏览器 ——
浏览器里仍然只有当前这一页的行。多表转换包以及多 sheet 工作簿里,
检索范围 MUST 是**当前选中的那张表**,MUST NOT 跨到同一份里的其他表。
整表检索不可用时(旧服务进程返回 404),MUST 退回只搜当前已经画出来的这一页,
并在结果区如实说明。

其余情形 MUST NOT 出现这颗按钮:HTML 原型的「预览」页(内容在隔离的 iframe 里,
看板读不到)、图片、图库、不渲染的原始格式文档、以及正文还在读取或读取失败时。

#### Scenario: markdown 正文有入口
- **WHEN** 预览窗打开一份 markdown 产物且正文已渲染
- **THEN** 内容区左上角出现搜索图标按钮,不随正文滚动
- **AND** 标题栏仍只显示标题、路径与右侧功能键,过长时标题与路径照旧截断

#### Scenario: 表格包切到数据页仍可搜
- **WHEN** 预览窗打开一个多表的转换包并停在「摘要」页
- **THEN** 搜索按钮出现在 tab 条下方的内容区左上角
- **WHEN** 切到「数据」页
- **THEN** 搜索按钮仍在,检索范围是当前选中那张表的**全表**,不只是当前这一页

#### Scenario: 多表包里不跨表搜
- **WHEN** 一个转换包里有多张表,当前选中的是其中一张
- **AND** 关键词只出现在另一张表里
- **THEN** 结果为空,并说明检索只覆盖当前这张表

#### Scenario: 分析中间产物的纯 csv 可搜
- **WHEN** 预览窗打开一份 csv/tsv 表格
- **THEN** 内容区左上角出现搜索按钮
- **AND** 检索范围是整张表,命中可以落在尚未翻到的页上

#### Scenario: xlsx 当前 sheet 可搜
- **WHEN** 预览窗打开一份 xlsx,当前停在其中一张 sheet
- **THEN** 内容区左上角出现搜索按钮
- **AND** 检索范围是这张 sheet 的全表,不是工作簿里的其他 sheet

#### Scenario: yaml 高亮预览可搜
- **WHEN** 预览窗打开一份已按 yaml 高亮的文件且正文已渲染
- **THEN** 内容区左上角出现搜索按钮
- **AND** 检索按行匹配,不发网络请求

#### Scenario: HTML 原型的预览页没有入口
- **WHEN** 预览窗打开一份 HTML 原型并停在「预览」页
- **THEN** 没有搜索按钮
- **WHEN** 切到「校验说明」页且说明已读到
- **THEN** 搜索按钮出现在内容区左上角

#### Scenario: 正文还没读到时没有入口
- **WHEN** 预览窗正显示「读取中…」或读取失败的提示
- **THEN** 没有搜索按钮
- **WHEN** 正文读取成功并渲染完成
- **THEN** 搜索按钮出现

### Requirement: 搜索条的开合与状态重置

点击搜索按钮 MUST 把输入框向右侧展开并把焦点落到输入框;展开用 CSS width
transition,MUST NOT 引入动画库。展开后的检索条 MUST 挂在预览窗内部,
MUST NOT 遮住标题栏上的其他功能键,也 MUST NOT 被右缘的文档目录轨盖住。

检索条 MUST 在下列任一情况下收起:再次点击搜索按钮、按 Esc、点检索条以外的区域、
选中了一条结果、预览窗关闭。关闭时 MUST 把关键词、结果、选中项一并清空,
焦点 MUST 还给搜索按钮。

预览的**内容对象**发生变化时(换文件、表格包/HTML 原型切 tab、重新转换后正文重读),
检索条 MUST 收起并清空,MUST NOT 把上一份文档的结果留在屏幕上。

#### Scenario: 打开即可输入
- **WHEN** 点击搜索按钮
- **THEN** 输入框向右展开,已获得焦点,可直接键入
- **AND** 未输入时不展开结果区

#### Scenario: Esc 关闭并归还焦点
- **WHEN** 检索条打开且输入框有关键词
- **AND** 按下 Esc
- **THEN** 检索条收起,关键词被清空
- **AND** 焦点回到搜索按钮

#### Scenario: 换文件不留残影
- **WHEN** 浮层打开且已列出结果
- **AND** 在左侧清单里点开另一份文件
- **THEN** 检索条收起,关键词与结果被清空
- **AND** 新文件的正文正常渲染,没有残留的高亮

### Requirement: 模糊匹配跑在本地,只针对当前这一份内容

markdown 正文、表格包的「摘要」页、HTML 原型的「校验说明」页、纯文本预览与代码类文本高亮预览的检索 MUST 全程跑在本地:
对**已经读进内存的这一份正文**匹配,MUST NOT 发起任何网络请求,MUST NOT 写任何文件或索引。

**唯一的例外是表格的「数据」页、单份 csv/tsv 与单份 xlsx/xlsm**:它们的检索走服务端
整表扫描接口(见 `table-scan-search`),因为整张表本来就不在浏览器里。
该接口同样 MUST 只读、MUST NOT 写任何文件或索引,匹配规则见那份 spec ——
「同一行命中全部关键词、按行号先后排」,与本条的模糊排序不同,界面 MUST 把这个区别说清楚。

无论走哪条路径,检索范围 MUST 限于当前预览的这一份内容(表格即当前选中的那张表
或那一张 sheet),MUST NOT 跨到其他文件。

本地匹配 MUST 是模糊的,至少满足:

- 关键词按中英分词(连续的 CJK 字符一段、连续的字母数字一段),分词后各段 MUST 可以
  **乱序**、**不连续**地出现在同一个块里就算命中;
- 比较前 MUST 先归一:英文按小写比较,全角字母数字归一到半角;
- 只命中部分分词的块 MUST 也能进结果,但排序 MUST 排在命中更多分词的块之后;
- 结果 MUST 有条数上限,超出上限时 MUST 在列表末尾说明"只显示前 N 条"。

归一与分词 MUST 只有一份实现,前端与服务端共用,MUST NOT 各写一套 ——
两侧切词不一致会让"服务端判定命中、前端却一个词都加不了粗"这类偏差无声发生。

排序 MUST 稳定:同分的块按其在正文中出现的先后排列,同一份内容 + 同一个关键词
每次得到的顺序 MUST 一致。

#### Scenario: 词序颠倒也能搜到
- **WHEN** 正文某段是「导出任务的失败重试策略」
- **AND** 关键词输入「重试 导出」
- **THEN** 这一段出现在结果里

#### Scenario: 大小写与全角不影响命中
- **WHEN** 正文某行是「字段 `taskId` 必填」
- **AND** 关键词输入「TASKID」或全角的「ｔａｓｋｉｄ」
- **THEN** 这一行出现在结果里

#### Scenario: 命中更全的排在前面
- **WHEN** 关键词是两个词,A 块两个词都命中、B 块只命中一个
- **THEN** A 块排在 B 块之前

#### Scenario: markdown 检索不发请求
- **WHEN** 在一份 markdown 产物里检索
- **THEN** 浏览器没有发出任何网络请求,匹配全程在本地完成

#### Scenario: 代码高亮预览检索不发请求
- **WHEN** 在一份 yaml 高亮预览里检索
- **THEN** 浏览器没有发出整表检索以外的任何网络请求,匹配全程在本地完成

#### Scenario: 一个字都没命中
- **WHEN** 关键词在这份内容里一处都不匹配
- **THEN** 结果区显示"没找到"的空态,说明搜索只覆盖当前这一份内容
- **AND** 表格数据页的空态 MUST 同时说明匹配口径是"一行里要出现全部关键词",
  并且说明的是**整张表**没有命中,而不是当前这一页
- **AND** 不显示任何结果条目,正文不发生滚动

### Requirement: 结果以块级片段呈现,命中词加粗

每条结果 MUST 对应正文里的一个**块**(标题、段落、列表项、表格行、引用、代码块等),
MUST 显示该块的一小段上下文片段;片段两端被截断时 MUST 有省略标记。

片段中命中的词 MUST 加粗突出,且 MUST 通过 `{ text, matched }` 片段数组渲染成元素,
MUST NOT 用 `innerHTML` 或 `dangerouslySetInnerHTML` 拼接 —— 正文内容不受看板控制,
拼 HTML 就是一条注入路径。

结果列表 MUST 有且只有一条"当前项",键盘上下移动与鼠标悬停 MUST 都能改变它,
当前项 MUST 有可见的选中态。

#### Scenario: 片段带上下文与省略
- **WHEN** 命中的块是一段三百字的正文,命中词在中间
- **THEN** 结果条目显示命中词前后各一小段,两端带省略标记
- **AND** 命中词在片段里加粗

#### Scenario: 正文里的尖括号不被当成标签
- **WHEN** 命中的块里含有 `<script>` 这样的字面文本
- **THEN** 结果片段把它按纯文本显示出来
- **AND** 页面上不产生任何新的脚本或元素

#### Scenario: 悬停改变当前项
- **WHEN** 结果列表有多条,鼠标移到第三条上
- **THEN** 第三条成为当前项,其余条目回到普通态

### Requirement: 选中结果后滚动定位并临时高亮,且不改动正文 DOM

选中一条结果(点击或在当前项上按 Enter)MUST 把预览的滚动区滚到该块所在位置,
块 MUST 大致落在可视区中部,滚动 MUST 平滑。随后该块 MUST 被临时高亮约两秒后自动恢复。

高亮 MUST 只通过给**块元素本身**加一个临时的 class 实现。
看板 MUST NOT 为了高亮而在正文里插入、删除或拆分任何文本节点或元素 ——
批注的锚点是「UTF-8 字节区间 → 文本节点」的映射,正文结构一变,已有批注的位置就会错。

高亮配色 MUST 取黑白灰体系的令牌,MUST NOT 使用 `--destructive`(橙)——
这不是"需要注意",只是"在这儿"。深色模式下 MUST 同样可辨。

定位失败(块元素已不在 DOM 里,例如正文在这期间被重读)时 MUST 走降级:
浮层照常关闭,滚动区停在原处不动,MUST NOT 报错弹窗,也 MUST NOT 高亮错误的块。

#### Scenario: 点结果跳到正文
- **WHEN** 结果列表里点击第二条
- **THEN** 预览滚动区平滑滚到该块,块大致居中
- **AND** 该块被临时高亮,约两秒后恢复
- **AND** 浮层关闭

#### Scenario: 高亮不打乱已有批注
- **WHEN** 这份 markdown 上已有若干条批注高亮
- **AND** 通过搜索跳转到某一块并触发临时高亮
- **THEN** 所有批注仍停在原来的文字上,位置一处不偏
- **AND** 临时高亮消失后正文与跳转前完全一致

#### Scenario: 目标块已经不在了
- **WHEN** 选中一条结果时,正文恰好因为重新转换而被重读、该块元素已不存在
- **THEN** 浮层关闭,滚动位置不变,页面上没有错误提示弹窗
- **AND** 没有任何块被高亮

### Requirement: 键盘与输入法行为

浮层打开时,上下方向键 MUST 在结果间移动当前项并循环,Enter MUST 选中当前项,
Esc MUST 关闭浮层;这三个键 MUST NOT 冒泡出去触发预览窗或页面上的其他行为。
没有结果时,上下键与 Enter MUST 什么都不做。

输入法组合期间(如中文拼音候选未上屏),上述快捷键 MUST 全部让位 ——
此时 Enter 是上屏候选、上下键是翻候选页、Esc 是取消组合,
看板 MUST NOT 把它们解读成"选中结果 / 移动当前项 / 关闭搜索"。

看板 MUST NOT 接管 `Cmd/Ctrl+F`,浏览器原生查找 MUST 照常可用。

#### Scenario: 上下键循环
- **WHEN** 结果有三条,当前项是第三条,按下方向键
- **THEN** 当前项回到第一条

#### Scenario: 拼音候选期的回车不触发跳转
- **WHEN** 正在用拼音输入法输入关键词,候选框展开且尚未上屏
- **AND** 按下 Enter 上屏候选词
- **THEN** 候选词进入输入框,浮层不关闭,正文不发生跳转

#### Scenario: 原生查找不被抢
- **WHEN** 预览窗打开,按下 `Cmd/Ctrl+F`
- **THEN** 打开的是浏览器自带的查找条,看板的搜索浮层不受影响
