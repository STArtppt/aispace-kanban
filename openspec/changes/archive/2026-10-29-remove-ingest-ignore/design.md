## Context

`input/.ingestignore` 是看板与模板脚本共用的一份约定：看板扫描时读它判 `ignored`、菜单里能往里追加一行；
`layout.py` 的 `load_ignore` / `is_ignored` 被 `ingest.py`、`pointtable.py`、`web_ingest.py`、`migrate_converted.py` 用来过滤；
`move_raw.py` 整理原件时还会改写其中字面命中的规则；`template.yaml` 把它列为 seedOnly，`init_workspace.py` 新建时铺过去。

它最初是为了让上千份存量资料里用不上的那些别一直挂在「待转换」里。现在原始资料列表与磁盘一一对应，
忽略与否都照样列出，它的实际作用只剩「全局『开始转换』时跳过这些文件」。用户决定连全局转换一起去掉。

## Goals / Non-Goals

**Goals:**

- 看板、契约、模板脚本里不再有「忽略」这个概念；看板对工作空间少一处写入。
- 看板只能转换用户明确点的文件或子目录，不能一键转全部；终端和 agent 跑 `ingest.py` 也必须写明范围。
- 旧服务进程 + 新前端、新看板 + 未更新模板的实例，都不白屏、不误写。

**Non-Goals:**

- 不删除已有实例里的 `input/.ingestignore`，也不迁移其中的规则。
- 不改单份 / 子目录转换的流程与进度显示。

## Decisions

**1. 已有实例的 `.ingestignore` 留着不动，只是不再生效。**
备选：模板更新时删掉它，或把其中规则迁成别的形式。不选：删是往工作空间写、还是删除，超出只读红线；
迁移没有目标形式可迁。留一份无效文件的代价只是一点困惑，技能里提示一句即可。

**2. 看板不读 `.ingestignore`，原来忽略的资料按有无产物显示待转 / 已转。**
备选：只去写入口，保留只读识别（继续显示「忽略」）。不选：模板脚本已不再按它过滤，继续显示「忽略」会和实际转换行为不一致。

**3. 全局转换在服务端也拒绝，不只是藏按钮。**
`startIngest` 对空路径和 `input/raw` 根返回 400。备选：只删前端按钮。不选：别的入口（旧前端、手写请求）仍能触发全量转换，
「保险」就不成立。`input/raw` 下的一级子目录照常允许。

**4. 契约里删字段，但前端对旧服务进程兜底。**
`FileItem.state` 收窄为 `'converted' | 'pending'`，前端遇到运行时值 `ignored` 当 `pending` 处理（类型上读成 string 再比对）；
`RawOrganizePlan.ignore` 改为可选且前端不再渲染，旧版 `move_raw.py` 仍会给它。
备选：保留 `'ignored'` 字面量在类型里。不选：留着会诱导以后的代码继续分支处理它。

**5. 模板 `move_raw.py` 直接删掉忽略规则改写，不保留开关。**
备选：保留改写以免实例里的遗留规则失效。不选：规则本来就不再生效，改写它没有意义，还要维护通配符分类那一套。

**6. 顺带把本会话已做的界面调整写进 spec。**
目录汇总标签、「改动」改名、标签位置、移动树——都是原始资料视图的同一批改动，若不记进 spec，现行 spec 就与界面不符。

**7. `ingest.py` 不带路径就拒绝，`--dry-run` 例外，显式 `input/raw` 允许。**
去掉忽略后，最容易误伤的是 agent 照着旧文档敲一句不带参数的 `ingest.py`。脚本自己拒绝，才算把保险落到每条路径上。
备选 a：加 `--all` 开关才允许全转。不选：多一个开关等于多一种写法，显式写 `input/raw` 已经表达了「我就是要全转」。
备选 b：`--dry-run` 也拒绝。不选：只打印计划不写盘，「先看全量计划」仍有用。
看板服务端仍拒绝 `input/raw` 根（决策 3），两边并不矛盾：看板是点按钮的地方，要更保守。

## Risks / Trade-offs

- [用户曾靠忽略挡住的大文件，在单份或目录转换里被一起转] → 目录转换只转用户点的那个目录；需要跳过就别对那个目录点转换，或把文件移出 `input/raw/`。
- [实例里的 agent 或人照旧习惯不带参数跑 `ingest.py`] → 脚本拒绝并给出带路径的示例；模板文档里的示例同步改掉。
- [已更新模板、但还没重启的旧看板服务仍可能发不带路径的转换请求] → 新脚本拒绝，任务以失败结束、显示脚本给的提示，不会误转。
- [旧服务进程仍提供 `/ignore`，旧前端还能写 `.ingestignore`] → 写进去也不再生效；重启看板后接口消失。
- [实例未更新模板时，旧 `ingest.py` 仍按 `.ingestignore` 跳过文件，看板却显示「待转」] → 过渡期现象；点「转换」时旧脚本会在日志里说被忽略，提示用户更新模板。

## Migration Plan

1. 合入后重启看板服务。
2. 各实例按 `pm-template-update` 技能更新模板；技能提示遗留的 `.ingestignore` 已不生效。
3. 回滚：还原本变更的提交即可，实例里的 `.ingestignore` 没被动过，规则仍在。
